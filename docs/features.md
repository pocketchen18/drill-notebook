## 2. AI 连接与会话能力

### 2.1 连接、记忆工具与运行限制（v0.7.1）

在 v0.7.0 记忆系统之上，让 AI 在对话中按需调用记忆工具：

| 能力 | 状态 |
|---|---|
| `search_memories`：按查询检索并读取相关记忆 | 已实现 |
| `list_memories`：按授权范围查看记忆标题 | 已实现 |
| `create_memory`：自然语言新增记忆（归一化去重、证据、作用域与有效期、被删除主题的显式重记） | 已实现 |
| `update_memory`：自然语言更新记忆（正文/ID 双定位、乐观锁、证据继承、不跨作用域） | 已实现 |
| 工具编排、作用域与权限、每模型「工具调用」开关 | 已实现 |
| 工具活动展示、加密历史恢复、自由滚动与中断反馈 | 已实现 |
| 多供应商/多模型、二级设置、用途绑定与稳定模型 ID | 已实现 |
| 可搜索预设、思考档位与默认值、自动发现与并发能力验证 | 已实现 |
| 全局运行限制、保存/取消/恢复默认、达限提示与主动继续 | 已实现 |
| 每次上游调用的用量/缓存分桶 | 已实现；独立用量详情页面未实现 |
| 向量语义记忆检索 | 未实现；当前仍为内存词法索引 |

- 模型工具能力开关位于「设置 → AI 连接 → 模型设置」；未验证自定义端点默认关闭，新增模型工具验证成功后自动开启，也可显式调整。各工具的全局独立开关见 §2.3。
- 记忆工具调用只对 v2 协议且本轮启用记忆的聊天生效；导入兜底模型不启用。v0.7.2 的会话工具不依赖长期记忆开关。
- 原始工具参数与结果只进入本轮上下文；安全的活动摘要通过 SSE 展示并加密保存到历史，不包含记忆正文或敏感参数。
- 自动提取对「请加入记忆 / 请记住 …」类消息只保存事实正文，剥离命令前缀；只有命令没有事实时不落库。
- 用户明确说「请记住」时，`create_memory` 会解除该主题之前删除留下的 `FAMILY` 抑制并重建索引；没有明确要求时返回 `SUPPRESSED`，不会写一条读路径看不见的幽灵记忆。`PREDICATE` / `EVIDENCE` 抑制仍留给自动提取。
- 纠正已有记忆时，如果 `search_memories` 没命中，模型会按 `list_memories` 标题里的主题词再检索一次，避免「我是女的」与存储的「用户是男性。」措辞不同就误判没有记忆。
- 「设置 → AI 对话 → 运行限制」全局默认 50 个工具阶段、100 次执行、整轮 30 分钟、单次请求 15 分钟；Token 额度与重复调用阈值可修改、恢复默认。每轮冻结配置，切模型不改预算；旧的整轮 15 条记忆与独立 3 次写入限制已取消。
- 修改模型 ID 不覆盖已设置项或未保存草稿；只有点击/回车应用预设才回填对应字段。新供应商自动发现一次，选择模型后最多 3 项并发验证，文本成功决定添加，视觉/工具结果分别保存。
- 删除来源会话或清理聊天记录保留已保存的长期记忆，仅清理来源证据；未人工修改的来源类型保持不变。切换聊天模型复用同版本记忆索引，重启后异步预热，不承诺零延迟。

发布范围、验证与升级：[v0.7.1 发布说明](release/v0.7.1-release-notes.md)。完成的施工材料：[v0.7.1 归档](archive/v0.7.1/README.md)；后续开发以对应版本的需求清单与当前状态文档为准。

### 2.2 会话协作与消息排队（v0.7.2）

| 能力 | 状态 |
|---|---|
| 首个完整问答生成标题、人工改名优先、失败手动重试 | 已实现 |
| 会话列表与二级菜单、复制稳定链接、来源预览 | 已实现 |
| `list_sessions` / `read_session`：筛选、分页、定位与分段读取本地会话 | 已实现 |
| `create_session` / `send_message`：携首条消息新建，向新旧会话派发，忙碌时顺序接续 | 已实现 |
| 不同会话并行、独立运行状态和停止、切换保留草稿与阅读位置 | 已实现 |
| 人工消息排队、编辑、移除撤销、暂停继续与加密恢复 | 已实现 |
| 插话不打断当前请求、接收状态、历史与三种格式导出 | 已实现 |

- 新建和删除当前会话后只进入未保存的新会话页；首条有效消息才创建数据库记录。AI 新建的会话也是普通会话。
- 会话工具复用模型工具开关与全局预算；查阅不依赖记忆索引，不自动建立长期记忆。链接仅在同一份本地数据中定位会话，不提供公开分享、跨设备同步或系统协议注册。
- 人工普通发送与工具派发共用 FIFO，每条消息独立成轮。编辑暂停接续，保存或取消恢复原暂停状态；尚未发送的输入草稿与已受理队列分别保存。
- 插话在下次模型请求前接入当前轮次，不取消已开始的输出或工具，不重置预算。停止或失败保留尚未开始的人工内容并暂停，取消工具待发项；重启恢复人工队列为暂停状态，已开始或交付未知内容不自动重发。

范围、已有切片验证和发布前待办见 [v0.7.2 发布说明](release/v0.7.2-release-notes.md)。该版功能清单、导航、四工具、人工排队与插话材料已在开始 v0.7.3 前整理至 [归档](archive/v0.7.2/README.md)。

| 能力 | 状态 |
|---|---|

| 「设置 → 工具」统一目录、独立全局开关与恢复默认 | 已实现，全部 20 项：16 开 / 4 关；保存与模型独立 |
| 移除常驻上下文卡片与右下角重复入口 | 已实现，保留右上角、快捷键与业务入口 |
| 上下文窗口与最大输出必填、取消最大输入与保守窗口 | 已实现；旧缺值模型须补齐或应用预设后使用 |

- 新前端只向本地后端提交消息绑定的页面快照，正文由工具按需读取；切页不改变已提交目标，未保存内容标明草稿。此能力不读取其它应用或系统桌面。
- 设置快照包含当前选项卡的可读选项与状态，「关于」包含实际版本、检查结果、检查时间和更新开关；连接只提供认证配置状态，不附加密钥、密码、连接地址或请求头。日历快照包含当前月份、选中日期、月历标记、自主计划及当前筛选的合并学习队列，随页面状态更新。记忆管理只登记状态、筛选与数量，记忆正文仍由记忆工具按既有策略读取。
- 修改只作用于委派字段，核对读取版本；新增 / 修改 / 删除回执避免重复操作。资料进入普通业务页，保留真实作答统计，工具活动只保存安全状态与来源。
- 所有工具独立启停，全局生效、不随模型切换；保留已有偏好。开启下一轮生效，关闭阻止尚未执行的调用；仍需模型支持工具调用，记忆工具另需启用记忆功能。
- 四个删除工具默认关闭，恢复默认也关闭；开启不等于任意删除授权。派发任务不提供删除能力；删除资料需核对版本，非空容器需明确一并删除，删除当前 / 上游 / 忙碌会话受保护。
- 「移出错题本」保留原题与作答记录；删除来源会话保留长期记忆。删除成功刷新目录，被删笔记的草稿不再保存。

### 2.4 失败重连、会话跳转与模型选择（v0.8.1）

三项已实现并通过工程验证，范围与默认策略见[本版清单](state/v0.8.1-features.md)，最终交互见[UI/UX](work/ai-conversation/ui-ux.md)，验证范围和待验收项见[计划](work/ai-conversation/plan.md)。

- 可恢复失败在原回答处显示实际次数、适用上限、供应商安全报错与等待时间，随时可停止。请求默认重试 4 次、回答默认重连 5 次，纯断网默认持续等待；「AI 对话 → 运行限制」可自定义 0–100 的有限上限，普通请求与流式重连按用户要求从 400ms 起翻倍，保留约 ±10% 抖动与服务端建议优先；断网仍沿用 Codex 独立策略。
- 自动恢复保持原请求、模型、预算、部分回答和已确认工具结果；失败原因加密保存，成功清除临时反馈。Chat Completions / Anthropic 通过同模型续答恢复，没有原流续传协议，不重放未确认的工具调用或插话。
- 正文右侧最多 64 个连续逐轮刻度，更多轮次在刻度或卡片上滚轮翻阅；静止短而淡，悬停 / 聚焦后所选及邻近刻度平滑加长。预览保留轮次与时间，提问粗体最多 2 行、回答浅色最多 3 行，超限显示 `...`，整卡点击定位。
- 可跨历史页定位，保持最多 500 条驻留消息，旧阅读位置不被输出或定稿拉回；草稿、附件、生成和队列保留，可回到最新。自动恢复不新增提问，手动重新生成沿用既有追加问答行为。
- 对话模型与档位统一在助手输入区选择，立即保存到 APP_ROOT 内的现有数据库，跨已有 / 新会话和重启共用；保存失败保留原选择和输入，已受理任务及历史保留原模型。设置只选择导入模型，去掉主模型应用、标记与用途下拉；未单独配置导入时跟随助手。

- 「设置 → 关于」提供当前版本、带 GitHub 图标的主页、手动检查更新、独立的自动更新开关、自动检查开关、检查间隔（默认 24 小时）及启动更新弹窗开关；检查与说明提醒共用一个间隔设置，分别记录实际检查和提醒时间，重启不重置冷却。
- 自动更新默认关闭；开启后每次启动立即检查，有未跳过的新版本就直接显示进度、下载并自动重启，不受共享间隔或自动检查开关限制。运行中开启只保存后续启动偏好，周期检查仍只提示新版。
- 发现未跳过的新版本时，顶部更新图标常驻；右上角 × 仅关闭当前弹窗，图标保留；已是最新版或「跳过此版本」后图标隐藏。手动检查不受间隔和跳过记录限制。
- 点击顶部图标或手动检查发现新版，展示 GitHub Release 说明；底部提供「跳过此版本 / 立即更新」，关闭统一使用右上角 ×。关于页另有 GitHub Star 提示与按钮；点击只打开仓库页面。
- 关于页「更新内容」只保留 GitHub 主页旁的入口，移除检查状态旁的重复按钮；采用 Magpie 的范围菜单和只读「关闭」操作。默认「上次更新以来」可附上已知待安装说明，「当前版本及之前 10 / 20 / 50 / 100 个版本」始终以实际安装版为上限，排除未安装新版。检查发现新版、顶部入口与启动提醒只展示安装版之后的未安装版本，不提供历史范围菜单。两处均逐版保留原始 Release 正文，不融合多版说明。
- 更新继续使用 Windows 便携 ZIP：点击「立即更新」后独立进度窗口连续完成下载、校验、保存、程序替换与自动重启，无需第二次确认。取消下载停止事务，关闭进度窗口仅隐藏界面；材料与备份均在 APP_ROOT 内，保留笔记、附件、模型、配置与草稿。新版启动失败恢复旧程序与停机数据库，失败目标阻止启动自动循环，仍可手动重试。

### 笔记混合检索接入资料工具（计划 v0.8.2）

2026-11-12 确定保留既有 embedding RAG，并按用户本次版本安排将笔记混合检索接入现有资料工具顺延至 v0.8.2。目前资料工具仍使用关键词匹配与分段读取，向量检索接入尚未实现。

- `search_materials` 的笔记自然语言查询复用既有 **BM25 + 向量 + RRF** 混合检索，改善同义表达、概念性提问与正文用词不同造成的漏命中。既有分块、索引、模型与降级能力见 [笔记检索说明](reference/ai-retrieval.md)。
- 搜索返回资料 ID、所属位置、来源链接和相关正文片段；模型需要更多前后文时调用 `read_notebook` 分段读取，保持按需获取资料。
- 保留精确关键词匹配与空查询目录浏览；明确 ID 的读取继续直接定位，避免语义候选稀释精确查找结果。具体查询策略在 v0.8.2 切片设计时确定。
- 向量模型或索引不可用时降级为 BM25；控制返回条数与片段总量、去除重复内容，目标是减少补查和无关正文读取。
- 准确度提升与整轮 token 节省属于预期收益，尚无本项目实测结论，不承诺固定提升幅度。依据公开经验确定接入方向，完整本地对照评测不作为立项前置条件；开发时仍需验证工具接入、降级与返回预算。
- 本项覆盖笔记资料检索；长期记忆继续复用现有 BM25 索引与标题列表，向量语义记忆检索另行规划。

决策参考：[微软混合检索评测](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/azure-ai-search-outperforming-vector-search-with-hybrid-retrieval-and-reranking/3929167)、[BEIR 跨领域评测](https://arxiv.org/abs/2104.08663)与 [Anthropic 检索实践](https://www.anthropic.com/news/contextual-retrieval)。公开结果支持词法与语义检索互补，也显示精确关键词可能退化；包含片段上下文补充或重排的提升不能全部归因于向量检索，不能直接套用到本项目的中文笔记与本地模型。

### 联网搜索工具配置（待排期）

全局工具目录与删除能力已在 v0.7.3 实现；联网搜索仍只记全局规划，尚未纳入本版实现。具体版本与 UI/UX 另行确认。

- 在现有 **“工具”** 设置中增加“联网搜索”分组，维护搜索服务、连接测试与必要参数；具体供应商与协议留待切片设计。
- 外部搜索由软件接入并纳入同一全局工具目录与执行检查；接入搜索服务不向助手开放 Shell 或任意本地文件修改能力。移动、批量删除与删除恢复也未在本版交付，不随设置目录补全而提前实现。

## 4. Non-Goals（当前明确不做）

- 当前没有将本软件做成 AI 编程工具或通用 Agent Harness 的计划。参考编程类产品仅借鉴窗口、会话、消息及运行状态等交互，不引入其开发执行环境。
- AI 助手只调用软件内置或由软件明确接入的工具；不赋予其任意本地文件修改权限，不提供 Shell、终端命令或通用脚本执行能力。
- 既有资料新增 / 修改 / 删除仍通过软件业务工具完成，由软件管理数据存储；这不等于允许模型直接编辑本地文件或操作项目目录。人工导入 / 导出等正常文件功能不受此产品边界影响。
- 不重做 v0.7.0 已交付的记忆管理、自动整理与对话记忆预注入。
- 不兼容旧 v1 AI 客户端；v0.7.0 起使用 v2 协议。
- 不在本地执行正式发行打包；正式发行只在 GitHub Actions 上做。
- 不把未验证的 PARTIAL 场景写成 PASS，不用评测 harness 的局部结果冒充完整 §7。
