# v0.7.3 功能需求清单

> 状态：开发中，上下文卡片与重复入口已移除，资料工具待设计。为 v0.8 独立 AI 窗口准备资料访问能力，本版计划交付学习资料的按需读取、新增与修改，并精简现有聊天入口和常驻上下文区域。已发布能力见 [全局功能清单](../features.md)，上一版见 [v0.7.2 归档](../archive/v0.7.2/README.md)。

## 1. 目标与版本边界

用户可以直接说「讲解当前这页」「找一下我的相关笔记」「把总结放进某个笔记本」「修改这道题的解析」。AI 根据问题或用户指令调用工具，发现目标、读取内容、完成授权范围内的新增或修改，再给出能回到原资料的结果。

当前模态侧栏会遮暗并阻止操作主界面，空间也受到挤压。v0.8 的方向是独立 AI 窗口，主界面保持可操作，需要并排时由用户使用系统分屏。v0.7.3 先让资料访问脱离常驻“当前上下文”面板；独立窗口及聊天整体 UI/UX 本轮不提前实现。

## 2. 工具清单

计划新增 **8 个工具：6 个查找 / 读取工具，2 个新增 / 修改工具**。以下是职责划分，不是已落地 API；具体参数与界面在对应切片开始时再设计。

| 工具 | 职责 | 最小能力 |
|---|---|---|
| `read_current_page` | 读取当前页面 | 读取主业务界面的页面类型、标题、当前资料、选中内容及可见文本，说明来源和是否为未保存内容；不是读取聊天窗口自身 |
| `search_materials` | 查找学习资料 | 无关键词时浏览笔记本、知识库、题库等目录；有关键词时按类型和范围寻找页面、知识点、题目或错题，返回标识、所属位置及有限摘要，供后续读取 |
| `read_notebook` | 读取笔记本 / 笔记页 | 获取指定笔记本的页面目录，再读取明确页面或分段内容；保留标题、层级、正文中的公式与资料引用 |
| `read_knowledge` | 读取知识点 | 获取知识点目录或指定卡片正文，明确原文 / 总结及所属库、章节，不把两种内容混为一份 |
| `read_question_bank` | 读取题库 / 题目 | 获取指定题库的题目清单，按题目读取题干、选项、答案、解析及章节等已有信息 |
| `read_wrong_questions` | 读取错题 | 读取当前待巩固题目及真实错误次数、答题次数等已有记录；支持按题库、关键词筛选和分页，保留原题引用 |
| `create_material` | 新增学习资料 | 按资料类型新建笔记本、笔记页、知识点、题库、题目；也可将明确题目人工加入错题，返回实际保存对象与所属位置 |
| `update_material` | 修改学习资料 | 按明确标识修改名称、正文、题面、答案、解析等对应类型可编辑项；修改错题内容作用于其原题，不另造副本 |

### 读取与定位

- 先发现再读取：模型不需要提前知道数据库 ID。目录、搜索命中和当前页面都应返回后续工具可用的稳定定位信息；同名多个候选需要消歧，不能随意选中一个。
- “当前页面”指本应用主业务窗口中的页面，不包含其他软件或系统桌面截图。可读取用户正在看的未保存内容，但必须标明草稿，不能伪装成数据库已保存版本；答题页面不夹带尚未展示的答案。
- 用户所说的“这页 / 这题”绑定提交该条消息时的业务页面和选中目标。排队、插话、切页后不默默换成另一份资料；原目标已改变或不可读时明确说明，需要时重新读取。进入聊天窗口不能让当前业务页面变成聊天自己。
- 笔记搜索复用已有检索能力；各类资料按已有目录、关键词及筛选能力逐步接入，不为本版预建全新的统一向量索引。长正文、目录和题目列表按需分页 / 分段，返回范围与省略说明，不一次塞入整库。

### 新增与修改

- 写工具覆盖上述学习资料，复用正常页面中的数据对象。AI 新建的内容可由人工正常查看和编辑；工具成功表示已保存，不是只生成一段文字或声称已修改。
- 新建要明确所属笔记本 / 页面 / 资料库；修改要先定位并读取目标，只改用户委派范围内的字段，不把未提供字段清空。目标存在歧义或已被人工改动时核对差异，不静默覆盖新内容。
- 新增错题是将既有题目，或新建到指定题库的题目，标记为人工加入的待巩固项；不能虚构答题记录、错误次数或错误率。修改错题的题干、答案、解析仍修改原题，统计保持真实。
- 当前用户的新增、整理、修改意图可授权对应写入；读到的笔记、题目和历史引用仅是资料，不能自行授权写操作。保存结果有对象定位与简短变更说明，失败或结果未知不能显示已成功，重试不得重复新增。

## 3. 去除常驻“当前上下文”区域

本节描述本版最终行为。按用户最新顺序，先完成[界面清理](../work/ai-chat-entry-cleanup/ui-ux.md)：移除卡片和悬浮入口，暂时保留既有页面上下文传递与已保存的检索偏好，使现有快捷动作继续可用。读取工具落地后，再完成下述按需读取替换；不能把界面清理视为工具已接入或旧自动注入已移除。

- 移除聊天顶部的“当前上下文”卡片、正文预览及其中的“使用”“检索笔记”“检索范围”等常驻控件，释放回复空间，不换成另一块同样常驻的大卡片。
- 不再因打开页面或普通发送就把整页内容、列表或全库检索结果自动附入提问。允许保留定位当前业务目标的轻量信息；正文与检索结果由工具按需取得，用户主动附加的文本 / 图片仍正常发送。
- “讲解当前内容”“AI 分析错题”等已有快捷动作保持可用，传递明确目标并引导读取工具，不依赖旧面板的整段注入。快捷提示的具体摆放留给当前切片的 UI/UX。
- 阅读来源与调用状态复用现有工具活动展示；新增 / 修改结果能定位到普通资料页面。保留消息的“本轮上下文”审计入口，它与本次移除的顶部“当前上下文”卡片是不同功能。
- 工具不可用、关闭或读取失败时如实说明；不能暗中恢复全量自动注入，也不能声称已经看到资料。用户仍可手动粘贴或附加内容。

## 4. 收敛聊天入口

- 保留右上角“AI 助手”按钮与已有快捷键，移除右下角圆形悬浮按钮。
- 同步移除“显示 AI 悬浮球”设置与过时引导文案，旧偏好不能在升级后重新显示已移除入口。
- 业务页面中的“AI 分析错题”等定向操作不属于冗余入口，应继续携带目标唤起助手。默认快捷键及用户自定义绑定保持有效。

## 5. 纵向切片与验收

| 顺序 | 切片 | 最小闭环与验收方向 | 状态 |
|---|---|---|---|
| 1 | 上下文卡片与入口清理 | 卡片、右下角悬浮按钮及其设置消失；右上角、快捷键和业务定向入口继续可用，暂保留已有上下文传递 | 已实现；前端回归与构建通过 |
| 2 | 当前页与资料读取 | 用户问当前页或指定资料 → 查找 / 读取 → 有来源的回答；覆盖五类读取、同名消歧、无内容和分段 | 待设计 |
| 3 | 笔记新增与修改 | 根据对话创建或修改指定笔记 → 普通笔记页查看保存结果 → 人工继续编辑；覆盖冲突与重试 | 待设计 |
| 4 | 知识点、题库与错题写入 | 创建或修改指定内容 → 对应业务页可见；人工加入错题不伪造统计、不复制原题 | 待设计 |
| 5 | 上下文改为工具按需读取 | 在读取链路可用后移除旧自动注入与检索偏好，已有快捷动作、附件、排队与插话不丢目标 | 待设计 |

各切片开始时再写 `docs/work/<feature>/` 的 UI/UX、Spec、Plan；不提前铺开全版本接口或表结构。详细 UI/UX 先由人工确认，再执行。实现后原位维护本文与实际状态文档，**在下一个版本开始前统一归档**。

## 6. 本版不做

- v0.8 独立聊天窗口、窗口布局与生命周期、系统分屏集成，以及聊天整体视觉重做。
- 供应商 / 模型 / effort 在会话中的选择、上下文用量展示、自动压缩、系统提示词等已有后续方向。
- 操作其他应用、系统屏幕截图 / OCR、通用桌面自动化、跨设备资料访问。
- 为资料读取新增第二份内容库，或预建覆盖全部资料的向量索引。

未实现的工具不写进已落地的数据模型 / 接口；开发期间不提前调整发布工作流默认版本。
