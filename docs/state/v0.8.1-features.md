## 2. 失败重连

参考用户提供的 **Codex app** 和 **Claude CLI** 截图：在当前回答的运行反馈处显示「正在重新连接 2/5」及上游具体错误，保留可取得的状态码和报错正文，例如 `rate limit exceeded`、`Request rejected (429) · Service Unavailable`。次数须对应真实恢复状态，不能只显示通用「请求失败」或把所有错误改写成同一种原因。

- 自动恢复网络、限流及其它可重试失败，覆盖请求开始、回复过程和工具调用完成后的响应；生成中的网关 `upstream_error` 也使用流式重连次数和原轮次续答。显示正在等待 / 重连、当前次数、适用上限和最近的供应商错误。没有上游正文时说明实际连接或超时原因，不编造状态码；敏感信息遵循已有错误展示规则。
- 「设置 → AI 对话 → 运行限制」允许覆盖相应重试上限并恢复默认。普通请求与流式重连分别沿用 Codex 默认值；纯断网等待默认持续，用户也可设置有限上限。有限次数允许 0（关闭该类自动重试），上限范围沿用源码的 0–100；表单组织见 [UI/UX](../work/ai-conversation/ui-ux.md#3-设置运行限制中的失败重连)。
- 初始请求不计入重试次数。达到配置上限后保留具体失败原因和已有输出，可由用户主动重试 / 重新生成；等待和重连过程中始终可以停止。
- 保留草稿、附件、已显示的回答及已确认的工具结果，避免重复用户消息或业务写入。不把重新请求伪装成供应商原流的无缝续传；恢复方式须按供应商能力明确处理。
- 重试沿用原轮次的模型、工具开关及运行预算，不能通过重连重置整轮时限、用量或写操作身份；停止、不可恢复的鉴权 / 额度 / 配置错误不自动重试。
- 各类次数针对当前模型步骤的连续恢复请求，取得完整响应后重置该步骤计数，整轮预算不重置。Chat Completions / Anthropic 断流后保留已有回答前缀和已确认工具上下文，请求同一模型继续回答；没有原流续传协议。失败或停止的恢复事实随原助手消息加密保存，零正文也能在历史中查看原因。

生成中上游错误修正（2026-11-14）：补齐 `upstream_error` 的可恢复分类，同时保留明确鉴权、参数与额度错误的停止规则；后端 9 类 / 120 项、前端 4 文件 / 60 项相关回归通过。验证范围见[测试清单](../test/QA_CHECKLIST.md#生成中上游错误重连修正验证2026-11-14)。

### 已核实的 Codex 默认策略

2026-11-12 按用户要求读取官方 `openai/codex` 仓库，固定参考提交 `6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3`。官方[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)也确认请求重试默认 4、流式重连默认 5。以下保留公开核心层的真实数值；本版沿用次数、分类与抖动，按用户要求将普通请求及流式恢复的起始等待改为 400ms（2026-11-13）；未核实桌面壳或云端编排是否另有覆盖，不把它们写成已确认的内部实现。

| 失败层级 | 默认次数 | Codex 源码间隔 | 本版间隔（没有服务端等待建议时） |
|---|---|---|---|
| HTTP 请求失败 | 最多重试 4 次，初始请求另计 | 200、400、800、1600 毫秒 | 400、800、1600、3200 毫秒 |
| 流式响应中断与可恢复的生成失败 | 最多重连 5 次，初始请求另计 | 200、400、800、1600、3200 毫秒 | 400、800、1600、3200、6400 毫秒；自定义次数后继续翻倍 |
| 纯网络连接失败 | 默认持续等待网络恢复，直到用户停止或本项目既有整轮预算到期；可自定义有限上限 | 5、10、20、40、60 秒，随后保持 60 秒 | 沿用源码，不使用普通重试抖动，也不消耗流式重连计数 |

普通请求与流式恢复每次乘以 `[0.9, 1.1)` 随机因子，首轮实际约为 `[360, 440)` 毫秒。

合法服务端等待建议优先于普通本地退避，并按接收时建立的截止时刻等待；错误展示耗时不能重新延长该期限，过期建议按 0 处理。等待建议不会增加配置的重试额度。纯网络持续等待采用源码的独立分支，不把 5 秒起步误记为所有报错的通用策略。

Codex HTTP 底层默认重试 5xx 和传输错误，429 在该层关闭直接重试，由上层识别临时限流等具体错误后决定。本项目适配两类供应商协议：HTTP 5xx / 408 和可恢复传输错误走请求分支，临时 429 与可恢复流式错误走生成恢复分支；额度耗尽、鉴权拒绝和 TLS 配置错误不会自动重试。SSE「服务器繁忙」须有明确等待建议；HTTP 响应头的合法建议也适用于 SSE 错误事件。

源码依据：[默认次数与范围](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/model-provider-info/src/lib.rs#L73)、[HTTP 重试配置](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/model-provider-info/src/lib.rs#L499)、[HTTP 退避与计数](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/codex-client/src/retry.rs#L43)、[流式退避](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/async-utils/src/backoff.rs#L7)、[连接失败与普通重连分支](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/core/src/responses_retry.rs#L88)、[持续等待默认开启](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/features/src/lib.rs#L1607)、[错误分类与服务端等待](https://github.com/openai/codex/blob/6aa83e5eee5499f7babaa6fd42cda9b3a39c9bc3/codex-rs/protocol/src/error.rs#L457)。

## 3. 会话内对话跳转

按用户提供的 **Codex app 左侧**与 **Qoder Desktop 右侧**截图，采用纵向细刻度导航和悬停预览卡片。结合本软件已有布局，选择**聊天正文区右侧**：左侧已承担会话列表，右侧刻度可以利用正文边缘的留白，不新增常驻大面板。

- 按当前保留的用户提问顺序提供轮次刻度，区分当前阅读位置与悬停项。每条独立用户消息一个定位点；自动恢复和同轮插话不新增提问，手动重新生成沿用既有追加新问答行为。
- 刻度中心间距固定 10px，上下各留 8px，整组随可见数量收缩并在消息区垂直居中；13 轮高 136px，64 轮高 646px。最多展示 64 个连续逐轮刻度，高度充足时显示 50 个以上；矮窗口按父消息区高度减少数量，间距保持固定。更多轮次通过刻度或预览卡片上的滚轮上下翻阅，边界停止；滚轮只改变预览窗口，不带动正文、不自动跳转，键盘仍可选择全会话轮次。
- 平时刻度短而淡；悬停或聚焦后，所选及附近刻度平滑加长，离开平滑收回。当前阅读位置继续用强调色标明；减少动态效果时取消过渡。
- 鼠标点击刻度直接定位，不强制聚焦或留下整条蓝框，键盘仍有焦点提示。首次悬停等待约 150ms，连续移动不延长等待；打开后逐帧合并最新目标，同轮去重，文本截断按原文及布局条件复用，减少反复测量。
- 向左展开的单张预览卡片保留轮次与提交时间，以粗体提问、浅色回答区分，不增加提问 / 回答标签或状态栏。提问最多 2 行、回答最多 3 行，超限显示字面量 `...`；点击整张卡片即可定位，不附加跳转按钮。预览从已有消息取片段，不额外调用模型。
- 时间显示该轮真实提问时刻，数据库 UTC 时间统一换算为系统本地时间；已加载消息、历史定位预览与会话列表共用解析规则，跨日和明确时区偏移保持一致。缺失或不可解析的时间不显示。
- 刻度固定在正文阅读区域右边缘，不延伸到输入区；打开右侧详情栏时仍属于正文区，不放入详情栏。窄窗口下与详情覆盖层协调，避免挡住输入、原滚动条和「回到最新」操作。
- 跳转保持本会话草稿、附件、正在生成的内容与任务状态；用户查看旧对话时流式输出不强拉回底部，可主动回到最新内容。
- 支持分页历史的定位与按需加载，超出最近 500 条时加载目标附近的有界阅读窗口，仍最多驻留 500 条；回到最新恢复最新窗口。空 / 单轮会话隐藏刻度，选中文字的复制 / 引用浮层出现时暂时隐藏导航。预览、键盘和窄窗口表现见 [UI/UX](../work/ai-conversation/ui-ux.md#4-会话内对话跳转)。

## 4. 助手模型选择持久化

- 对话模型统一在 AI 助手输入区选择，模型与支持的思考档位立即全局保存。切换已有会话、新建会话、关闭助手或重启应用均使用最近成功保存的选择。
- 设置 → AI 连接只管理供应商和模型配置、选择导入模型；去掉「应用 / 已应用」、主模型标记及用途下拉。导入模型可独立选择，未单独设置时跟随 AI 助手模型。
- 选择保存到 APP_ROOT 内现有数据库的 `ai_connections`，不新增 schema 版本。旧集合的 chat 绑定作为初始选择；旧会话选择与助手草稿里的 choice 不再覆盖全局选择。
- 保存成功后才回显新模型；保存期间暂缓提交新消息，失败保留原选择和输入，允许重试。已受理的轮次、队列与自动重连沿用受理时配置，历史保留实际使用的模型与档位。
- 总结、计划等共用对话模型的任务沿用助手当前选择；独立导入绑定、模型参数默认值和专用记忆维护模型继续按各自配置解析。切换模型不重置运行预算或工具权限。

### 4.1 设置与日历的当前页面适配

- 主窗口不再将设置、日历强制登记为无正文页面。助手输入区分别显示「设置 · 当前分区」和「日历 · 选中日期」，沿用原页面定位入口。
- 九个设置分区逐项登记允许读取的展示数据；常规包含实际主题和快捷键，关于包含实际安装版本、检查结果、检查时间、更新设置和 GitHub 主页。分区切换与设置状态变化同步更新，未保存的配置草稿标明草稿。
- 不扫描 DOM、输入框或浏览器存储，不序列化整份连接配置；密钥与密码仅提供配置状态，连接地址及请求头不进入正文。记忆管理只登记管理状态、筛选和数量，记忆正文仍遵循记忆工具的既有读取策略。
- 日历包含当前浏览月份、真实今天、选中日期、月历计划与到期 / 逾期标记、自主计划的完成状态和当前筛选的合并学习队列。月份与选中日期分别登记，翻月不将当天队列误写成浏览月份的队列。
- 加载、失败和空态明确区分；快照仍绑定消息提交时刻，切页、切分区、选择日期、修改筛选不会改变已提交消息或插话的页面。正文沿用 32,000 码点上限和既有工具分段读取，不自动注入模型请求，不新增数据库迁移或落盘目录。

验证：前端相关 **13 文件 / 106 项**、后端资料读取 **12 项**全部通过，无失败、跳过或未处理错误；前端构建及后端隔离打包通过，开发 JAR 已同步。具体用例与验证边界见[测试清单](../test/QA_CHECKLIST.md#模块三十二设置与日历的当前页面适配v081)。

## 6. 本版暂不纳入与推进约定

- 读取工具的向量检索接入、长期记忆的向量索引重做、联网搜索及其它尚未排期候选。
- 跨会话全文搜索、消息分支树或新会话组织体系；跳转只作用于当前会话。
- 重试不扩展模型权限、自动更换供应商或重放交付未知的写操作；沿用 APP_ROOT 便携落点、现有并行 / 队列 / 插话与停止规则。

三项已按「需求 → UI/UX → 规格 → 实现与验证」完成。普通重试调整和模型持久化本轮通过前端 124 项（另 2 项既有跳过）、后端 10 类 115 项，前后端构建及设置落盘 / 静态便携审计通过，开发 JAR 已同步。前次全量验证基线为前端 935 项通过、4 项既有跳过，后端 1531 项通过、3 项既有跳过，构建和相关便携审计通过；刻度与悬停修正另通过 54 项相关前端回归、前端构建和草图离线交互检查。随后将间距调为 10px，导航 9 项、前端构建和草图复验通过，用户已确认前次悬停流畅。详细范围及尚未执行的尺寸观感、DPI / 读屏和真实供应商验收见实施计划与测试清单。施工材料保留在 `docs/work/ai-conversation/` 至下一版本开始前统一归档。当前[发行准备说明](../release/v0.8.1-release-notes.md)已补齐，云端与本地打包默认版本同步为 v0.8.1；实际发行状态以 GitHub Release 为准。
