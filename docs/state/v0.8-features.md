# v0.8 功能需求清单

> 状态：开发中（2026-11-11）。整窗框架 [UI/UX](../work/ai-window/ui-ux.md) 已人工确认；四个切片均已实现并完成自动化验证，待用户验收；真实供应商、多显示器、系统分屏、缩放与读屏尚未验证。v0.7.3 已由用户确认完成并[归档](../archive/v0.7.3/README.md)；已落地能力仍以[全局功能清单](../features.md)及现有状态文档为准。

## 1. 目标与已确定方向

将 AI 助手从遮挡主界面的模态侧栏改为**独立桌面窗口**。用户可以一边操作笔记、题库和错题，一边与 AI 对话；需要并排时使用系统分屏。独立窗口承载会话管理、消息输入与阅读、模型选择、工具活动及运行状态，形成完整的 AI 助手工作界面。

产品定位遵循[全局边界](../features.md#4-non-goals当前明确不做)：当前不规划 AI 编程工具或通用 Harness，助手只使用软件内置或明确接入的工具，没有任意本地文件修改、Shell 或通用脚本执行能力。软件内学习资料的读写继续通过既有业务工具完成；之后的外部搜索也按软件接入工具规划。

- 主业务窗口保持可操作，不再因打开助手而灰屏或阻断操作。保留右上角入口、已有快捷键和业务定向入口，不恢复右下角悬浮按钮。
- 全面优化聊天体验，同时保留已有会话、附件、记忆、20 个工具、跨会话协作、并行运行、排队与插话能力。
- 在对话中选择供应商、模型及模型支持的思考档位；以当前上下文占用说明容量，不增加“最近对话保留条数”设置，也不恢复顶部常驻页面上下文卡片。

下列清单是本版建议范围。功能边界先明确，布局、控件、菜单、视觉样式及具体状态交互留到各切片 UI/UX 设计时确认。

## 2. 功能目录

| 编号 | 功能 | 用户可获得的能力 | 范围 |
|---|---|---|---|
| F01 | 独立助手窗口 | 打开 / 唤回独立窗口，主界面可继续编辑；支持正常移动、缩放、最大化与系统分屏；重开恢复会话和运行状态 | MVP 必需；建议整个应用复用一个助手窗口，窗口内管理多个会话 |
| F02 | 主界面与助手协作 | 从业务页携带明确目标唤起助手；工具读取主业务页，点击资料来源返回主窗口；AI 修改资料后两个窗口显示一致 | MVP 必需；继续复用现有资料与工具，不复制一套业务页面或数据库 |
| F03 | 对话模型与思考档位 | 在对话中查找并选择已配置供应商的模型，调整当前会话的 effort，知道实际使用了什么模型与档位 | 本版核心；供应商密钥、能力与容量仍在 AI 连接中维护 |
| F04 | 会话管理与导航 | 在独立窗口切换、新建、查找和管理会话；保留自动标题、重命名、复制链接、导出、删除及运行标识 | 本版核心；先支持标题筛选，不引入项目 / 文件夹 / 多层组织体系 |
| F05 | 消息阅读与输入 | 充分利用独立窗口空间阅读长回复；流式输出时自由滚动；文字、图片和引用输入及常用消息操作易于使用 | 本版核心；兼顾宽窗口、系统分屏后的窄窗口、缩放和键盘操作 |
| F06 | 思考与工具活动 | 清楚看到等待、思考、工具执行、回答、完成或失败；能按需查看工具状态和来源，长任务不挤占正文 | 本版核心；优化已有活动展示，不展示供应商未提供的内部思考或敏感原始参数 |
| F07 | 并行、排队与插话 | 当前会话回复时继续输入；区分待发消息、插话与输入草稿；管理后台会话运行、暂停、停止及接续 | 本版核心；沿用已实现语义，重点改善可见性与操作连贯性 |
| F08 | 当前上下文与用量反馈 | 了解当前会话送入模型的上下文占用、模型窗口容量，以及已有的本轮用量 / 上下文审计信息 | 本版核心；区分估算与实测，不扩展成独立费用报表或压缩设置页 |

## 3. 关键功能边界

### 窗口与跨窗口状态

- 首期建议只打开一个可复用的助手窗口；重复点击入口唤回已有窗口。多会话并行不等于每个会话都创建一个系统窗口。
- 收起或关闭助手界面不应隐式停止正在执行的回复；应用仍在运行时，任务和队列继续，重新打开能接回实际状态。主动停止、关闭窗口和退出应用需要有明确区别；关闭主窗口、退出确认及重开恢复的具体交互在首个切片中确定。
- 会话选择、草稿、附件、阅读位置与任务状态不因窗口切换串到其他会话；历史、模型设置、工具开关及资料修改在两个窗口间保持一致，不能重复发消息或重复执行工具。
- 记忆窗口大小、位置等必要偏好，显示器变更后窗口仍可见；延续 APP_ROOT 便携落点，不引入系统目录、注册表或第二个后台服务。
- “当前页面”仍指主业务窗口的内容。消息、排队和插话各自绑定提交时的业务目标；打开助手、切页或后台执行不能悄悄换目标。主窗口未提供有效页面时明确不可用，指定资料的读取仍按实际可用性处理。
- 资料来源在主业务窗口定位，会话链接在助手中定位；切换只响应用户操作，不因后台工具完成而抢夺正在编辑的位置或焦点。

### 模型与思考设置

- 建议采用“新会话默认跟随全局主模型，当前会话可显式选择模型”的方式；调整某个会话不改其他会话、全局主模型或导入模型。选择结果能够随会话恢复。
- effort 只提供该模型在设置中声明支持的档位，默认沿用模型默认值；服务默认表示不额外指定参数。没有 `ultra` 档位，不把并行代理模式当成思考强度；预算型模型按已有能力适配，不强造统一档位。
- 已开始的轮次保持其模型与参数；已受理的待发消息保留提交时配置，后续改选不追溯覆盖。插话沿用目标轮次的模型；具体生效提示在 UI/UX 中确定。
- 切换到不支持当前档位的模型时，明确回到该模型默认值；配置缺失、模型不可用或容量未填写时提示修复，不静默调用别的供应商。历史记录应能辨认实际使用的模型，而非随当前选择变化。

### 阅读、活动与接续

- 长回复、公式、表格、代码、图片和资料来源在宽窄窗口下保持可读；不出现多层狭窄滚动区。用户上翻后流式输出不强拉到底，可主动回到最新内容。
- 保留消息复制、现有导出、失败反馈及本轮上下文审计；增强前先迁好已有能力，不把新的消息分支、版本树或多模型对比默认纳入范围。
- 工具活动区分运行中、成功、失败、跳过与结果待核对；折叠选择和阅读位置不被增量更新反复重置，重开窗口显示实际进展。
- 保留“正在回复，可先输入下一条问题”文案。普通发送排队接续，插话在下一次模型请求前加入当前轮次，不中断已开始的输出或工具；暂停、停止、重启和交付未知继续遵守既有恢复规则。
- 新建入口和删除当前会话后只显示新会话页；首条有效消息发送前不创建空记录。其它会话可继续运行，各自停止互不影响。

### 上下文占用

- 展示与当前模型窗口相对应的上下文占用，说明是最近实际请求还是待发送估算；工具多次往返的累计用量不能冒充一次请求的上下文长度。
- 历史、系统提示、记忆、资料 / 工具结果及输出预留会影响容量；能取得可靠分项时才提供详情。缺少供应商 usage 时明确未知或估算，不伪造精确 token 数。
- 保留已有上下文处理与审计入口；确有裁剪或摘要时如实反馈。临近容量上限提供可理解的提示，不要求用户手动选择保留几条消息。

## 4. 建议的纵向切片顺序

| 顺序 | 切片 | 最小可验收闭环 |
|---|---|---|
| 1 ✅ 已实现 | 独立窗口 MVP（F01 / F02） | 主页面打开助手 → 发送问题 → 工具读取该页 → 流式回答 → 来源回到主页面；期间主界面可编辑，关闭再打开助手能恢复，既有并行 / 队列 / 工具不退化 |
| 2 ✅ 已实现 | 会话模型与 effort（F03） | 会话中选择供应商 / 模型 / 档位 → 发起真实请求 → 查看实际选择 → 切换会话与重开仍正确；已有轮次及待发项配置不被覆盖 |
| 3 ✅ 已实现 | 上下文反馈（F08） | 发送包含历史与工具结果的问题 → 查看可信的上下文占用和本轮用量 → 切模型后按对应容量解释，缺失或估算明确 |
| 4 ✅ 已实现 | 会话与消息体验完善（F04–F07） | 查找会话 → 阅读长回复与工具活动 → 排队或插话 → 切到另一个运行会话 → 回来继续；宽窄窗口、键盘操作与自由滚动可用 |

四个切片共用 `docs/work/ai-window/` 的 UI/UX、[规格](../work/ai-window/spec.md)与[计划](../work/ai-window/plan.md)，各片开工时原位补充。验收后的修订记录在规格的「验收修订」两节：第一轮为入口切换、面板宽度可调、会话置顶；第二轮为恢复窗口固定（垂直图钉）、标题双击改名、选中文本的复制 / 引用、上下文面板只留输入与输出。窗口内三个新快捷键可改绑。

## 5. 本版暂不纳入（Non-Goals）

- 自建窗口停靠 / 分屏管理器、恢复模态侧栏、任意数量的独立会话窗口、多窗口复杂布局保存。
- 新的 Agent / 助手角色体系、项目工作区、消息分支树、多模型同题对比；不照搬编程工具的 Git / 文件 diff / 终端界面。
- 全局系统提示词编辑、独立用量 / 费用统计页、自动压缩策略设置及联网搜索服务配置；仍为后续候选，不因聊天改版自动入版。
- 新增 MCP / 插件平台、通用电脑控制、系统截图或 OCR、资料移动 / 批量删除 / 删除恢复、跨设备同步与公开分享。
- 重做记忆索引、修改全局运行限制或默认工具开关；不将旧业务重构混入窗口迁移。

2026-11-11 查阅下列官方文档与官方仓库，仅参考窗口、会话、输入与阅读、工具活动等交互。编程工具的文件编辑、Shell、执行环境及 Harness 能力不属于本项目规划；下表也不代表本项目已实现外部产品的功能。

| 参考 | 关注点 | 本版取舍 |
|---|---|---|
| [Cherry Studio 官方仓库](https://github.com/CherryHQ/cherry-studio) | 多供应商与模型、会话管理、丰富内容呈现 | 借鉴完整聊天客户端的组织能力，不引入多助手体系或同时询问多个模型 |
| [Chatbox 官方更新记录](https://chatboxai.app/en/help-center/changelog) | 会话级模型选择、可搜索模型及思考深度、上下文占比反馈 | 采纳会话选择和容量反馈，不采用按消息条数配置历史 |
| [Qoder 聊天概览](https://docs.qoder.com/user-guide/chat/overview)与[工具及消息队列](https://docs.qoder.com/user-guide/chat/tools-new) | 独立聊天窗口、并行任务观察、工具与排队 / 插话 | 借鉴并排工作和运行反馈，不引入编程工作区概念 |
| [Codex app 官方入口](https://developers.openai.com/codex/app/features/)与[项目及会话管理](https://learn.chatgpt.com/docs/projects) | 集中管理会话、继续已有工作 | 保留本项目已实现的并行、排队与插话，简化可见状态；项目、Git 和计划模式不纳入 |
| [VS Code Copilot Chat 界面](https://code.visualstudio.com/docs/agents/run/chat-view)与[对话操作](https://code.visualstudio.com/docs/chat/chat-overview) | 独立聊天窗口、会话模型选择、并行与运行状态 | 直接以独立窗口为产品方向，不保留多种停靠位置或照搬编辑器布局 |

本版功能只在本文维护；实现后再更新相应状态文档，发布前同步全局功能清单。v1.0 之前仍为不保证稳定性的预发行版；发布工作流版本到本版发布准备时再调整。
