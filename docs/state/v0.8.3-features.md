# v0.8.3 功能规划

> 状态：已规划，尚未实现。当前开发版本仍为 v0.8.2。2026-11-15 按用户决定，将 harness 调查后的上下文策略调整与上下文压缩一起纳入 v0.8.3。

## 1. 目标与现状

建立一份当前模型上下文视图，统一实际发送、窗口占用统计、上下文详情和压缩触发条件。保留用户完整原始历史，让长会话在模型窗口内继续工作，同时减少重复携带大块工具结果。

v0.8.2 已区分当前全局占用、供应商请求实测和会话累计用量，但发送仍采用既有有界历史投影（约 2,400 Token 的历史预算、最多扫描 32 轮）。占用统计与外发历史裁剪目前不是同一份视图；这项差异与压缩机制在本版一起修正，不将当前统计直接作为已经统一的发送量。

共同结论：单纯提前裁掉大部分历史虽然省输入，却容易丢失连续任务状态；成熟 harness 通常保留近期完整内容与受控工具证据，再在窗口需要时压缩。更换策略不承诺固定准确率或 Token 节省幅度。

## 3. F01：窗口阈值与上下文压缩

- 根据当前会话所选模型的窗口、输出预留和用户设定阈值判断是否需要压缩。阈值、近期保留预算等具体默认值在实施设计中确定。
- 达到阈值时生成结构化续接摘要，包含当前目标、约束、已完成事项、关键结论、待办和必要来源引用。摘要替代较早上下文的呈现，原历史在 APP_ROOT 内保留。
- 保留近期完整问答与必要工具调用 / 结果配对。较早的大结果保留摘要、关键片段或来源定位，需要时通过已有读取工具补取。
- 失败、停止、预算不足或未解锁时不破坏原上下文，不假装已经压缩成功。摘要版本、覆盖范围和失效条件继续使用现有代数 / revision / coverage 机制。
- 同一会话的运行、工具往返、断流重连和原地重试遵守同一份上下文视图与预算；压缩不触发重执行已完成工具，也不替换计费用量账本。

## 4. F02：统一上下文策略

- 替换固定激进的历史裁剪，改为随模型窗口计算的预算；发送内容、当前占用、详情及压缩阈值来自同一份投影，不能各自拼装。
- 普通思考文本与供应商协议要求的签名 / 加密推理状态分别处理。可省略的普通思考不长期累积；必须回传的协议状态按供应商 / 模型兼容规则保留，不能一概删去。
- 工具定义、参数、结果各自有预算。尽量保留近期完整证据，较早长结果有界化；按需加载工具 / 来源时不扩大授权。
- 保持稳定系统前缀和尽可能稳定的上下文顺序，减少对提示词缓存的破坏。缓存命中率和会话累计用量继续与窗口占用独立展示。
- 通用结构化摘要加近期原文作为跨供应商基础方案；原生 compaction / checkpoint 在能力明确、切模兼容与可恢复性验证后再作可选优化。
- 所有原历史、摘要、来源关联和临时材料继续落在 APP_ROOT；不增加系统目录、注册表、登录浏览器或外部缓存依赖。

## 5. 验收要求

验证发送 / 占用 / 阈值的一致性、压缩前后数值变化、摘要覆盖与原历史保持、长工具结果的关键证据与配对、模型切换、断流恢复、停止 / 压缩失败、原地重试与旧摘要失效。核对普通思考与协议状态的供应商差异，以及稳定前缀的缓存行为。

压缩产生的实际模型请求仍逐次记账，计费用量只增加、不因上下文变短而扣减。需要针对真实供应商验证协议和缓存口径；模拟测试不作为原生压缩兼容承诺。完成实现与验证后再更新为已完成状态。
