# 会话派发实现规格

> 2026-11-09。基于已确认 [UI/UX](ui-ux.md)，本切片不实现人工排队输入框。

## 运行与受理

- 后端 `SessionDispatchService` 持有任务；SSE 只是订阅，断开不取消。人工发送仍用原 v2 请求与 requestId，同会话人工重复发送返回忙碌；工具发送可以 FIFO 排队。统一调用 `AiService` 的轮次、加密、用量、标题及工具循环。
- SQLite schema 13 增加派发收据，只保存 requestId、目标、来源调用身份、输入指纹、状态与时间；正文、附件、密码、模型配置仅在进程内持有。排队正文执行时才进入原有加密历史和容量事务；受理不承诺未来仍有存储空间，执行时容量不足则失败并取消后续项。
- 创建普通会话与首条收据在一个立即事务提交；消息/配置/解锁校验在此前完成。未受理不留下空会话。队列及运行总量有界（64 项），超出明确拒绝。每会话最多一个执行任务；不同会话独立执行。模型配置在受理时冻结，API Key 不进入新表。
- 同来源 requestId + toolCallId 幂等，参数改变拒绝冲突；不同调用相同文本允许。`send_message` 只接精确链接/ref/ID。目标范围和历史不被来源替换，新建继承来源范围。
- 派发链共享现有时间、输出和工具预算；禁止向自身或祖先派发。执行线程与上游并发许可分开，等待结果时不占上游许可，避免父会话等子会话死锁。
- 只有正常 COMPLETED 才启动下一项；失败、停止取消本目标尚未执行的项，其他目标继续。重启将遗留排队项标 CANCELLED、执行项标 INTERRUPTED，不重放。删除、清理和归档在有收据未结束时拒绝。

## 接口与工具

- `create_session({message,title?})`；`send_message({session,message})`。文本非空，最多 2000 码点且参数 JSON 最多 16 KiB。工具结果为 CREATED/SENT/QUEUED，并带 session、requestId、queuePosition；均只表示受理。
- `read_session` 增加 `requestId`、`waitSeconds`（0–60）；与普通历史游标互斥，精确校验所属会话。进行中返回状态，终态只读取对应轮的问答，正文上限沿用 6000 码点并明确截断。不存在、清理、需解锁真实返回；不能拿其他轮次冒充。等待可取消且有截止时间。
- `list_sessions` 条目增加运行状态和 queueCount。
- 原 `/chat/stream` 保持事件形状，生产入口交给后台服务；`/chat` 同身份等待该任务。新增 `GET /sessions/runtime?sessionId=` 返回列表状态及所选会话当前/最近任务快照；新增 `POST /sessions/{id}/stop` 以 expectedRequestId 防迟到取消伤到新轮。
- `/turns/{requestId}` 能查询尚未开始的收据；前端只读恢复，不自动重放已受理请求。运行快照在内存有界保留，终态正文从现有加密历史读取。

## 界面

- hook 按 sessionId 维护活跃请求；通过运行快照恢复外部工具启动的会话和断线内容。当前会话忙碌才禁用发送，停止后等后端终态。
- 列表/当前入口独立运行图标、待发送数量和停止菜单；标题生成状态放辅助行。暂时失联显示静止重连状态。
- 每会话保存本次前端生命周期内的草稿、附件、阅读位置；切换不丢输入、不把后台消息写入当前会话。
- 写工具活动仅保留安全受理摘要、精确目标链接和发送标识，不将发送正文或历史原文写入活动日志。打开目标是显式操作，原有只读引用预览保持可用。

## 验证

覆盖不同目标并行、同目标 FIFO/最新历史、重复受理、错误与停止、重启不重放、精确结果读取、配置快照、链预算/循环、删除清理保护；前端验证多会话草稿与状态隔离、断线恢复、停止确认和菜单。使用工作区隔离数据及虚构模型做浏览器验收。
