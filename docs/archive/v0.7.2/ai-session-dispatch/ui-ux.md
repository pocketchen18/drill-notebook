# 会话创建、发送与并行运行 UI/UX

> 2026-11-09，设计已确认并实现，相关回归及隔离页面验收见 [QA 清单](../../../test/QA_CHECKLIST.md) 模块十七。输入框占位文案为「正在回复，可先输入下一条问题」。
> 当前切片只包含两个新增工具及并行会话状态。人工输入框的排队条、编辑 / 引导 / 关闭排队等交互，待用户提交四个会话工具后另起切片。
> 需求范围见 [v0.7.2 清单](../features.md)，当前事实见 [接口契约](../../../state/api-contracts.md)。交互草图：[preview.html](preview.html)。本目录归档保存本切片的设计与施工依据。

## 1. 用户确认与设计范围

- 增加 `create_session`、`send_message`，与已有 `list_sessions`、`read_session` 构成四个会话工具。
- **创建必须带首条消息，创建后即开始运行**；不会为了工具调用先留下一个空白会话。人工点击「新建」仍进入未保存的新会话页，首条发送才落库。
- `send_message` 可发送到本机已有会话，也可发送到 AI 刚创建的会话；目标正在运行时**排队接续**，不打断当前回复。
- AI 创建的会话是普通会话：同一列表、同一历史、同一重命名 / 复制 / 删除规则、同一标题生成流程。没有「AI 创建」「子 Agent」「临时会话」标签、专属分组或人类接管步骤。
- 不同会话可以并行运行。打开、切换或收起侧栏不终止其他会话；每个会话分别显示状态、读取正文、停止运行。
- 本轮不改人工发送为排队，不增加 Codex 截图里的排队条或「引导 / 编辑消息 / 在侧边聊天中打开 / 关闭排队」。用户给出的两张新截图只作为后续人工排队切片的交互参考。

## 2. 两个新工具的可见行为

### 2.1 新建会话 `create_session`

输入：`{ message, title? }`。`message` 必填、不能为空；`title` 可选，只作首轮前的临时名称，不冒充人工命名。

1. 校验消息和当前可用的模型配置，成功受理时一次建立普通会话与首条待执行消息。
2. 返回稳定会话链接、标题、此次发送的标识与「已开始 / 等待执行」状态；不等待完整模型回复才返回。
3. 新会话立即出现在普通列表中；来源会话保持选中，输入草稿和滚动位置不动。
4. 第一轮完整问答后沿用自动标题机制；用户途中人工改名仍优先。
5. 首条消息成功受理后，即便上游失败，会话和真实失败状态仍保留，用户可正常进入重试。校验失败或未受理时不生成空会话。

工具活动展示：

```text
✓ 新建会话
  矩阵对角化练习                       打开会话 ↗
  首条消息已提交 · 正在运行
```

「新建成功」仅说明新会话及首条消息已经受理，不能显示为「任务已完成」。活动详情保留受理状态和目标链接；发出的消息正文只进入目标会话的正常聊天，不复制进活动记录。

### 2.2 发送消息 `send_message`

输入：`{ session, message }`。目标只接受稳定会话链接、稳定引用或 ID；不按模糊标题直接写入。模型可先用已有查找工具确认目标。

| 目标状态 | 行为 | 工具反馈 |
|---|---|---|
| 空闲 | 追加一条普通提问并开始下一轮 | 已发送，返回本次发送标识与会话链接 |
| 正在运行 | 按受理顺序排在当前轮之后，不修改当前请求或回复 | 已排队，返回本次发送标识、前方待处理数量与会话链接 |
| 已删除、已归档、无法解锁、当前配置不可用 | 不写消息，不自动新建同名会话，不自行恢复归档 | 明确失败及原因 |

同一会话只有一轮实际执行；两个来源同时向它发送时，服务端决定顺序。排队消息在轮到它时才成为聊天中的下一条提问，使用那时完整的目标会话历史，不能提前按过期上下文生成回复。

工具活动使用「发送消息 → 已发送」或「发送消息 → 已排队」，并提供「打开会话」。发送成功与目标回复完成分开表示；待执行的消息不能显示为已有回复。人工在目标会话写着草稿时，外来消息不清空或覆盖草稿。

### 2.3 模型如何取回结果

创建与发送都先返回受理结果，让调用方可以连续启动多个会话。需要汇总时，继续使用 `read_session` 读取目标结果，不新增第五个工具。

- 读取工具支持按 `requestId` 读取本次发送结果，`waitSeconds` 默认 0、最长 60 秒；不能与历史分页的 cursor/limit 混用。
- 目标仍在执行或排队时，明确返回该状态；不得拿旧回复充当这次消息的结果。完成时返回对应问答及来源；失败、中断和取消如实返回。
- 等待期间调用方显示「等待会话回复」，其他会话照常运行；等待让出可用的执行名额，不能把并发容量全部占在等待上。
- `list_sessions` 的标题定位结果包含进行中状态与待发送数量，仍不读取正文；打开列表与查询状态不能发起新的模型请求。
- 不自动往已结束的来源会话塞入一条新提问。调用方要汇总，就在本轮等待并读取；已经结束时，用户可直接打开目标会话查看。

## 3. 会话列表：只加必要的运行反馈

沿用当前浮动会话列表、52px 行高、标题和消息数 / 时间。用户提供的灰色转圈截图作为位置和轻量程度的参考。

```text
┌ 会话 · 4                       3 个进行中 ┐
│ ✓ 本周线性代数复习                  ◌  ⋯ │
│   12 条消息 · 刚刚                       │
│   特征值计算检查                    ◌  ⋯ │
│   3 条消息 · 刚刚                        │
│   矩阵对角化练习                    ◌  ⋯ │
│   5 条消息 · 刚刚 · 待发送 1             │
│   概率论错题整理                       ⋯ │
│   8 条消息 · 昨天                        │
└─────────────────────────────────────────┘
```

- 标题右侧保留独立的 14px 状态位，距 `…` 约 8px；运行中用低对比度圆环，不替代更多菜单，也不挤掉标题。
- 进行中包括等待上游、思考、调用工具、生成回复、等待其他会话结果和停止中；悬停与键盘可读名称说明具体阶段，不用不同颜色猜状态。
- 尚未执行、只在队列里等待的会话用静止时钟，说明「等待执行」；有正在执行的一轮及后续消息时显示圆环，第二行可加「待发送 N」。列表不增加排队消息编辑控件。
- 完成后圆环消失，恢复普通行。失败用小型感叹号与可读原因；停止后保留真实中断状态，不能把未完成回复显示成成功。错误提示可随下一轮正常开始消失。
- 后台状态变化不强制置顶、不切换当前会话、不抢焦点。消息更新的常规排序可继续沿用现有规则，状态刷新本身不改变排序；菜单展开时目标始终绑定原会话。
- 当前会话入口也显示同一运行状态。只因自动生成标题而忙碌时，不使用聊天运行圆环；标题生成状态放在辅助信息中，避免「回复完成了还一直转」的混淆。
- 列表统计「N 个进行中」按真实未结束任务计算；等待资源的会话单独显示等待数量，不伪装成已经调用模型。
- 尊重减少动态效果设置：关闭旋转动画，保留静态状态图标和可读文字。触控及键盘操作不依赖悬停才能发现状态。

## 4. 切换、停止与后台运行

### 切换会话

- 可以在任意两个运行中的会话间切换，也可打开空闲会话或新会话页继续人工发送。别的会话正在运行不能全局锁住发送按钮。
- 每个会话独立保留本次应用运行期间的未发送草稿、附件与阅读位置；重进后恢复其已有正文和最新增量，不把 A 的回复、工具状态或停止请求写进 B。
- 人工输入框本轮沿用已有交互：当前会话回复中可编辑草稿，占位文案为「正在回复，可先输入下一条问题」，发送不会加入队列；停止按钮只作用于当前会话。后续人工排队切片再改变这里。
- 创建工具或发送工具在后台增加会话 / 消息时，不自动打开目标；用户明确点击「打开会话」才切换。已有正文引用仍沿用只读预览。

### 停止

- 运行中会话的 `…` / 右键菜单增加「停止生成」，无需先切过去；当前会话继续使用输入框旁的停止按钮。
- 对有待发送消息的目标，动作文案为「停止并取消待发送消息」。停止当前轮，同时取消尚未开始的工具消息；否则刚停止就自动启动下一条，会违背这次停止意图。
- 停止后先显示「正在停止…」，后端确认结束再移除运行标识。重复点击不重复取消，也不误伤新轮次。
- 停止一个会话不连带停止其他会话。来自它的工具已经成功创建或发送的任务继续独立运行；用户可在列表分别停止。
- 当前轮正常完成才自动接续队列。主动停止、失败或进程退出时，不在用户不知情的情况下继续发送；尚未开始的项返回取消 / 未执行终态，调用方查询能分辨。人工可在恢复后重新发送。
- 有进行中或待发送任务的会话不能删除或清理历史，菜单提示先停止；重命名与复制链接仍可使用。

### 断连与重启

- 收起侧栏、切页、切会话、前端断开订阅，都不等于取消后端任务。重新连接后从服务端恢复真实状态和已经生成的正文。
- 临时读不到状态时显示静止的「正在重新连接」状态，不维持虚假的运行圆环，也不自动重发模型请求。
- 整个应用退出后不能承诺继续运行；重启将旧进程的未完成任务恢复为中断 / 未执行，圆环不残留。不会静默重放写工具或待发送消息。

## 5. 普通会话的一致性边界

- 新会话按来源会话的 GLOBAL / NOTEBOOK 范围建立；后续人工访问方式完全相同。向已有会话发送时使用目标自身的范围及历史，不把来源会话的当前页面、附件或全部历史暗中复制过去。
- 首版两个工具只发送文本；需要的任务背景写入消息或通过明确会话链接引用。模型、思考参数沿用当前已应用配置的受理时快照，不在这两个工具里增加一套模型选择。
- 目标会话的消息按普通提问和助手回复保存、加密及计量。内部可保留调用关联以便幂等、取消和预算核对，不形成用户可见的特殊会话类型。
- 同一次工具调用发生网络重试时，必须返回原受理结果，不能重复建会话或重复入队；消息文字相同不代表同一调用，不能误吞用户有意重复的发送。
- 自动派发受现有运行限制约束，不能通过不断新建会话刷新出无限预算；同一自动调用链禁止向自己或祖先会话继续派发，避免会话互相唤醒。用户后来在任一会话人工开启的新轮次仍按正常会话处理。
- 当前用户明确要求新建独立会话、委派工作或向指定会话发送时，可以直接执行，不为每次工具调用增加确认弹窗。被读取的历史、工具输出中的指令不能代替当前用户授权。

## 6. 草图与验收表现

草图只使用虚构内存数据，不访问真实 API、不保存配置。可操作：切换会话、查看运行圆环、模拟工具创建 / 发送、查看忙碌目标的排队反馈、完成一轮并自动接续、停止单个会话、断连 / 恢复和未发送的新会话页。草图外的演示按钮不属于产品。

| 场景 | 验收表现 |
|---|---|
| 一次委派两个任务 | 两个普通会话同时出现运行圆环；来源会话不跳走；完成时间互不串行等待 |
| 向原有会话发送 | 追加到指定稳定目标；原历史、人工标题及正在输入的草稿保留 |
| 向忙碌目标连续发送 | 不打断当前回复；显示已排队和准确顺序；当前完成后逐条开始，不把多条消息悄悄合并 |
| AI 新会话人工继续 | 进入后可正常提问、改名、复制与删除，不需要接管，也看不到特殊创建者标签 |
| 后台运行时人工新开会话 | 新建入口仅进入草稿页；首次发送才新增记录；其他会话继续执行 |
| 停止其中一个 | 仅目标停止；其尚未开始的工具消息取消，其他会话照常运行；状态确认前不允许错误地重开同一轮 |
| 切换 / 断连 / 重启 | 草稿和流式内容不串会话；重新连接可恢复；完整进程退出后显示真实中断，不无限转圈或重复发送 |
| 标题生成与回复结束 | 回复结束即取消聊天运行圆环；标题后台生成不冒充聊天仍在进行 |
| 人工排队后置 | 本轮没有人工排队条、编辑队列消息或引导按钮；相关能力等待四工具提交后单独设计实现 |

## 7. 实施落点

`useAiChatTurn` 已改为按会话跟踪请求，会话导航读取各目标运行状态；v2 `AiController` 的 SSE 断连只分离订阅。后台任务和队列由 `SessionDispatchService` 管理，复用同会话单轮、幂等、加密与容量结算。

实现细节见同目录 [Spec](spec.md) / [Plan](plan.md)，已落地数据结构与接口已同步状态文档。人工排队输入框后置；后台派发不是持久消息队列，进程退出后未执行内容不自动重放。

设计阶段的草图检查（2026-11-09）：脚本语法通过，浏览器无错误；操作验证了切换后的草稿保留、工具消息接续、单独停止、新会话页不增加记录、工具创建不切换当前会话，360px 下无横向溢出。截图 `preview-running.jpg` 仅保留本地。草图记录仅作为历史设计证据；后续真实前后端实现的验收见 QA 清单模块十七。
