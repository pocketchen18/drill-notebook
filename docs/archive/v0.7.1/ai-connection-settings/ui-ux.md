## 1. 当前切片与设计目标

最小闭环：**添加供应商 → 配置连接 → 添加多个模型 → 单独设置模型 → 应用一个模型 → 清楚看到当前使用项**。

用户已明确的边界：

- 本轮改造「设置 → AI 连接」；AI 侧边栏的布局、聊天模型选择器和消息展示留到后续。
- 同时保存多个供应商，每个供应商下可保存多个模型；切换时不反复覆盖 URL、密钥和模型 ID。
- 流式输出、工具调用移入各模型独立的二级设置页，主页面只显示简短摘要。
- 借鉴用户提供的 Cherry Studio 截图：分组模型列表、行内设置入口、模型详情内分区编辑。截图中的模型名称和数值不作为真实能力或默认参数来源。

已确认方案：左侧供应商列表，右侧连接信息与模型列表；「应用」默认切换主模型，菜单可指定导入兜底；编辑连接和模型设置均使用右侧内容区的二级页面。

### 范围

### 新增连接与自动验证（用户已授权）

新增供应商保存成功后立即打开模型选择窗口，并自动获取一次模型列表。用户勾选后点击「验证并添加」，自动并发验证并逐项显示结果，无需再单独点击测活；列表获取失败或为空时可在同一窗口手动填 ID。已保存的供应商保留，即使没有模型验证通过也可稍后继续。

```text
添加模型 · 学习网关
  [搜索获取的模型…                         ]
  ☑ model-a     已匹配预设
  ☑ model-b     未匹配预设，可手动配置
  手动模型 ID [                           ] [加入待选]
                            [稍后添加] [验证并添加（2）]

验证模型 · 学习网关
  model-a                                 已添加
    文本请求       ✓ 通过（决定是否添加）
    图片请求       ✓ 通过
    工具调用请求   ✓ 通过，已开启
  model-b                                 验证中…
    完成后显示三项结果
                  [取消剩余验证] / [重试失败项] [完成]
```

- 采用直接展示三项结果的轻量列表。验证中只显示当前模型的进度，不假装三个探测已同时完成。成功后显示「已添加」；文本失败显示「未添加」，可重试未添加项，已成功模型不重复验证。
- 文本请求必须实际返回非空正文，失败则不添加且跳过其余两项；图片/工具失败不影响添加。失败仅表示本次未通过，不能断言永久不支持。
- 图片使用应用内存生成的测试图片，核对图片中的内容；工具使用无副作用测试工具，核对真实结构化调用及参数。仅 HTTP 200、普通文本自称支持工具，都不算通过。
- 工具验证通过时为新模型自动开启「允许工具调用」，未通过默认关闭。新建表单的开关不可手动改写，提示添加后可调整。只改变此模型偏好，不改变记忆页授权或注册任何真实业务工具。视觉验证结果记录在模型设置中，不自动改变侧栏布局。
- 验证同时运行最多 3 个候选模型，单次提交最多 20 个，其余显示「待验证」；完成一项立即补入下一项，结果保持原选择顺序。每模型仍先验证文本，通过后检测图片和工具，最多三次短请求，文本 30 秒、图片/工具各 20 秒超时。取消时停止排队并取消全部在途验证；重试跳过已添加项。选模型页面提示会产生少量用量，不发送用户会话、图片、笔记或记忆。
- 取消会停止当前探测及剩余队列，不提交尚未完成的模型；已添加模型保留。取消先等待后端确认，再结束前端等待并重载配置；取消接口超过 5 秒未响应时显示提示，等待当前请求结束，不继续队列。文本失败、取消或配置冲突不留下半个模型。
- 手动添加的二级编辑页使用同一验证入口；已有模型的保存不会自动重新验证或覆盖人工工具开关。单独「测试连接」仍按已有短文本检查工作，不改历史模型偏好。
- 保存连接与验证添加模型均不自动「应用」；用户在列表主动应用主模型，原主模型不变。

本切片包含：供应商增改删、模型获取与手动添加、分组/搜索、模型增改删、独立流式与工具设置、可选 Token 上限、测试连接、主模型与导入兜底应用、旧配置保留。

本次已确认扩展：获取模型时匹配本地预设，添加时自动补全可用资料；模型设置增加思考控制方式、可用档位和默认强度。最小闭环为「获取 → 识别预设 → 添加并查看设置 → 保存默认强度 → 请求实际生效」。

不纳入本切片：新的 API 协议、运行时云端模型目录、供应商自动测速/故障切换、已有模型的批量重新检测、模型价格、MCP 管理、记忆工具新增能力、视觉控制、图片生成/编辑、音视频、嵌入/重排、侧边栏模型/effort 选择器。嵌入与检索、记忆维护专用模型仍在各自领域中管理。

## 2. 用户概念与信息归属

| 概念 | 用户理解 | 放什么 |
|---|---|---|
| 供应商 | 一套连接，例如「学习网关」「备用账号」「本地服务」 | 显示名称、API 格式、Base URL、认证方式与密钥 |
| 模型 | 该连接下一个可以调用的模型 | 模型 ID、显示名称、分组、思考档位及默认值、流式输出、工具调用、可选 Token 上限 |
| 使用用途 | 软件在哪些任务中使用哪个模型 | 主模型；导入兜底（独立指定或跟随主模型） |

- 同一品牌可有多个供应商条目，用不同名称区分账号或端点；名称不决定协议。
- 同一个模型 ID 可以存在于不同供应商；同一供应商内不能重复添加相同 ID。ID 去除首尾空白后保留大小写，不擅自改写。
- 浏览中的供应商、编辑中的模型、已应用的模型是三种不同状态；选择高亮只表示正在浏览。
- 每个模型保存自己的设置；切换供应商、获取模型、应用别的模型都不重置它。
- 供应商共享连接配置，不在每个模型中重复放 URL 和密钥；需要不同连接时新增供应商。

沿用设置页现有顶部分区、字体和主题令牌。AI 连接内部使用列表—详情布局，避免继续叠加整页表单卡片。

```text
设置   常规  [AI 连接]  记忆  嵌入与检索  学习与复习  数据管理

当前使用   主模型：学习网关 / 通用对话
           导入兜底：跟随主模型
──────────────────────────────────────────────────────────────
供应商                  学习网关                         [更多 ⋯]
[搜索供应商]            OpenAI 兼容 · 2 个模型

[学习网关       主]     连接信息                  更多菜单：编辑连接
 2 个模型               OpenAI Chat Completions
 备用网关               https://example.invalid/v1 · 密钥已配置
 1 个模型
 本地服务               模型       [搜索名称或 ID] [获取模型] [+ 添加]

                       ▾ 常用
[+ 添加供应商]           通用对话       流式 · 工具     [已应用 ▾] [设置] [⋯]

                         study-reasoner
```

示例名称与域名仅用于说明，不表示内置供应商或实际模型能力。

### 3.1 当前使用条

- 固定在 AI 连接内容顶部，使用两行紧凑信息，不做两张大卡片。
- 主模型显示「供应商 / 模型名称」，为空时显示「未设置」，附「选择模型」定位到模型列表。
- 导入兜底显示「跟随主模型」或明确的供应商/模型；独立指定时提供「恢复跟随」操作。
- 点击已应用模型名称定位到对应供应商和模型，清除遮挡它的搜索条件、展开所在分组；仅定位，不重新应用。
- 该条始终显示已保存并生效的结果；应用失败时保留原值。
- 辅助说明仅一句：「主模型用于对话、总结、学习计划等 AI 任务。」不展开后端术语。

### 3.2 供应商列表

- 内容宽度 ≥ 760px 时采用约 232px 左栏 + 自适应右栏；左栏只放名称、模型数量和用途标记。
- 列表选中态用背景与文字强调；「主」「导入」为独立文字标记，不能仅用颜色区分。
- 搜索按名称或地址过滤；清空搜索恢复原列表，选中供应商不因过滤而被应用或删除。
- 添加按钮常驻；不预置几十个空供应商。空状态主操作为「添加供应商」。
- 顺序为创建顺序；本轮不加入拖拽排序、收藏或启停开关。
- 首次进入定位到主模型所在供应商；无主模型则定位第一个供应商。若开启界面状态记忆，可恢复最近浏览项，已失效则按上述规则回退。

### 3.3 连接摘要

- 已保存供应商默认展示紧凑只读摘要：名称、API 格式、Base URL、认证状态。供应商标题右侧的三个点展开纵向操作菜单，依次为「编辑连接」「删除供应商」；摘要区不再放重复的编辑按钮。
- 密钥只显示「已配置」或「无需密钥」，不展示原文，也不以一串星号假装真实密钥。
- 点击「编辑连接」后，右侧内容区整体切换为连接编辑页，隐藏原供应商标题、连接摘要与模型列表；左侧供应商列表和顶部当前使用条保留。
- 浏览状态下，模型列表是页面主要视觉区域；编辑完成后恢复列表。

### 3.4 模型列表

- 工具条：模型数量、名称/ID 搜索、「获取模型」「添加模型」。所有入口持续可见。
- 按用户填写的分组折叠展示；空分组归「未分组」。分组按名称排序，「未分组」在末尾，组内按添加顺序。
- 搜索匹配显示名称、模型 ID 和分组名；有匹配时临时展开相应分组，清空后恢复折叠状态。
- 每行首行是显示名称，次行是模型 ID；两者相同时只显示一行。全名可经聚焦/悬停提示查看。
- 右侧依次为配置摘要、用途标记、应用、设置、更多。模型名与「设置」点击打开二级页，**不触发应用**；按钮事件不穿透。
- 摘要最多显示「流式」「工具」两个中性标签，表示已保存配置为开，不声称经过能力验证。两个都关则省略摘要。
- 「设置」配齿轮图标与文字；窄屏可保留有可访问名称的图标按钮。「更多」收纳测试连接、删除；删除不紧贴高频应用按钮。
- 没有模型：提示「添加模型，或从供应商获取」，两个入口均可用。搜索无结果使用独立文案，不显示成供应商没有模型。

## 4. 供应商连接的新增与编辑

「添加供应商」打开一个短表单弹窗；「更多 → 编辑连接」进入右侧完整的二级页面，交互方式与模型设置一致。

```text
供应商                  [← 返回模型列表]
[搜索供应商]            编辑连接
                        学习网关
[学习网关       主]
 2 个模型               供应商名称    [学习网关                    ]
 备用网关               API 格式      [OpenAI Chat Completions   ▾]
 1 个模型               Base URL      [https://example.invalid/v1]
                        认证方式      [API Key                   ▾]
[+ 添加供应商]          API Key       已配置  [更换]

                        影响主模型；从下一次请求生效。
                                            [取消]  [保存连接]
```

- 编辑页顶部依次显示「返回模型列表」、标题「编辑连接」和已保存的供应商名称；进入时焦点落在标题，明确页面已经切换。
- 表单和底部操作在同一内容流中随页面滚动，不在下方保留固定或禁用的模型列表，也不覆盖列表。
- 保存或取消后恢复原搜索、分组与滚动位置，焦点回到供应商更多菜单入口。
- 返回、取消、Esc、切换供应商或离开设置均沿用未保存保护；有修改时提供「继续编辑 / 放弃修改 / 保存并继续」。

| 字段 | 控件/规则 | 默认与提示 |
|---|---|---|
| 供应商名称 | 必填文本；去首尾空白，1–60 字；同名给行内错误 | 无预填；例「学习网关」 |
| API 格式 | 单选下拉 | `OpenAI Chat Completions` / `Anthropic Messages`，与现有支持范围一致 |
| Base URL | 必填文本；须为无账号密码、无查询参数/片段的 HTTP(S) 基础地址；本地 HTTP 可用 | 不因选协议自动覆盖用户已输入的地址；实际路径归一规则在确认后由 Spec 明确 |
| 认证方式 | 「API Key / 无需密钥」 | 新建默认 API Key；无需密钥适用于免密服务 |
| API Key | 选 API Key 时必填；已有密钥可保留 | 已保存时显示「已配置」及「更换」；不回传已保存明文 |

- 新建保存只新增供应商；没有模型也能保存，不自动获取或应用。
- 编辑已有密钥：点「更换」才显示输入框；取消更换则保留原密钥。空输入不能被当成清空指令。可切换刚输入内容的可见性，不支持揭示旧密钥。
- 从 API Key 改为无需密钥时，说明「保存后将移除此连接的密钥」；保存成功才移除，取消不改变原值。
- 名称、URL、协议、认证均独立于模型设置。修改 URL/协议/认证后测试状态变为「未测试」，显式保存过的模型偏好仍保留。
- 若该供应商已有应用用途，保存按钮上方显示「影响主模型 / 导入兜底；从下一次请求生效」。保存不替换已运行请求的连接。
- 保存中锁定当前表单提交；成功返回模型列表；失败停在编辑页并保留输入和错误，允许重试。不得用旧查询结果覆盖未保存输入。
- 存量 `mock://local` 以「本地演示连接」回显并保留原有可用性；不作为普通远程供应商地址，也不开放获取模型。

## 5. 模型获取、手动添加与测试

### 5.1 获取模型

1. 新供应商保存成功自动打开获取窗口并请求一次列表；已有供应商可主动点击「获取模型」。不把所有返回模型自动加入常用列表。
2. 「获取模型 · 〈供应商〉」弹窗包含搜索、可多选列表、已添加状态、手动 ID，底部「稍后添加 / 验证并添加（数量）」。
3. 已添加 ID 标记「已添加」，不可重复勾选；选择结果按供应商隔离。
4. 确认后按 §1 的三项验证逐个处理，文本通过才添加；既有名称、分组、流式、工具设置不被上游列表覆盖，不自动应用。
5. 上游列表为空、不支持模型列表或请求失败，都保留手动添加入口。错误文案例如「此服务未提供模型列表，可手动添加模型 ID」。
6. 再次获取不删除上游未返回的本地模型，也不推断它们失效；手动模型仍可测试和应用。

连接编辑页不展示模型列表及其操作入口；保存或取消返回后，才可获取模型、添加模型、应用或进入模型设置。

### 5.2 手动添加

- 「添加模型」进入与编辑共用的二级页，标题「添加模型」。
- 新建时模型 ID 必填；模型名称默认随 ID，用户可修改；分组可留空。
- 点击「验证并添加模型」进入同一验证流程；成功后加入列表，关闭结果后返回，不自动应用。失败保留草稿。
- 保存后模型 ID 仍可编辑和复制；手动修改 ID 只改 ID，所有已保存设置与当前未保存的设置都保留，包括名称、分组、容量、思考控制方式/档位/默认值/预算、流式与工具开关。保存时保留内部身份及主模型/导入绑定，从下一次请求起使用新 ID。同供应商重复 ID 阻止保存并保留草稿。更换 ID 后清除旧验证记录、视觉验证与缓存探测状态；这些检测记录不属于用户设置，页面提示可重新测试。
- 新建、编辑和发现窗口中的手动 ID 共用预设候选：聚焦展示当前供应商可用预设，按输入的 ID、别名或名称筛选；可点击或用上下键、回车选择，Esc 只关闭候选。明确选择时填入所选的完整 ID/别名及名称、容量、思考设置；没有匹配仍可输入自定义 ID。选择候选仅修改草稿，不直接保存或发起请求。

### 5.3 测试连接

- 每个已保存模型都可在「更多 → 测试连接」或二级设置页发起，不依赖是否获取过模型列表。
- 点击后展开小面板，保留现有可编辑测试提示词；默认「你好，请回复 pong。」。「开始测试」旁用一句话说明「发送一次短请求，可能产生少量用量」。
- 仅用测试提示词，不附会话、笔记、记忆或工具；测试不改变应用绑定。结果只证明这次基础请求可用。
- 状态为「未测试 → 测试中 → 通过/失败」；展示响应时间、简短回复或可理解的错误原因。支持取消，过期请求不得串到其他模型。
- 通过不自动开启工具或流式，不标记为支持视觉/推理；工具模式仍需后续真实对话验收。
- 测试结果仅保留在本次弹窗内；关闭后重新打开从「未测试」开始，不把旧配置的成功结果作为当前连接状态。
- 未保存的模型设置须先保存或取消才能测试，结果与使用的配置一致。

### 5.4 预设匹配与自动补全

预设提供起始资料，人工修改优先。不会把上游模型强制替换成预设中的另一个模型，也不锁死已识别模型的设置。

```text
获取模型 · 学习网关
[搜索模型 ID]

☑ study-reasoner    已匹配预设                        [查看]
  深度分析 · 上下文 128K · 可选思考强度
☐ custom-chat      未匹配预设，可手动配置
☒ study-chat       已添加

已匹配模型将在添加时填入预设资料，之后仍可修改。
                                     [取消]  [添加所选（1）]
```

以上名称、容量与档位仅为布局示例，不代表真实模型参数。

- 获取成功即展示匹配状态；「查看」展开将填入的字段和预设来源，但不提前保存。勾选后在「添加所选」时一并落地；重复获取不修改已经添加的模型。
- 优先匹配相同供应商端点、API 格式下的完整模型 ID；其次使用已核验的通用模型条目或显式别名。模糊名称、任意前缀/后缀裁剪不作为自动套用依据；有多个候选时保留未匹配状态，允许手动选择参考预设。
- 上游返回的模型 ID 始终保留，用原 ID 发请求。关联参考预设只改变模型资料，不改供应商地址、协议或模型身份。
- 名称、上下文容量、输出容量和经当前协议核验的思考控制资料可自动补全。预设没有独立输入容量时，最大输入 Token 保持留空；容量不能突破应用已有的任务预算。
- 「支持工具调用」是能力资料，「允许工具调用」是用户偏好。预设不越过现有端点默认策略、记忆授权或用户已关闭的设置；预设明确不支持时默认关闭，未提供能力资料时保持未知。流式偏好不从 `reasoning` 字段推导。
- 预设中的 `temperature` 布尔值表示能力，不作为温度数值写入；图片/视频等资料不自动开放应用尚未实现的输入入口。第三方 SDK 的原始 `variants/options` 不能直接透传为 HTTP 请求体。
- 手动输入模型 ID 仅筛选候选，不自动填写、清空或还原其他字段；无论新建/编辑、字段是否保存、是否在本次编辑中选择过预设，均遵循此规则。清空 ID、改成未知 ID、命中另一预设或改回原 ID 都不影响其余设置。只有点击或回车明确应用预设，才填写该预设负责的名称、容量和思考设置，分组、流式与工具开关保留；选定的参考资料随设置一起保存。异步资料返回、预设查询失败和保存动作都不能重算草稿，保存提交当前完整设置。发现列表首次添加仍可按所选模型初始化预设；已有模型读取、切换供应商、点击应用均不重套预设。
- 已保存模型显示「参考预设：〈名称〉」及「已自定义」状态。用户可在「调整能力资料」中选择其他参考预设，或点「恢复预设资料」先更新当前草稿；保存前仍可取消，且不重置名称、分组、用途绑定和用户偏好。
- 预设随应用携带经核验的本地快照，记录来源与版本；外部目录更新不覆盖已保存配置。这一轮不新增启动联网刷新、远程配置执行或后台同步。

使用右侧内容区整页替换，左侧供应商列表和顶部当前使用条保留。返回后恢复模型列表搜索、分组和滚动位置。不会在列表每一行展开长表单。

```text
基本信息

模型 ID               study-chat                   [复制]
模型名称              [通用对话                     ]
分组名称              [常用                         ]

开启后逐步显示回答。
允许工具调用                                      [开]

▸ 上下文与输出上限（可选）

```

### 6.1 基本信息

| 字段 | 规则 |
|---|---|
| 所属供应商 | 只读；调整连接返回一级页面 |
| 模型 ID | 新建与编辑均可输入且必填；提供可筛选、点击/回车选择的预设候选；不得与同供应商其他模型 ID 重复 |
| 模型名称 | 选填，最多 80 字；留空按模型 ID 显示；可与其他模型同名，次行 ID 负责区分 |
| 分组名称 | 可输入或选已有组，最多 40 字；留空为「未分组」；名称变更即移动该模型，不做另一个分组管理页面 |

所有文本仅去首尾空白；不自动更改模型 ID 的大小写或标点。

### 6.2 输出与工具

| 设置 | 含义 | 默认与继承 |
|---|---|---|
| 流式输出 | 对支持该模式的交互逐步显示回答；关闭则等待完整结果 | 新模型默认开；迁移模型保留原值 |
| 允许工具调用 | 允许主模型对话使用应用提供的工具；不等于开启全部记忆功能 | 新模型由本次实际验证初始化；已保存模型的人工设置优先 |

- 两项使用独立设置行：左侧标题和一句说明，右侧开关；不把开关、长说明、内部工具名挤成一行。
- 流式与工具互不禁用，四种组合都可保存。开启工具不代表一定调用工具，流式也不等于开启推理能力；工具阶段可能先等待再显示最终回答。
- 只保存该模型的偏好，不修改其他模型，也不触碰「记忆」页总开关、授权范围和工具实现。
- 已应用到导入兜底的模型仍有完整设置页；在工具说明下面提示「仅对主模型对话生效，导入解析不调用记忆工具」。同一个模型可同时服务两种用途，执行时按用途约束。
- 不出现 `search_memories`、工具循环预算等内部术语；不增加尚未支持的推理、视觉、音频等可点击能力标签。说明采用「允许模型使用应用已提供并获授权的工具」，不写死为检索；并行开发的新增工具何时可用、如何授权，由其自身契约决定。
- 端点实际不支持某项时沿用明确错误反馈，不能悄悄改偏好或自动切换到另一供应商。

### 6.3 上下文与输出上限

默认折叠，用三个数字字段承接参考图里的参数配置。本轮纳入实现，必须落实到实际请求与上下文预算。

| 字段 | 用户含义 | 默认 |
|---|---|---|
| 上下文窗口 | 此模型单次请求输入与输出的总容量上限 | 未指定，沿用应用现有策略 |
| 最大输入 Token | 允许用于输入的上限，含提示词、历史和检索内容 | 未指定，沿用应用现有策略 |
| 最大输出 Token | 单次回答输出的上限 | 未指定，沿用应用现有策略 |

- 三项为可清空的正整数；清空表示取消自定义，`0`、负数、小数不合法。手动填写准确整数；本轮不做密集的容量快捷按钮。
- 不凭模糊模型名字猜容量，不把截图里的数值当默认，也不将缺省值显示成 0。本次扩展确认后，按 §5.4 的可靠匹配结果补全预设容量。
- 已填写的输入/输出上限分别不得大于已填写的上下文窗口。输入与输出上限是各自天花板，不要求两者相加一定小于窗口；单次实际输入加输出预留必须落在总窗口内。
- 实际预算仍受应用各任务已有上限约束。页面显示一句「自定义上限不会突破应用的任务限制」。不能因填大数而扩张工具或导入任务预算。
- 输入容量用于既有上下文预算流程；当前输入即使按既有整理策略处理后仍放不下时，给出明确错误，不能截掉当前问题后假装正常回答。具体预算映射在确认后的 Spec 中决定。
- 参数校验错误就地显示，不允许仅保存无效字段或静默忽略。供应商拒绝某个值时保留原输入，提示调整。

### 6.4 保存与返回

- 「保存模型设置」只保存模型属性，按钮名称不含「应用」。非当前模型保存后仍不是主模型。
- 已应用模型保存成功后，对引用它的用途从下一次请求生效；页内显示受影响用途。已进行的请求继续使用原配置。
- 成功后返回列表并定位原模型；失败停在编辑页，保留所有输入，包括开关，不回滚成旧查询数据。
- 从脏表单返回、换供应商、切设置分区或离开页面，统一提示「有未保存的修改」；提供「继续编辑 / 放弃修改 / 保存并继续」。保存失败不执行原导航。
- 取消、关闭、Esc 的含义一致；没有修改时直接返回。保存中防止重复提交和目标漂移。
- 新模型默认值只在首次创建时使用；再次打开、重命名、分组、应用均不重算默认。

### 6.5 思考能力、默认强度与侧边栏边界

设置页管理「这个连接下的模型怎样控制思考、支持哪些档位、默认使用哪档」；未来侧边栏负责「本次会话使用哪档」。用户指定参考 CC Switch 的多选下拉：可用等级与默认等级放在同一弹层，预设负责初始勾选，用户可直接修正，不再把等级列表藏进高级配置。

```text

参考预设：深度分析

思考设置
思考等级         [low → max                             ▾]
来自预设 · 默认：自动（服务默认）
                 ┌───────────────────────────────────────┐
                 │ [搜索思考等级…                       ]│
                 │   none                                │
                 │   minimal                             │
                 │ ✓ low                                 │
                 │ ✓ medium                              │
                 │ ✓ high                                │
                 │ ✓ xhigh                               │
                 │ ✓ max                                 │
                 ├───────────────────────────────────────┤
                 │ 默认等级                              │
                 │ [自动（服务默认）                    ▾]│
                 └───────────────────────────────────────┘

▸ 高级兼容设置
  控制方式       [强度档位                              ▾]
                                            [恢复预设资料]

输出与工具
流式输出                                                [开]

```

上图使用虚构模型演示交互；候选词表不代表任何真实模型支持所有等级。字段规则：

| 项目 | 规则 |
|---|---|
| 思考控制方式 | 默认「强度档位（effort）」；也可选「未知」「无思考能力」「支持思考但不可调」「预算控制」。缺少档位不等于不支持思考；预设明确使用其他控制方式时按预设初始化 |
| 思考等级 | 一个可搜索的多选下拉；等级使用原始值 `none / minimal / low / medium / high / xhigh / max` 并按此顺序显示。排除 harness 自定义的 ultra。预设勾选适配项，允许人工调整当前协议适配器能发送的项；未适配的候选禁用并说明原因。若切换协议后旧值不再适配，仍允许取消旧选择；不接受任意参数 |
| 收起摘要 | 无选择显示「未设置」，一个等级显示原值；连续至少三个等级压缩为 `low → max`，有缺口时分段，例如 `low, high → max`，绝不能暗示选中了缺失的 medium。完整等级可通过聚焦/悬停查看 |
| 默认等级 | 在同一弹层底部显示单选，候选仅为「自动（服务默认）」和上方已勾选等级。初始自动；自动表示不主动发送思考控制参数，不代表 `none`、adaptive 或中等；收起后旁边显示当前默认值 |
| 清空/取消勾选 | 清空只表示没有声明可用等级，不等于无思考能力。移除当前默认等级时回到自动，并就地提示「已移除默认等级，改用服务默认」；仍处于未保存草稿，可用页面取消撤回 |
| 预算控制 | Anthropic 协议显示思考 Token 预算，留空沿用服务默认；当前 Chat Completions 适配器禁用此模式。不把第三方人为划分的低/中/高当成厂商原生 effort。预算至少 1024，且小于本次实际输出上限 |
| 不可调或未适配 | 明确说明「由模型决定」或「当前协议暂不支持调整」，不显示可操作但无效的强度下拉；未知模型默认不发送此参数 |
| 恢复预设资料 | 恢复能力与容量字段到当前参考预设，进入待保存草稿；保留合法的默认强度。若当前默认值已不在可用集合，明确显示已回到「服务默认」，不能静默换成另一档 |

- 手动覆盖只影响此供应商下的这一模型；另一供应商的同名模型不跟随变化。源资料与手动值不互相覆盖，后续刷新预设也不抹掉人工修正。
- 多选时弹层保持展开，搜索只过滤展示而不清除选择；无匹配显示空结果。默认等级区域不随等级列表滚走；短窗口内弹层自动翻转/限制高度，只让等级列表滚动，嵌套默认值菜单层级高于外层弹层。
- 点击外部仅关闭等级弹层，保留草稿及被点击控件的焦点；第一次 Esc 关闭弹层并恢复触发器焦点，之后 Esc 才触发整个编辑页的离开保护。键盘可搜索、逐项勾选并进入默认等级下拉；选择后仍需点页面「保存模型设置」。
- 默认强度用于普通主模型对话与其工具循环，从下一次请求生效。导入、提取、总结等任务保留各自现有预算及禁用思考约束，不因修改聊天默认值而扩张。
- 设置必须连同请求适配一起实现，不能只保存一个前端下拉值。测试连接使用已保存的思考控制配置；成功仅说明本次请求可用，不证明全部档位、工具循环或真实推理均已通过验证。
- 未来侧边栏优先级为「会话选择 → 模型默认 → 服务默认」；聊天界面提供「使用模型默认」及该模型实际可用的档位。该选择只影响当前会话后续请求，不改全局模型设置；切模型时不携带另一个模型的无效档位。具体布局留到侧边栏切片。
- 本次实现验收至少覆盖：精确命中自动补全、未知/歧义模型不误配、旧模型与人工修改不被覆盖、协议不支持的档位不可选、多选搜索不丢选择、非连续摘要不跨缺口、移除默认值回到自动、弹层关闭不误退出编辑、短窗口默认值可达、默认值实际进入请求、服务默认不发控制参数、工具循环沿用本轮配置、失败保留草稿。

设计依据（2026-11-07 核对，外部资料不是本项目的实现契约）：

- 用户提供的 [AI Toolbox 预设文件](https://github.com/coulsontl/ai-toolbox/blob/main/tauri/resources/preset_models.json)：可作为名称、容量、能力与 variants 的种子资料；上线前逐项核验当前支持协议的映射。
- CC Switch 的 [预设资料转换](https://github.com/farion1231/cc-switch/blob/main/src/config/presetModelMetadata.ts)、[模型资料解析](https://github.com/farion1231/cc-switch/blob/main/src/lib/modelMetadata.ts)：同地址预设优先，结合 models.dev 补缺失字段的做法值得借鉴；不照搬其为其他客户端设置的特殊窗口上限。
- CC Switch 的 [CodexFormFields.tsx](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/forms/CodexFormFields.tsx) 中 `ReasoningLevelsEditor`：搜索多选、连续区间摘要、面板底部默认等级及默认值失效回自动。参考交互，协议支持范围仍按本应用实际适配判断。
- [OpenAI 官方 GPT-5.2 模型文档](https://developers.openai.com/api/docs/models/gpt-5.2)列出的档位为 `none / low / medium / high / xhigh`，而所给 JSON 此条含 `minimal`，说明目录内容需要校验，不能以“命中预设”保证参数正确。
- Anthropic 官方 SDK 的 [OutputConfigParam.effort](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/output_config_param.py) 与 [ThinkingConfigParam](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/thinking_config_param.py) 为独立类型；实际支持范围须按具体模型与协议核验，不把 SDK 类型的全部枚举当成每个模型都支持。

## 7. 「应用」的完整语义

### 7.1 主操作与用途菜单

| 入口 | 操作 | 成功表现 |
|---|---|---|
| 行内「应用」 | 将此供应商的此模型设为主模型 | 顶部主模型更新；新行变「已应用」；原行恢复「应用」 |
| 「应用」旁独立下拉 | 选择「用于导入兜底」 | 顶部导入兜底显示该供应商/模型；该行增加「导入」标记 |
| 顶部导入兜底「恢复跟随」 | 取消独立选择，跟随主模型 | 显示「跟随主模型」，不删除模型配置 |

- 「应用」前显示短说明「应用将切换主模型」；菜单入口有明确可访问名称「其他应用用途」。当前主模型的主按钮禁用为「已应用」，菜单仍可设置导入用途。
- 同一个模型可同时是主模型和导入兜底；角色标记可以并列。恢复跟随后随主模型变化，不保留隐藏的旧导入绑定。
- 不要求测试先通过才能应用；字段完整即可尝试。最近测试失败只给非阻断提醒，不以一次网络故障永久锁死配置。
- 供应商缺地址、缺必要密钥、无模型 ID 或存在未保存修改时，禁止应用并给出可定位的原因。
- 所有用途操作（应用主模型、应用导入、恢复跟随）共享忙碌状态；提交期间禁用重复切换，避免响应乱序。只有保存成功后才更新用途标记和顶部信息。
- 成功提示：「已应用：学习网关 / 通用对话，从下一次请求生效。」失败保留旧绑定，候选模型和编辑内容仍在。

### 7.2 生效边界

- 主模型覆盖现有主模型用途：侧栏对话、总结、学习计划、建议评分，以及原本配置为跟随主模型的后台任务；独立记忆维护模型不被覆盖。
- 所有后续请求按最新应用项执行，包括已有会话中的下一轮；正在生成的一轮、运行中的导入或后台任务不被中途换模型。
- 切换时不清空历史会话、不新建会话、不改历史消息归属；本轮不设计侧栏新增提示或选择器。
- 上述“从下一次请求生效”也约束一轮内的多次工具请求；同一轮必须使用同一份连接和模型设置。
- 切换失败、连接失败都不自动回退到其他供应商；导入只有在用户选择「跟随主模型」时才跟随，不能把独立模型的失败解释为未配置。

## 8. 删除、迁移与边界状态

### 8.1 删除

- 删除模型位于行内更多菜单；删除供应商位于供应商详情更多菜单。确认中明确名称；供应商删除还列出将移除的模型数量和密钥。
- 仍被主模型或独立导入用途引用时禁止删除，告知「先应用其他模型」或「先恢复导入跟随」；不静默解绑或替用户挑替代项。
- 未被引用的对象可确认删除；失败保留列表与选择。删供应商只删除其连接和模型配置，不删除会话、记忆、笔记或历史用量。
- 测试弹窗关闭时取消测试并忽略迟到结果；后端在读取线程退出前保护配置。任何任务仍依赖旧配置时，删除给出「仍有任务使用此配置，完成后再删除」，不破坏正在运行的请求。

### 8.2 旧配置首次进入

- 原主模型转为可识别的供应商和模型，并保持主模型绑定、密钥与每项已保存偏好。
- 原独立导入配置保留为另一个清楚命名的条目并绑定导入用途；默认不自动合并，避免同端点不同密钥或不同模型偏好被覆盖。
- 原导入为空时显示「跟随主模型」；原来保存过但字段残缺的配置显示「待补全」，不能冒充未配置或自动应用。
- 迁移不得要求重新填写密钥，不展示明文；不得把原来关闭的工具改为开启。原来没有显式工具值时，沿用迁移前实际生效值。
- 首次转换失败需展示错误和重试入口，保留旧配置可恢复；迁移成功后再刷新仍只出现一份条目。
- 嵌入与检索、记忆维护专用连接不纳入本次转换；其现有用途保持。

### 8.3 状态反馈

| 状态 | 页面表现 |
|---|---|
| 初次加载 | 骨架与禁用操作，不把未加载当作空配置 |
| 加载失败 | 错误区和重试，禁止覆盖为默认空表单 |
| 零供应商 | 「添加你的第一个供应商」；顶栏显示未设置 |
| 零模型 | 「添加模型，或从供应商获取」 |
| 搜索无匹配 | 保留搜索框，提供清空搜索 |
| 401/403 | 「认证失败，请检查此供应商的密钥或权限」及编辑连接入口 |
| 模型不存在/不可访问 | 「模型 ID 不可用，请检查 ID 或账号权限」及模型设置入口 |
| 超时/离线/限流 | 明确可重试，不删除模型、不改应用绑定 |
| 保存/应用冲突 | 保留本地输入；提示配置已变更，允许重载后核对，不自动覆盖他人修改 |
| 编辑离开 | 同一套保存/放弃/继续编辑提示 |

## 9. 视觉、响应式与无障碍

- 遵循 [DESIGN.md](../../../DESIGN.md) 与 `frontend/src/styles/app.css`：现有蓝色用于操作、焦点和选择；浅色/深色均复用令牌。
- 采用淡色左栏、细分隔线、平铺模型行；不为每个模型套大卡片，不照搬截图里的彩色能力按钮。
- 模型行至少 56px，操作控件对齐；表单采用标题/说明在左、开关在右的独立行。分区之间用留白和细线，减少嵌套边框。
- AI 连接内容宽度 < 760px 时，供应商栏改为上方选择区，详情单列；顶部用途条、模型行操作允许换行。二级页不缩成狭窄侧抽屉。
- 主详情跟随现有页面滚动；供应商列表可使用有名称的滚动区，模型正文不再嵌套一层固定高度滚动。短窗口下保存按钮仍可滚动到达。
- 测试 980px、760px、480px 内容宽度和 200% 缩放；长供应商名称、长 ID、两种用途标记同时出现时不能盖住操作。
- 控件有中文可访问名称，开关标签/说明正确关联；禁用原因可由文本读到。所有行操作支持键盘，不依赖悬停。
- 进入二级页将焦点置于标题/首个字段；返回把焦点还给原模型设置入口。弹窗限定焦点范围，关闭恢复触发点；提示用合适的 status/alert，不让进度反复打断读屏。
- 后续实现继续使用 Arco 控件和现有组件约定；不要用原生 `label` 包裹 Arco Select 导致 portal 点击失效。
