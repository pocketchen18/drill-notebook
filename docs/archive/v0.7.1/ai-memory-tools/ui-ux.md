# v0.7.1 AI 记忆工具：对话工具活动 UI/UX

> 已于 2026-11-08 归档。工具活动与全局 AI 对话设置已实现；本文保留已确认设计，当前交互见 [DESIGN.md](../../../../DESIGN.md)，历史验证见同目录 Plan。

## 全局 AI 对话设置（当前切片）

设置页增加独立的「AI 对话」分区，当前分组为「运行限制」，不放进供应商或模型编辑器。说明仅一句：对所有聊天模型生效，保存后从下一轮开始使用。

```text
设置  常规 | AI 连接 | [AI 对话] | 记忆 | 嵌入与检索 …
┌ 运行限制 ──────────────────────── [恢复默认] ┐
│ 对所有聊天模型生效，保存后从下一轮开始使用。   │
│ 工具阶段上限                [50     ] 轮      │
│ 工具执行上限                [100    ] 次      │
│ 整轮最长时间                [30     ] 分钟    │
│ 单次模型请求最长时间        [15     ] 分钟    │
│ 整轮输出 Token 上限         [128000 ]         │
│ 单次请求输出上限            [16384  ]         │
│ 最终回答预留                [8192   ]         │
│ 相同调用无新结果时停止      [3      ] 次      │
│                          [取消修改] [保存]   │
└─────────────────────────────────────────────┘
```

- 所有输入支持键盘，字段下各用一句话说明；工具阶段指模型发出一批调用，执行数按单个工具累计。
- 恢复默认只回填当前草稿，点击保存后生效；取消恢复已保存值。保存中禁用编辑，失败保留草稿。
- 单次请求时间不得大于整轮时间，最终回答预留须小于整轮 Token 上限；不合法时显示字段提示并禁止保存。
- 模型自身容量仍可收紧单次输出；不将这些全局设置写回模型参数。
- 次数或 Token 达限时，额外保留一次不带工具的最终回答。时间到期或上游断连时如实结束，保留已确认活动，不假装完成；提示区显示具体限制原因。
- 达限回复提供「继续」按钮，发送可见的后续用户消息，沿用同一会话的已有回答和新一轮预算；不自动重发上一轮写操作。它不是恢复已丢失的上游连接。
- 工具活动不再截断于 16 项；活动列表长时可以滚动，结束后的折叠与自由阅读行为不变。

需求基线：[requirements.md](requirements.md)。交互草图：同目录 `tool-activity-preview.html`；其中所有对话、时间、数量均为虚构示例，状态切换控件仅供审阅。

## 1. 本轮范围

用户应能在当前回复中看清：**正在调用什么工具、何时开始、结果如何、是否实际改变了记忆**。

- 覆盖现有四种记忆工具：检索、读取、新增、更新。后续工具可复用相同的记录结构。
- 沿用 AI 侧边栏、消息气泡、输入框与「中断生成」入口；只为助手回复增加工具活动区。
- 设置中的工具开关、供应商、模型和思考档位由 [AI 连接 UI/UX](../ai-connection-settings/ui-ux.md) 负责，本文不重复定义。
- 本轮不设计侧边栏整体改版、工具授权管理、原始调试日志、逐工具重试或回滚按钮，也不添加尚未存在的文件 / 终端工具。
- 按已确认界面补齐同目录 Spec / Plan 并实现；发布准备时已同步全局状态文档并完成归档。

## 2. 推荐布局：回复内的可折叠活动列表

工具记录属于对应的助手回复，不作为独立聊天消息。放在回答正文上方；若本轮存在当前界面已支持的模型思考内容，顺序为「思考内容 → 工具活动 → 回答正文 → 现有引用与操作」。工具记录不代替或编造模型思考过程。

每条回复最多一个活动组，组内按实际调用顺序排列。重复调用保留独立行。没有实际调用时，整个活动组不出现，也不显示空的「工具调用 0 次」。

### 执行时

```text
┌ AI 助手 · 当前会话 ──────────────────┐
│                        用户的问题… │
│                                    │
│ ┌ 助手回复 ──────────────────────┐ │
│ │ ⠿ 正在新增记忆              ⌄ │ │
│ │   已完成 1 项 · 2 次工具调用   │ │
│ │                               │ │
│ │ ├ ✓ 检索记忆          0.6 s  › │ │
│ │ │   完成 · 已返回 2 条         │ │
│ │ └ ⠿ 新增记忆          0.2 s  › │ │
│ │     执行中                    │ │
│ └───────────────────────────────┘ │
│ [输入消息…]             [中断生成]│
└────────────────────────────────────┘
```

### 完成后

```text
┌ 助手回复 ──────────────────────────┐
│ ✓ 已检索记忆 · 已新增 1 条        › │
│   2 次工具调用 · 0.9 s              │
│                                    │
│ 记住了，以后我会先给结论，再展开步骤。│
│                                    │
│ 插入笔记                 本轮上下文 │
└────────────────────────────────────┘
```

- 活动组使用次要文字、16 px 图标和细连接线；不为每次调用叠加一张大卡片。
- 中文工具名优先；执行中使用加载图标，成功使用勾选，未产生变更使用中性图标，异常使用警示图标，同时必须有文字状态。
- 组标题概括当前动作或已确认的结果；下一行是调用次数与工具执行耗时。耗时不包含模型生成时间，不显示伪百分比或预计完成时间。
- 完成态默认收起成两行，仍直接透露「检索 / 新增 / 更新」等关键动作。多个写入结果应分别概括，不能只用「完成」掩盖失败或未变更。
- 部分失败时标题为「部分工具未完成」；全部不可用时为「工具暂不可用」，禁止统一绿色勾选。

## 3. 单次调用与详情

点击工具行在原位展开详情；再次点击收起，不打开新窗口。行内保留工具名、结果短句、耗时和展开箭头。详情使用简单键值列表，不显示 JSON 面板。

```text
✓ 检索记忆                           0.6 s  ⌄
  完成 · 已返回 2 条
  开始时间   14:32:08
  执行耗时   0.6 秒
  查询范围   当前有权访问的记忆
  执行结果   返回 2 条相关记忆
  工具名称   search_memories
```

- 当天显示 `HH:mm:ss`；跨日 / 历史记录显示本地日期与时间。没有可靠时间时显示「时间未记录」，不使用打开页面的时间冒充开始时间。
- 进行中耗时可由真实开始时间更新；结束后使用确认的执行耗时。页面重开不重新开始计时。
- 仅展示安全摘要：操作范围、实际返回数量、写入数量、可理解的失败原因。分页 / 截断时写「本次返回 N 条」，不能当作记忆库总量。
- 技术工具名仅在详情中作为可核对信息；不显示内部 ID、版本号、谓词、族键、原始参数 / 返回体、完整记忆正文、鉴权信息或堆栈。
- 「返回了 2 条记忆」只说明检索结果，不能宣称模型一定使用了全部结果。现有记忆使用提示与「本轮上下文」保留各自语义。

## 4. 工具名与结果文案

| 实际工具 | 行标题 | 常见完成结果 |
|---|---|---|
| `search_memories` | 检索记忆 | 已返回 N 条 / 未找到相关记忆 |
| `list_memories` | 读取记忆 | 本次返回 N 条 / 当前范围没有记忆 |
| `create_memory` | 新增记忆 | 已新增 1 条 / 已存在，未重复添加 |
| `update_memory` | 更新记忆 | 已更新 1 条 / 内容相同，无需更新 |

下表描述界面语义，不新增或改写 API 契约；后台状态与展示状态的映射在 UI 确认后写入 Spec。

| 真实结果 | 行内文案示例 | 视觉与组摘要 |
|---|---|---|
| 正在执行 | 执行中 | 加载图标；指出当前工具，不只写「思考中」 |
| 成功且有返回 / 变更 | 已返回 2 条 / 已新增 1 条 / 已更新 1 条 | 勾选；写入数量只统计已确认的实际变更 |
| 无匹配 / 空列表 | 未找到相关记忆 / 当前范围没有记忆 | 中性完成；不等同于工具失败 |
| 重复 / 内容未变 | 已存在，未重复添加 / 内容相同，无需更新 | 中性完成；不计作新增或更新 |
| 不可用 / 超时 / 索引准备中 | 读取超时 / 记忆暂不可用 / 记忆索引准备中 | 警示；说明没有取得结果，不写成「没有记忆」 |
| 无权限 / 写入被拒绝 | 无权执行此操作 / 本次内容未写入 | 警示；仅在后台确认未写入时使用该文案 |
| 目标不存在 / 匹配不唯一 / 数据已变化 | 未找到待更新的记忆 / 需明确要更新的记忆 / 记忆已变化，未更新 | 警示；不把冲突伪装成成功或自动覆盖 |
| 内容不符合保存条件 / 参数无效 / 超过调用限制 | 未保存此内容 / 工具请求无效 / 已达本轮调用上限 | 中性跳过或警示；详情给出经过筛选的原因 |
| 用户中断且已确认取消 | 已取消 | 中性停止；保留先前已完成行 |
| 中断 / 断连后无最终确认 | 执行结果未确认 | 警示；停止加载动画，不推断成功、失败或回滚 |

## 5. 状态流与折叠规则

1. **等待模型**：沿用当前等待反馈；收到工具执行事件后才出现该工具行，不根据回答文字、固定延迟或假定步骤制造进度。
2. **工具执行中**：第一次出现活动组时自动展开；每次新调用追加到组尾，在原行更新结果。重复事件不能产生重复行，也不能把已结束的调用退回执行中。
3. **继续生成回答**：已结束工具保留最终结果，整体反馈转为「正在生成回答」。不让最后一个工具继续转圈以代替模型生成状态。
4. **本轮结束**：所有工具均正常结束或无变更时，未被手动操作过的组自动收起；存在异常 / 未确认结果时保持展开，并在收起标题保留异常提示。回答失败不应抹掉已经成功的工具记录。
5. **尊重手动选择**：用户一旦主动展开或收起，本轮后续状态更新不能覆盖该选择；正在查看详情时也不能自动折叠。异常发生在手动收起的组内时，仅更新标题提示。
6. **取消**：沿用输入框的「中断生成」。已确认写入成功的记忆保留，界面明确说明；仍无结果的操作标记「结果未确认」，必要时提示到记忆库核对，不能一概宣称没有写入。没有逐工具重试，避免误触重复写入。
7. **断连 / 重开**：重新读取本轮已记录的结果；最终状态未确认时显示未确认，不能继续无限加载。切换模型或打开历史不触发工具重放。

一个组内没有正在执行的工具、但模型尚未结束时，组标题显示已有结果，另以一行轻量状态显示「正在生成回答」；不在组内预告模型尚未发起的下一次调用。

## 6. 滚动、窄屏与可访问性

- 沿用现有自由滚动规则：仅用户原本停留在底部时跟随新增内容；用户上滚后，工具新增、计时、结束或正文追加均不能强制拉回底部。
- 展开 / 收起时保持触发按钮在当前视口的位置；自动收起也不造成阅读位置突然跳动。不自动把焦点移到新工具行。
- 沿用当前主题字体、颜色、消息圆角和间距。运行态使用主题强调色，异常使用提示色，普通完成保持低视觉权重；兼容明暗主题。
- 320 px 窄视口下工具名称与结果可换行，耗时让位到次行，不出现横向滚动；活动列表超过 480 px 后可在组内滚动，避免长工具链占满聊天区域。
- 组和工具行使用可键盘操作的按钮，包含 `aria-expanded` / `aria-controls`；状态文字使用低打扰播报，仅播报状态改变，不每秒播报计时。减少动态效果偏好下停用旋转动画，保留「执行中」文字。

## 7. 历史与实现边界

- 新产生的对话需要保留最少的工具活动元数据，使重开后仍可知道做过什么；历史默认收起，异常摘要始终可见。详情只包含第 3 节允许的信息，不存储原始工具参数与结果正文。
- 旧消息未记录工具活动时不补造记录、不重新执行。需要解释时仅在现有上下文查看入口注明「该消息未保存工具记录」。
- 开关关闭、模型未调用工具、模型不支持工具，均不能因为“已启用记忆”就出现一次虚构检索。自动注入上下文与模型显式工具调用分开表达。
- 关闭正文流式输出也不应关闭工具状态反馈；工具开始与结束仍应及时出现，正文可一次性呈现。具体传输方式留给后续 Spec 决定。
- 工具状态由服务端真实执行事件提供，已确认结果保存在本轮加密元数据中；正文仍使用既有输出逻辑。计时器仅更新真实开始后的耗时，不制造调用或结果。

## 8. 草图覆盖与验收表现

交互草图提供「工具执行中、生成回答、已完成、读取并更新、无匹配结果、工具不可用、已中断、历史记录、未调用工具」九种示例，可展开组和单次调用详情。它用于确认视觉与交互，不连接真实模型或记忆库。

| 场景 | 应观察到的表现 |
|---|---|
| 检索后新增 | 先后两条真实调用；开始时间与各自结果可查；完成摘要含已新增数量 |
| 同一工具被多次调用 | 各次顺序与结果独立保留，不合并成一条模糊状态 |
| 无匹配与不可用 | 前者正常完成，后者警示；都不能编造检索到的内容 |
| 重复新增 / 更新无变化 | 明确未产生变更，不显示新增 / 更新成功数量 |
| 一项成功、一项失败 | 保留成功结果；组标题明确部分未完成 |
| 工具结束后模型继续回答 | 工具行不再加载；「正在生成回答」独立呈现 |
| 用户正在展开查看 | 后续完成事件不折叠该组、不收起详情、不移动焦点 |
| 用户上滚或展开详情 | 不中断阅读，不强制滚到底部 |
| 已写入后中断、断连或回答失败 | 已确认写入保留；不确定操作单独标记未确认 |
| 重开会话 / 非流式回答 / 无工具回答 | 历史可查且不重放；状态不依赖正文流式开关；无调用则无活动组 |
| 隐私与可读性 | 不展示原始 JSON 和敏感内容；中文状态可读；窄屏、暗色、键盘可用 |

## 9. 本次审阅重点

建议采用本方案：**每条回复一个轻量活动组，执行时展开、正常结束后收起；工具名和结果常驻，时间与技术名按需展开。**

用户已确认活动组的位置、信息密度与折叠行为。实际完成情况以同目录 Plan 的验证结果为准；后续若有调整，直接覆盖本文与同目录草图。
