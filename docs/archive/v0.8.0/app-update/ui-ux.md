# v0.8.0 软件内更新与关于：UI/UX

> 已于 2026-11-12 随 v0.8.0 归档，仅作历史参考；下文的「当前」与待验项均保留施工时口径，归档不新增验证结论。版本收尾与后续调整见 [归档说明](../README.md)。

> 状态：已实现，工程验证通过（2026-11-12），尚未发布。需求见 [requirements.md](requirements.md)，协议与验证见[规格](spec.md)和[计划](plan.md)，版本状态见[当前 F09](../features.md)。`app-update-preview.html` 保留为确认设计的示例，实际功能来自 React 与 Electron；本轮尚未做真实界面人工观感、缩放和读屏验收。

## 1. 页面与入口

沿用现有主窗口侧栏、顶栏与设置横向 pill 标签，在末尾加「关于」。不额外增加第二列设置导航。颜色、字体、间距、按钮与表单继承[全局设计规范](../../../DESIGN.md)及现有设置面板；支持明暗主题和窄窗口。

顶部更新入口位于主窗口右上角，与 AI 助手入口相邻：使用 32px 图标按钮和 Lucide `circle-arrow-up`，有新版时采用柔和的成功色，悬停 / 聚焦说明「发现新版本 v…，查看更新内容」。常驻表示有可用新版，不闪烁、不循环动画。

顶部入口与关于页反映同一全局更新状态。已跳过版本隐藏入口；更高的新版本可重新显示。窗口重开恢复实际状态，不能因弹窗关闭或换页丢失入口。更新进行中点击顶部入口重新打开同一进度窗口。

## 2. 关于页

### 2.1 单行入口布局

从上到下使用三个现有样式的面板：

1. **Drill Notebook**：品牌、当前版本与「预发行」标记；右侧独立「检查更新」按钮。下方只显示上次成功检查 / 当前检查状态，删除状态行右侧重复的「更新内容」文字按钮；底部并排放置带 Lucide `github` 图标的「GitHub 主页」与唯一的「更新内容」按钮。
2. **更新设置**：独立自动更新开关、自动检查开关、一个共享的检查与提醒间隔、启动时更新提醒开关；必要时追加跳过记录和「恢复提醒」。
3. **支持项目**：一行 Star 提示与「去 GitHub 点 Star」按钮。只打开仓库，不读取用户登录状态，不自动执行 Star。

当前版本来自实际运行包。草图中的 `v0.8.0 → v0.8.1` 和文案只用于展示布局，标记为「设计示例」。发布脚本注入实际版本；本轮只扩展便携打包的更新组件与校验材料，没有调整实际版本号或发布 Release。

### 2.2 更新内容入口

关于页「更新内容」移到 GitHub 主页旁，使用相同大小的按钮，可带 Lucide `file-text` 图标。正文放在按需打开的弹窗，不再放独立设置行。关闭自动检查时该入口仍可用。

该入口采用用户参考的 `yetone/magpie` 的范围菜单与只读交互：默认范围可附上待安装说明，历史 N 范围只阅读已安装版及更早版本；检查更新的新版弹窗仍只显示尚未安装的版本。正文逐版展示，各版保留自己的完整 Release 内容。

### 2.3 设置文案

| 标签 | 辅助文字 | 控件 |
|---|---|---|
| 自动更新 | 每次启动立即检查，有新版本时自动下载并重启。 | 独立开关，默认关闭 |
| 自动检查更新 | 按设定间隔检查新版本，在顶部显示更新入口。 | 开关，默认开启 |
| 检查与提醒间隔 | 自动检查与启动弹窗共用此间隔；频繁重启不会重复提醒。 | 下拉选择 1 / 6 / 12 / 24 / 48 小时、自定义；默认 24 小时 |
| 启动时更新提醒 | 有新版且距上次提醒已满设定间隔时，启动后显示更新说明。 | 开关，默认开启 |
| 已跳过 v… | 此版本不再自动提示；仍可手动查看或更新。 | 「恢复提醒」文字按钮 |

自定义输入单位为小时，范围 1–168 整数；输入错误就地说明，保留上次有效值。关闭自动检查时，间隔与启动提醒置灰但不清空偏好；独立的启动自动更新、手动检查与已知未跳过版本的顶部图标继续可用。

开启自动更新时，启动说明提醒置灰并显示「自动更新已开启，启动时直接显示更新进度。」；保留原偏好，关闭自动更新后恢复。检查间隔仍只控制周期检查与说明提醒。开关即时保存，正在使用时开启不立即下载或重启；手动检查始终先展示说明，由「立即更新」发起完整事务。

## 3. 检查与提醒

### 3.1 关于页状态

| 状态 | 内容与操作 |
|---|---|
| 尚未检查 | 「尚未检查更新」，可点击「检查更新」 |
| 正在检查 | 按钮显示「检查中…」并防重复；旧的可用更新入口不因检查开始而闪退 |
| 已是最新 | 「当前已是最新版本」，显示本次成功检查时间，隐藏顶部更新入口 |
| 发现新版 | 只显示「发现 v…」，顶部入口常驻；手动检查发现后打开说明弹窗 |
| 已跳过 | 「发现 v…，已跳过此版本」；关于页可打开更新内容 / 恢复提醒，顶部图标隐藏 |
| 检查失败 | 显示真实原因与「重试」；保留上次成功检查时间，不显示虚假的最新结论 |
| 正在更新 | 独立进度弹窗显示下载百分比、校验或准备重启等真实阶段；顶部入口可重新打开同一进度，检查结果仍保留 |

「检查更新」始终表示重新检查。手动检查发现新版或点击顶部图标时，打开尚未安装版本的说明；更新已经进行时，顶部图标打开进度窗口。GitHub 主页旁的「更新内容」打开带 Magpie 范围菜单的只读说明。「立即更新」发起下载、校验、保存、程序替换与自动重启，成功路径无需第二次确认。

### 3.2 自动提示

自动更新关闭时，启动恢复配置与更新状态，后端与主窗口就绪后按间隔异步检查。仅在需求中的所有条件满足时自动打开 Release 弹窗，本次启动最多提示一次；运行中到期检查只显示顶部入口。

检查与自动弹窗使用**同一个间隔值**，分别记录成功检查时间和实际提醒时间。手动检查忽略间隔，展示新版说明也推进提醒时间；关闭与重启不清空记录。当前启动最多一次自动提示，后台到期检查不弹。

例如自动更新关闭、默认 24 小时：第一次弹窗后点击 ×，5 分钟或 23 小时内重启仍只见顶部图标；满 24 小时后启动且新版仍可用、未跳过，才允许再次提醒。达到间隔不等于运行中立即弹出。

### 3.3 启动自动更新

自动更新开启后，每次启动读取便携配置并立即检查，忽略共享间隔、说明提醒冷却和自动检查开关。有未跳过新版时，不先展示更新说明确认，直接打开 §4.3 的进度窗口，连续完成更新并重新打开软件。启动检查与业务恢复协调，优先完成更新，避免刚恢复编辑或 AI 任务就重启。

没有新版或新版已跳过时正常进入软件。检查、下载或校验失败时显示真实原因并允许继续使用当前程序；替换或新版本启动失败进入恢复流程，失败目标不反复自动重试重启。手动检查仍可查看并更新已跳过的版本。

## 4. 更新内容弹窗

### 4.1 两种入口与逐版正文

- **GitHub 主页旁的「更新内容」**：采用 Magpie 的范围菜单。右上方为 pill 范围按钮和 ×；按钮展开标题「显示的更新说明」及五个选项，选中项带勾。默认「上次更新以来」可附上已知待安装版本；选择「当前版本及之前 10 / 20 / 50 / 100 个版本」时，只显示实际安装版及之前最多 N 版，绝不混入新版。标题取当前列表中最新的版本，历史 N 范围因此始终显示安装版；底部只有「关闭」，没有跳过、下载或重启按钮。
- **检查发现新版、顶部图标与启动提醒**：标题版本为本次检查到的目标新版，只展示安装版之后、直到目标新版的 Release，每版标注「尚未安装」；不显示当前安装版、旧版正文或历史范围下拉。底部操作始终作用于本次目标新版。
- 默认范围以「上次成功运行版本」判断本次是否刚升级：刚升级时展示其后到当前安装版的说明；普通同版启动或缺少记录时，已安装部分只剩当前版。已知待安装版本放在这些说明前。历史 N 范围固定以安装版为上限，共最多 N+1 版；检查和跳过不能改变这个上限。关于页入口重开后恢复默认范围。
- 每个版本独立展示版本号、日期、完整 Markdown 正文与原文链接，各版间使用轻分隔线。历史里的安装版标注「当前安装」；新版里的各版标注「尚未安装」，已跳过的目标另标「已跳过」。不融合或重写多版正文。
- 标题、范围（关于页入口）与底部操作固定，正文独立滚动。长标题与链接换行；窄窗口将范围按钮放到下一行，菜单宽度适配弹窗，× 始终可见。范围按钮及选项均可用键盘操作，Esc 先收起菜单，再关闭弹窗。无说明时在对应版本下显示真实空状态。
- 说明加载失败保留所选范围内已有正文，顶部显示错误，重试继续请求同一选中范围；不得为保留旧正文而混入范围外版本。更新检查失败不改变历史 N 范围的安装版上限；手动查看缓存的新版说明时明确检查失败。正在阅读或下载的更新目标不被后台检查替换。

### 4.2 未下载

- 标题「v… 更新内容」，状态为「发现新版本」，右上角 ×，可按 Esc 关闭。
- 元信息显示「当前 v… → 新版 v…」、发布日期及必要的「预发行」标记。
- 正文只逐版渲染安装版之后、到目标新版之间的 GitHub Release，每版提供自己的「在 GitHub 查看」，不提供历史范围下拉。窄窗口允许按钮换行，不压缩正文到不可读。
- 底部仅「跳过此版本」与主按钮「立即更新」。关闭沿用右上角 ×，避免把关闭弹窗与取消下载混为同一个动作。

| 操作 | 结果 |
|---|---|
| 右上角 × / Esc | 关闭当前弹窗；不改变跳过记录、自动检查偏好或现有顶部图标 |
| 跳过此版本 | 保存目标版本、关闭弹窗、隐藏该版本顶部图标；该版本不再自动弹出或在启动时自动下载 |
| 立即更新 | 关闭说明界面，打开独立进度窗口；成功下载与校验后自动保存、退出、替换并重启，无需再次确认 |
| 在 GitHub 查看 | 打开对应 Release 原文，当前弹窗状态保留 |

手动查看已跳过版本时显示「此版本已跳过自动提醒」，仍可立即更新；查看本身不恢复提醒。关于页的「恢复提醒」清除该版本跳过记录，恢复顶部入口，但不主动再弹窗、不重置已有提醒时间。

点击遮罩不关闭，以免误点丢失阅读位置。对话框有可访问名称，打开时焦点进入弹窗、Esc 关闭后回到触发入口；焦点在弹窗中循环。长 Release 支持键盘阅读与链接访问，未提供说明时显示真实空状态。

### 4.3 独立更新进度

点击「立即更新」或启动自动更新发现新版后，打开同一个独立进度窗口，标题「正在更新 Drill Notebook」，显示当前版 → 目标版与「完成后将自动重启」。正文聚焦更新阶段、进度条、百分比、已下载 / 总大小及速度，不继续堆叠 Release 正文。

阶段连续推进：下载更新包 → 校验更新包 → 保存当前工作并准备重启 → 退出后替换程序并重新启动。无法取得总大小时只显示真实已下载量，不造百分比；校验、保存与替换阶段显示阶段状态，不将下载百分比当成整个安装百分比。完成后直接打开新版本，不增加成功确认或「重启并更新」按钮。

右上角 × / Esc 只隐藏进度窗口，已发起的更新与后续自动重启继续；窗口内清楚说明这个行为。顶部入口可重新打开同一进度，多个窗口观察同一事务，不重复下载。下载阶段底部单独提供「取消下载」，停止整个更新事务并回到新版说明，阻止自动重启；校验及后续阶段不再展示此按钮。

断网、空间不足、校验失败或便携包不可用时显示具体错误，提供「重试更新」及 GitHub 原文入口。失败不退出或替换当前程序，仍可继续使用。重试是用户明确重新发起事务；下载完成后的正常路径没有额外点击。

### 4.4 保存、重启与恢复

点击「立即更新」或已开启的启动自动更新足以授权成功后的自动重启。校验成功后复用现有自动保存与退出保护，处理未保存编辑、AI 活动和待发内容；常规成功路径不增加重启确认。保存失败或已有退出保护需要处理时暂停更新并说明原因，不能丢弃草稿或强杀任务。启动自动更新尽量在恢复业务任务前完成，减少这类暂停。

正常退出主窗口、助手与后端后，由便携辅助程序完成替换并重新启动。只有新版本实际成功启动才记为升级成功，顶部新版提示随之消失。

程序替换或启动失败时保留错误与恢复材料。只有旧 Electron 和 JVM 已退出、停机数据库与程序备份完整时才执行替换；新版就绪前业务页面保持启动等待。新版启动失败会先保留失败数据库副本，再恢复旧程序与停机数据库并自动重开旧版，关于页显示真实失败原因，目标版不再启动自动重试。新版本健康确认后不得回滚用户继续编辑的数据；遇到仍在运行的进程或损坏备份时保留现状并提示人工处理。具体边界见[规格](spec.md)。

### 4.5 关于页只读内容

GitHub 主页旁的「更新内容」与 Magpie 一样，可在默认范围阅读本次升级说明和已知待安装说明；10 / 20 / 50 / 100 范围始终只阅读实际安装版及更早版本。每版独立显示正文与原文链接，底部只有「关闭」。只读查看不推进新版提醒时间，跳过记录也不受影响；待安装内容上的标记只说明状态，不能在这里触发下载。

## 5. 视觉与草图交互

- 继承现有 `panel`、`settings-row`、主题令牌、Segoe UI / Microsoft YaHei 字体与 4px 间距体系；设置标签与按钮使用现有圆角和大小。
- 顶部图标只用柔和成功色表达可更新，主要更新动作沿用本项目蓝色；关闭 / 跳过为低强调操作，避免混用不同软件的按钮风格。
- 草图只保留当前选定的单一布局；可以点击 GitHub 主页旁唯一的「更新内容」阅读默认范围，打开带勾的范围菜单阅读安装版与历史；点击检查或顶部按钮阅读未安装版本，再关闭、跳过、恢复提醒。点击一次「立即更新」后独立进度连续推进，并自动完成模拟重启。
- 宿主设计选项可切换检查结果（有新版 / 已是最新 / 检查失败）、更新结果和使用场景（正常使用 / 软件启动），用于观察启动自动更新与进度布局；它们不出现在真实产品流程中。正常使用时开启自动更新只保存偏好，切换到软件启动才模拟启动检查。
- 草图不访问真实 Release、不下载更新、不保存项目设置、不重启应用；所有示例数据明确标注。已落地组件覆盖 9 项交互测试，实际更新与恢复另经原生和完整应用测试验证；工程测试结果不能以草图交互代替。用户已验收的旧 AI 按钮无需再次人工核对。
