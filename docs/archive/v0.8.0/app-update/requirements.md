## 1. 目标

用户在软件内查看当前版本与 GitHub Release 说明，手动检查并发起下载后自动重启的完整更新，也可开启每次启动自动检查、下载和重启的「自动更新」。按间隔的自动检查和提醒减少漏看更新；共享的时间间隔与持久化提醒时间避免短时间重启反复弹窗。

继续使用 Windows 绿色便携包。更新只替换程序，不改变软件根目录和用户的笔记、题库、附件、模型与设置，不要求安装器或管理员权限。

## 2. 功能范围

| 编号 | 需求 | 验收表现 |
|---|---|---|
| U01 | 「设置 → 关于」 | 在现有横向设置标签末尾增加「关于」，显示运行中的实际版本、带 GitHub 图标的仓库主页、手动检查更新及 Star 提示；「更新内容」只保留 GitHub 主页旁的入口，检查状态行不再放重复按钮 |
| U02 | 自动检查更新 | 提供开关；间隔可设置，默认 24 小时；在应用运行期间到期检查，下次启动已到期时补查；无重复检查任务 |
| U03 | 手动检查 | 独立的「检查更新」按钮始终可用，忽略自动检查间隔与跳过记录；同一时间的重复检查合并 |
| U04 | 顶部更新入口 | 发现未跳过的新版后显示小型图标并常驻，悬停 / 聚焦提示版本；关闭更新弹窗保留图标；已是最新版或跳过该版本时隐藏 |
| U05 | 启动时更新提醒 | 关于页可启停；自动更新关闭时，只在启动、存在未安装且未跳过的新版、距上次提醒达到共享间隔时弹出；运行中后台发现新版只显示顶部图标 |
| U06 | 新版 Release 说明 | 顶部入口、手动检查发现新版和自动提示共用新版「更新内容」弹窗，只展示高于当前安装版、直到目标新版之间尚未安装的版本；各版独立显示 GitHub Release Markdown 正文、状态、日期及原文入口 |
| U07 | 关闭 / 跳过 / 更新 | 右上角 × 或 Esc 仅关闭当前弹窗；底部提供「跳过此版本」和「立即更新」。跳过持久化并隐藏该版本顶部图标，新的更高版本重新按规则提示 |
| U08 | 一次操作完成便携更新 | 点击「立即更新」后打开独立进度弹窗，下载匹配的便携 ZIP；成功校验、保存当前工作并通过退出保护后自动退出、替换程序及重启。无需再次点击「重启并更新」 |
| U09 | GitHub Star | 展示「如果 Drill Notebook 对你有帮助，欢迎在 GitHub 点个 Star。」及「去 GitHub 点 Star」按钮，点击打开仓库页面 |

| U11 | 启动自动更新 | 提供独立「自动更新」开关，默认关闭；开启后每次启动立即检查，不受检查与提醒间隔限制，发现未跳过的新版本后直接显示进度并完成下载、校验、程序替换与自动重启 |

仓库主页为 <https://github.com/qilin-software/drill-notebook>。本功能不需要用户提供 GitHub 账号或访问令牌。

## 3. 设置与时间规则

### 3.1 设置

| 设置 | 默认值 | 行为 |
|---|---|---|
| 自动更新 | 关闭 | 每次启动立即检查；有未跳过的新版本就下载并自动重启，独立于自动检查开关，不受间隔限制 |
| 自动检查更新 | 开启 | 按间隔获取版本信息，发现新版显示顶部入口；运行中不自动下载或重启 |
| 检查与提醒间隔 | 24 小时 | **唯一的间隔设置**，自动检查和自动弹窗共同使用；提供 1 / 6 / 12 / 24 / 48 小时与自定义 1–168 整数小时 |
| 启动时更新提醒 | 开启 | 自动更新关闭时，只有新版和提醒冷却条件满足才自动弹出；关闭后保留顶部入口 |

「自动更新」与「自动检查更新」分别控制启动更新和周期检查。关闭自动检查会暂停周期检查与启动说明提醒，但不影响已经开启的启动自动更新；间隔置灰并保留原值。自动更新开启时，启动说明提醒置灰并保留偏好，由更新进度替代下载前的说明提醒；关闭自动更新后按原偏好恢复。手动检查始终可用，手动检查发现新版仍先展示说明，点击「立即更新」才发起更新。设置即时保存，重启后恢复；更改间隔按已有时间重新计算，不伪造刚检查或刚提醒。

### 3.2 共用间隔，分别计时

只对用户展示一个间隔值。内部保留「上次成功检查时间」和「上次更新弹窗提醒时间」两类事实：

- 自动检查到期：距上次成功检查达到所设间隔；首次无记录时允许检查。成功检查才推进该时间，失败单独退避，手动检查成功也更新此时间。
- 自动弹窗到期：距上次实际展示新版弹窗达到同一间隔；首次无提醒记录时允许提示。实际展示时记录时间，右上角 ×、Esc、切换页面或重启都不能清空它。
- 启动说明提醒还须同时满足：自动更新关闭、自动检查与启动提醒开启、本次启动的初始化阶段、存在更高且未安装的未跳过版本、当前启动尚未自动提示。已有缓存可恢复顶部状态；本次检查失败不据此弹出过期的自动提示。
- 手动检查、点击顶部入口不受提醒冷却限制；它们展示新版弹窗时也记录提醒时间，以免用户刚看完就因重启再次自动看到。
- 关于页「更新内容」为只读入口，即使默认范围附上待安装说明，也不属于新版提醒，不推进提醒时间。
- 运行中周期检查不自动打开弹窗、下载或重启。启动自动更新不使用上述间隔或说明提醒冷却；成功检查仍记录真实检查时间。软件关闭时不运行更新任务；没有系统计划任务、托盘更新常驻服务或启动项。

时间记录落在 APP_ROOT，不能仅存在当前窗口或进程内。辅助窗口不能另起检查计时器或重复弹出同一个更新提示。

### 3.3 默认 24 小时的提醒例子（自动更新关闭）

| 场景 | 自动弹窗 | 顶部图标 |
|---|---|---|
| T0 首次发现新版并显示弹窗，点击 × | 关闭当前弹窗，记录 T0 | 保留 |
| T0 + 5 分钟重启，仍有同一个新版 | 不弹 | 保留 |
| T0 + 23 小时重启，仍未更新 | 不弹 | 保留 |
| T0 + 24 小时后启动，仍有未跳过新版且本次检查正常 | 可再次提示 | 保留 |
| 应用一直运行，后台到期发现新版 | 不弹 | 显示 |
| 点击「跳过此版本」后重启 | 该版本不弹 | 隐藏 |
| 手动检查发现之前跳过的版本 | 仍展示，允许立即更新；仅查看不清除跳过记录 | 继续隐藏，除非用户明确恢复该版本提醒 |
| 后续出现更高的新版本 | 按共享间隔与启动条件提示 | 显示新版本入口 |
| 更新后运行的版本已是最新 | 不弹 | 隐藏 |

「跳过」只作用于明确的目标版本，不关闭自动检查。关于页显示跳过记录并提供「恢复提醒」，避免用户只能通过更新才能撤销选择。

### 3.4 每次启动自动更新

- 读取 APP_ROOT 内的偏好后，只要「自动更新」开启，本次启动立即发起一次真实检查，即使上次检查未满间隔或「自动检查更新」关闭。与其他检查入口合并同一在途任务，不因主 / 助手窗口初始化重复检查。
- 有更高且未跳过的版本并存在匹配便携包时，不先弹出 Release 确认，直接显示更新进度并进入 U08 的完整更新事务。启动进度尽量在恢复业务编辑和 AI 任务前显示，避免先开始工作再立即重启；更新成功后自动重新打开软件。
- 没有新版或目标已跳过时正常进入软件；跳过记录同时阻止该版本的启动自动下载。手动检查与「立即更新」仍可更新已跳过的版本。
- 检查、下载或校验失败时反馈真实原因，保留当前程序并允许正常使用；不会据此声称已是最新或自动反复重启。程序替换 / 新版本启动失败沿用事务恢复，失败目标需手动重试，不能形成启动更新循环。
- 开启开关本身只保存后续启动偏好，不在正在使用的软件中立即重启。已经开始的更新由进度弹窗的「取消下载」停止；关闭进度窗口不取消已发起的更新和自动重启意图。

## 4. 版本来源与 Release

- 使用本仓库公开 GitHub Releases。排除 draft，按语义版本选出适用于当前 Windows x64 的更高版本，禁止版本字符串字典排序与降级。
- 兼容当前发布规则：v1.0 前 Release 均标记 Pre-release、没有 Latest。因此不能只查询 `/releases/latest`，也不能把无后缀的 v0.x 当成稳定发行。
- 匹配现有资产 `Drill-Notebook-<版本>-win-x64-portable.zip`；不下载其他系统、架构、安装包或源码 ZIP。存在新版但无匹配便携包时说明不可用，不显示「已是最新版」。
- 当前版以打包后 Electron 运行时版本为准，发布脚本注入版本；开发态明确标记，不允许下载后的程序覆盖开发工作区。
- 弹窗展示该 Release 的原始正文，支持常用 Markdown 标题、列表、链接、代码与表格；正文为空时显示「此版本未提供更新说明」及原文入口，不生成虚构说明。
- 检查失败、限流、离线及无法识别版本分别反馈真实状态；上次成功的检查记录只作历史信息，不能将失败结果写成「已是最新版」。

### 4.1 关于页的更新内容：Magpie 范围与只读展示

关于页的「更新内容」按钮放在「GitHub 主页」旁边，两者使用同样的按钮样式。GitHub 主页实际实施使用 GitHub 图标与文字，草图同样保留该图标。

采用用户参考的 [yetone/magpie](https://github.com/yetone/magpie) 的更新内容范围与菜单交互。这里的「当前版本」始终指**当前正在运行的已安装版本**，不指检测到的新版或正在查看的某个 Release。此入口只读，不提供跳过、下载或重启操作；底部只有「关闭」，右上角 × / Esc 也可关闭。

弹窗右上方使用 pill 按钮打开范围菜单，菜单标题「显示的更新说明」，选中项带勾；默认「上次更新以来」，不使用原生 select：

- **上次更新以来**：沿用 Magpie 以「上次成功运行版本」判断本次是否刚升级的方式。刚升级时展示上次运行版之后、直到当前安装版的各版说明；普通同版启动、首次使用或没有记录时，已安装部分只显示当前安装版。已知有待安装新版时，将当前安装版之后、直到已知目标新版的各版说明放在前面，每版标注「尚未安装」；已跳过目标另标「已跳过」。检查失败但有上次成功的新版缓存时可供手动阅读，并明确缓存状态。
- **当前版本及之前 10 / 20 / 50 / 100 个版本**：包含当前已安装版及其之前最多 N 个版本；可用 Release 少于上限时展示实际数量。即使已缓存更高的新版本，也必须从这个列表中过滤掉。
- 「当前版本及之前 N 个版本」最多为 **N+1 版**；只有实际运行新安装版，上限才随之改变。切换范围可以按需获取该范围的 Release 正文，但不执行版本检查、不改变跳过记录或新版提醒时间。
- 说明加载失败时保留该范围内已有正文，在顶部显示错误，并提供对同一选中范围的重试；缓存不足时明确实际数量，不混入范围外的版本。更新检查失败不能改变历史 N 范围的安装版上限，也不能据此声称已是最新。
- 再次从关于页打开时恢复默认「上次更新以来」。范围菜单支持键盘和窄窗口，正文仍逐版展示，不采用 Magpie 的多版融合、去重或重新归类。

### 4.2 检查更新后的内容：只展示尚未安装的版本

手动检查发现新版、顶部图标和启动提醒打开新版「更新内容」弹窗，只展示**当前安装版之后、到目标新版之间**的各个 Release，不混入当前安装版或更早历史。每版标注「尚未安装」，已跳过的目标另标「已跳过」。这里只展示需要更新的版本，不提供历史范围下拉。

例如已安装 v0.7.2、检查到 v0.8.0，中间存在 v0.7.3：检查更新弹窗依次展示 v0.8.0、v0.7.3。关于页默认范围可在已安装说明前附上这两个待安装版本；切换到「当前版本及之前 10 个版本」时，则只展示 v0.7.2 及更早最多 10 版，直到实际升级成功。

手动查看已跳过的目标仍可更新，查看本身不恢复提醒。检查失败时只允许手动查看上次成功检查所得的新版内容并明确提示缓存状态，不能自动弹出过期提示或声称已是最新。正在阅读、下载、校验或重启的更新目标固定，不被后台检查中途替换。

两个入口均按语义版本从新到旧逐个展示，各版保留独立版本号、日期、原始 Markdown 正文和对应的 GitHub 原文链接；不融合、去重或重新生成多版说明。可复用同一弹窗组件，但两种入口的版本筛选、范围控件和底部操作必须按上述规则分别处理。

## 5. 便携性与更新保护

以下约束已落地并通过原生及真实应用验证。所有路径从已有便携路径解析取得 APP_ROOT，详细字段与事务协议见[规格](spec.md)。

| 材料 | 实际落点 |
|---|---|
| 更新偏好、跳过记录、检查与提醒时间、上次成功运行版本 | `APP_ROOT/config/update-settings.json` |
| Release 元数据与下载 ZIP | `APP_ROOT/cache/updates/` |
| 解压暂存、替换辅助程序、事务与健康记录 | `APP_ROOT/runtime/updater/<事务 ID>/`，与退出时清理的 `runtime/tmp/` 分开 |
| 旧程序与停机数据库备份、失败启动后的数据副本 | `APP_ROOT/backups/updates/<事务 ID>/` |
| 失败目标与恢复原因 | `APP_ROOT/config/update-failure.json` |
| 助手未发送草稿与便携加密材料 | `APP_ROOT/config/assistant-drafts.json`、`assistant-drafts-key.bin` |

- 只按程序文件清单替换 Electron、后端 JAR、随包 JRE 等受管理文件；不能直接解压覆盖整个根目录。保留用户数据、附件、配置、已有导入 / 备份 / 本地模型及其他非程序文件。
- 下载包校验公开 GitHub 来源、语义版本、ZIP 总大小及 SHA-256，优先使用 GitHub 资产 digest，否则读取同名 `.zip.sha256`；缺少校验材料或程序清单时拒绝替换，提供 GitHub 原文入口。ZIP 与 `drill-program-manifest.json` 的文件集合、逐文件大小及摘要必须一致，拒绝路径穿越、Windows 别名、重复路径、链接和清单外文件。
- 替换前预检根目录可写、空间足够、下载包有效。点击「立即更新」或启用后的启动自动更新已经发起完整更新事务；下载与校验成功后自动保存编辑、处理 AI 活动和待发内容，并正常退出主 / 助手窗口与后端，不再增加常规的重启确认。保存失败或已有退出保护需要用户处理时暂停后续替换并说明原因，不能丢弃草稿或强杀运行中的任务。
- 辅助程序仅在本次更新事务内运行，等待本应用退出再替换和重新启动；只作用于经核验的 APP_ROOT，没有管理员提权、安装服务、注册表或持久化环境变量。
- 只在旧 Electron 和 JVM 均退出后备份程序及 SQLite 数据库，完整恢复基线落盘并校验后才替换。新版后端与主界面就绪前不恢复业务编辑；新版启动失败时保留失败数据副本、恢复旧程序与停机数据库并重开旧版，不让旧程序直接打开迁移后的数据。已确认健康是事务提交点，之后的恢复不得覆盖用户继续编辑的数据。失败版阻止启动自动更新循环，仍允许用户手动重试。
- 下载 / 校验失败不替换程序，保留可理解的重试入口。「取消下载」终止当前更新及其后续自动重启；右上角 × / Esc 只关闭进度界面，成功后仍继续自动重启。下载缓存与程序备份只保留有界数量，成功后清理本事务暂存，不能让每次更新都无限堆积整包与解压副本。
- 不写系统 `%TEMP%`、用户 AppData、注册表或系统目录。真实更新、自动重启和失败恢复的运行审计通过；外部受监控目录新增 / 变化为 0。静态审计及 Rust / mjs 补充扫描未发现持久化注册表或环境变量操作，开发工具只恢复 Process 范围环境变量。
