## 1. 结论与产品目标

v0.7 要让用户感受到三件事：换个会话仍知道已经确认的学习偏好和目标；对话变长后不会无节制地重复发送历史；用户能查看、更正、停止使用和真正遗忘记忆。

v0.7.0 地基采用 **SQLite 加密事实库 + 进程内词法索引 + 有限后台提取 + 任务续接摘要 + 后端统一上下文投影**。R4 后续在同一底座上增加“自然语言管理 + 共用读取服务 + 有界只读工具 + 可选本地混合检索”。沿用 Java、SQLite、React、现有模型代理，不安装新的独立服务。历史保留与模型输入长度分别管理，压缩不改写、也不删除原聊天。

“跨会话记忆”与另外三种能力必须区分：

| 数据 | 回答的问题 | 是否跨会话注入 | 谁是事实来源 |
|---|---|---|---|
| 长期记忆 | 用户偏好什么、当前有什么目标 | 按授权、作用域和相关性 | 用户原话或用户手动录入 |
| 会话摘要 | 本会话的目标、约束、建议与待完成事项 | 否，仅原会话 | 已完成对话；助手自述不等于执行成功 |
| 笔记本 RAG | 用户资料里写了什么 | 沿用现有检索选项 | 笔记正文 |
| SRS/界面状态记忆 | 该复习什么、界面停在哪里 | 不作为个人事实库 | 学习业务数据/界面设置 |

记忆不是完整历史的无损替代物，也不是让模型修改系统规则的入口。目标是“有预算、可追溯、能纠错”，不承诺“永远只用 100 Token”或“所有历史细节都记得”。

### 1.1 v0.7.0 地基发布必须包含的能力（后续增量见 §9.5–§9.8）

1. 手动添加、编辑、停用、删除记忆；自动提取可单独开关；默认首次使用需用户选择开启。
2. 自动记忆有原话证据、作用域、创建时间、有效期、版本和来源；不把 AI 推测当作用户事实。
3. 新会话可检索已生效记忆；本次不使用记忆、本会话不学习均有独立控制。
4. 同一事实更新后默认只使用当前版本；不确定的冲突进入待确认，不能简单“最后生成者获胜”。
5. 长会话有摘要和预算裁剪；当前问题不会被静默截断；所有缩减有可查看的状态。
6. 普通和 SSE 对话使用同一套上下文与落库逻辑；支持停止、切会话、重试与进程重启。
7. 使用记录显示“提供给模型的记忆”，不伪称模型确实使用了每一条。
8. 有真实输入用量/估算用量、缓存命中、后台调用次数；达到限额自动暂停后台任务，不影响普通聊天。
9. 原始聊天按游标分页查看，默认不按条数/天数自动删除；达到本地容量上限时先提示，不悄悄清历史。
10. 回答下可检查本轮实际发送的上下文类别、来源和省略原因；打开历史或检查器不会发起新推理。

### 1.2 明确不做

- 自动从整库笔记、题目、网页、附件或模型思考链推断个人画像。
- 多账号、云同步、长期原始聊天全文搜索、任意实体关系图、多跳图查询。
- LLM 自由调用记忆 CRUD、自改系统提示词、无限反思循环。R4 后续仅允许受服务端权限与预算约束的只读 search/list 工具。
- 自动扫描全部历史聊天、默认外发记忆做 embedding、下载新的生成模型。
- 为命中缓存而把短提示词填充到长前缀；照搬某厂商测试中的省钱比例或延迟保证。
- v0.7.0 不提供记忆向量检索；后续 E6 评测本地混合检索，不把它当 E4 工具闭环的前置。远程向量化需另设计并取得授权，不是默认后备路径。
- 不迁入 harness 的完整分支树、任意工具调用、明文 JSONL/Git 记忆仓库、自动 dream agent 或自动重跑中断任务；会话继续仍由用户发起。

### 2.1 必须先解决的现有风险，仅限本次涉及路径

- 消息加密失败：移除新聊天写入路径的明文回退。普通响应仍可显示已生成内容，但返回 `persistenceStatus=failed`，不触发记忆；流式同理。不得把失败伪装成保存成功。
- 不在本版本追溯重加密全库，不修改原有密钥算法或全库引入 SQLCipher；旧明文消息读取兼容，但记忆本身必须加密。
- R3 替换旧的 500 条自动删除策略：500 仅作为前端驻留消息上限，数据库保留遵循 §7.4。旧版本已经删除的原文无法通过迁移恢复；不作无限容量或备份之外的数据恢复承诺。
- `DESIGN.md` 的旧 autosave debt 与 MEMORY/新代码可能不一致；不顺手改编辑器。

### 3.2 ADR-01：不用图数据库，采用“结构化事实 + 来源 + 版本”

主要问题是“偏好简短/详细解释”“正在准备哪场考试”“某本笔记的学习目标”，不是企业关系网络。用 `subject/predicate/value/scope/time` 可表达，SQLite 事务还更容易保证手动修改与后台任务不互相覆盖。未来若评测证明实体多跳是主要失败原因，再增加图投影；事实库仍为权威数据源。

### 3.3 ADR-02：不把记忆明文写入现有 RAG 表

记忆逻辑 corpus 为 `CONVERSATION_MEMORY`，**物理上独立存加密表**；v0.7.0 解锁时建立只在 Java 堆内的词法索引。后续本地语义索引遵守同样的隔离/锁定规则，不把个人正文复制到 NOTEBOOK FTS。NOTEBOOK 继续使用现有系统；两条来源经上下文计划汇合，各有预算，不把 BM25 和向量原始分数直接相加。

这是对 `docs/reference/ai-retrieval.md` §13“复用所有物理表”的有意修订：保护个人事实的保密性和 NOTEBOOK 既有 coverage 契约优先于表复用。实施时更新该节，注明设计变更；不得一边宣称加密，一边把解密正文复制进 `retrieval_chunk.text`、FTS、日志或磁盘缓存。

v0.7 的 NOTEBOOK corpus 枚举可维持原样；新增记忆域自己的类型常量即可。未来若统一索引，必须先设计按 corpus 的授权与状态，不能污染现有 selected space。

### 3.4 ADR-03：LLM 提候选，服务端决定是否写入

提取模型不接收数据库句柄，不产生可执行 SQL，不任意删改 ID。输出候选事实与原话位置；确定性校验器决定 CREATE、CONFIRM、REPLACE、REVIEW、IGNORE。低能力模型最多让某条记忆不产生，不能让库被误删或越权。

### 3.5 Harness 源码证据与可迁移机制

下面区分“代码中看到的机制”和“本项目的设计选择”，不把别的产品实现当成兼容性保证，也不复制其长提示词或代码。

### 3.6 ADR-04：借鉴会话管理机制，不引入通用 agent 系统

三个视图必须独立：①历史视图保留用户实际说过/模型实际返回的记录；②上下文投影视图只包含本轮有权限且装得下的内容；③学习来源视图只包含获授权的新 COMPLETED 用户来源块。压缩只替换②中的部分呈现，不修改①、不扩大③。摘要、历史和事实也不能共用一个“已处理”标志。

Codex 的两阶段机制在此落为“有限 LLM 候选 → 本地去重/冲突/版本事务”，不是再调用 agent 整理全库。Pi 的 checkpoint 思路落为加密摘要＋来源覆盖＋有界近期查询，不要求另建 JSONL、树状会话或复制冷存储。进程重启/打开会话只恢复可读状态，不续跑旧聊天动作。

## 4. 最终架构与不可破坏的不变量

```text
React：本次输入 + 会话ID + 请求ID + 页面上下文 + 记忆选项
                         ↓
ChatTurnService：校验/幂等/来源绑定/开始轮次
                         ↓
ConversationProjection：有效检查点 + 有界历史尾部 + 来源/权限过滤
                         ↓
ChatContextAssembler：固定规则 + 任务续接状态 + 相关记忆 + 笔记RAG
                         ↓
ContextBudgeter → 唯一 ChatContextPlan → AiUpstreamClient / 本轮上下文检查器
                         ↓
事务：保存轮次终态、完整消息、用量、待处理工作范围
                         ↓（提交成功后，且已授权）
MemoryMaintenanceWorker：有界提取/摘要 → 校验与冲突处理 → 加密事实库
                         ↓
提交后更新进程内索引；下一次对话可见
```

不变量：

1. 一个 `requestId` 只对应一个会话、一个输入指纹、一个逻辑轮次；一个会话最多一个运行中轮次。
2. 只有 `COMPLETED` 且正文非空的轮次可自动学习；reasoning 永不进入提取、摘要或记忆检索。
3. 关闭自动学习不能阻止手动管理；关闭使用记忆不能偷偷把记忆送去模型。
4. 任何网络调用都不在 SQLite 写事务内；外部服务失败不得破坏已保存消息。
5. 记忆只有 ACTIVE、未过期、作用域匹配、已解锁、已获当前模型外发授权才可注入。
6. 人工编辑保护优先于后台结果；旧任务不能覆盖新版、撤回授权或“遗忘”操作。
7. NOTEBOOK 的存储、RAG 开关、远程 embedding 授权和 coverage 与记忆独立。
8. 所有新文件只在 APP_ROOT；运行时不写 `%TEMP%`、注册表、用户配置目录或持久化环境变量。
9. 清空/删除返回成功前，读路径就不能再取到目标内容；索引不能靠下一次重启才失效。
10. 预算裁剪、摘要生成、前端卸载旧页面均不能删除原始历史；删历史只能走用户确认的清理事务。
11. 请求序列化、Token 估算、实际提供的引用与检查器来自同一个不可变 ContextPlan，不分别挑选内容。
12. 摘要中的待办/建议不是执行指令；中断信息来自服务端终态，助手自述不能产生“已验证完成”状态。

## 5. 产品行为、授权和作用域

### 5.1 开关不合并

设置页新增“AI 记忆”卡片，每项仅一句说明；详细边界放帮助/首次授权弹窗。

| 设置 | 默认 | 精确定义 |
|---|---|---|
| `enabled` | false | 允许使用本地记忆模块；关闭暂停提取/注入但不删除内容 |
| `autoExtract` | false | 开启后从后续合格用户发言提候选；关闭不阻止手动添加 |
| `autoApplyLowRisk` | true（autoExtract 开启后才生效） | 明确、低风险且无冲突的偏好自动生效；其余待确认 |
| `compressSession` | false | 允许为当前会话生成有偿滚动摘要；无论开关如何都执行硬预算 |
| `allowMemoryUse` | 每轮继承设置 | 该次是否向当前聊天模型提供已保存记忆 |
| `learnFromSession` | 新会话默认 true | 本会话是否可用于后续自动提取；关掉同时取消未提交学习任务 |
| `scope` | GLOBAL | 会话的记忆读取/写入上下文；可显式绑定 NOTEBOOK ID |

“本次不使用记忆”和“本会话不学习”不等于无痕聊天：原聊天仍按现有规则保存。v0.7 不使用“临时聊天”这个容易误导的名称。

首次启用按两个动作分别授权：①把选中的历史记忆发给当前主模型辅助回答；②在后台把新对话发送给维护模型做提取/摘要并产生额外用量。展示 endpoint 主机、模型、数据种类、每日限制，未同意不能发送。手动录入在本地可用，不需要外发授权。

授权指纹：`purpose + normalizedEndpoint + apiFormat + model + policyVersion`。purpose 区分 `MEMORY_USE` 与 `MEMORY_MAINTENANCE`。按现有 endpoint 归一化，不擅自改路径/大小写敏感部分；改变目标即失效。仅更换同 endpoint 的 API key 不改变数据接收方，但仍检查 key 是否可用。复用聊天设置不等于自动继承提取授权。

维护模型 v0.7 默认用主模型，无新增“导入兜底”隐式调用。设置中支持 `maintenanceModelMode=chat|dedicated`；dedicated 使用新 `purpose=memory` 配置行和现有模型卡片。选定后失败就暂停，不偷偷回退另一家、更贵模型或导入模型。切换模式需重新确认实际目标。调模型连通性测试只发固定 pong，不带用户数据。

### 5.2 作用域

- 一个 APP_ROOT 视为一个本地使用者；不是多用户安全边界。共用电脑的人应使用不同便携数据目录。
- GLOBAL 保存明确的普遍偏好；NOTEBOOK 保存仅对某笔记本适用的事实/偏好，scope ID 必须后端验证存在。
- 全局会话只能读 GLOBAL；绑定笔记本会话读 GLOBAL + 同一本 NOTEBOOK；不能从其他本“顺便召回”。
- 同 predicate 的笔记本偏好覆盖全局偏好，但不删全局记录；当前用户指令覆盖二者。
- 页面跳转不能悄悄改变会话 scope；切换 scope 需显式操作并显示标签，下一轮生效。
- 用户提到“在另一门课里……”不能由模型自行绑定或创建 notebook ID；进入待确认。
- 删除笔记本时，同 scope 的记忆/候选/后台工作删除，相关会话解除绑定为 GLOBAL。既有聊天不级联删除；清除对应摘要，禁止自动将被删作用域的旧发言转为 GLOBAL 记忆。

具体切换事务：存在 RUNNING 时返回409 `SESSION_BUSY`，不在正在回答时改变其来源。否则将当前最大turn ID记为边界，递增context_generation、修改scope、将提取/摘要scan水位推进至边界、失效摘要并取消旧generation任务，再提交。UI说明“此前未整理内容不再自动补记，已确认记忆仍留在原范围”。每个新turn固化source_scope_type/source_scope_id/source_timezone及generation，job复制这一快照，只处理同generation/scope的轮次。即使切回原笔记本也不回扫旧边界。删除笔记本不等待网络：取消相关运行请求并递增generation，使其迟到结果无学习资格，再解除绑定。旧turn的scope快照保留原ID，不设会级联变GLOBAL的外键。历史UI仍可查看旧发言，但自动近期上下文只取当前generation，切换处显示上下文已重置。

### 5.3 什么值得记

自动提取仅面向：回答风格/语言偏好、明确学习目标、明确学习背景、正在进行的任务及约束。例：“以后解释算法先给例子”可记；“这题举个例子”仅本轮要求，不长期记；“假如我是医生”不是职业事实。

默认不自动保存：密钥/密码/验证码/证件/金融账户、精确住址与联系方式、健康与其他敏感个人信息、第三人的个人画像。识别到凭据格式时，送维护模型前用占位符替换；候选和原话片段再次过滤。规则与模型都不是完美 DLP，文案不得承诺自动识别全部敏感数据。凭据类手动记忆也拒绝；其他敏感事实仅用户手动明确录入并确认。

模型自己的回答、引文、笔记、导入资料、system 指令、错误文本和“无法解密”占位符都不是自动事实来源。assistant 正文只可供会话摘要解释讨论过程，不能证明用户事实或执行成功。

优先保存能改善未来互动的明确反馈，例如“以后先指出我的推理错误，再给答案”；在现有 answer.* 无法准确表达时进入 other 待审阅，不擅自扩充可执行 predicate。一次任务的进展通常留在本会话摘要，只有用户明确表达跨会话目标/约束时才进入长期候选。笔记里可重新检索的定义、题解、文档说明不复制为个人记忆；短事实库也不加一层有偿 LLM 索引摘要。

### 5.4 来源必须结构化，不能只靠提示词排除附件

v2前端提交独立userText和attachments，不再把文本文件拼入用户正文。后端保存USER_AUTHORED/ATTACHMENT_TEXT/ATTACHMENT_IMAGE来源块及稳定blockId；提取只读取USER_AUTHORED块，候选quote必须在对应block内连续匹配。用户正文中粘贴的引文仍需否定/引用语义校验，无法确定则拒绝或待确认，不能宣称来源标签解决全部语义歧义。v1及旧混合消息只供历史展示，不自动学习。

附件仅供聊天回答，不进入事实提取、existingFacts或摘要原料；摘要可记录有来源的助手讨论结论，但不得把它升级为用户事实。结构化消息、加密附件持久化和跨轮图像重放按contracts §4.3执行，不能继续用“[图片附件]”占位符冒充可恢复图像。

## 6. 数据模型与加密契约（schema 9）

先建立 DTO、枚举、migration 测试，再写仓储。表名固定如下；字段可为工程需要增加，但不得省略并发、来源和授权字段。完整字段约定见配套 [数据与协议规格](v0.7-ai-memory-contracts.md)。

| 表 | 核心内容 | 生命周期 |
|---|---|---|
| `ai_memory_vault` | 单个本地记忆库 ID、wrapped DEK、mode、加密版本、epoch、revision | 首次手动创建/启用时创建，不在迁移时自动建密钥 |
| `ai_memory_settings` | 开关、预算、两种授权指纹、policy revision | 启用/撤销必须递增版本 |

| `ai_memory_evidence` | 用户消息 ID/轮次/会话、加密最短原话、内容指纹 | 不依赖前端是否加载历史；用户删来源时同步清理 |

| `ai_memory_suppression` | 遗忘/停用的 HMAC key 与作用域、时间水位 | 防旧任务/旧历史重新引入；只有显式解除才移除 |

不要将个人文本写成 SQL key：`subject/predicate/value/title/keywords/evidenceQuote` 放加密 payload，索引需要的等值 key 用专用派生 HMAC 密钥；枚举、状态、时间和 scope ID 可明文，明确这些元数据仍会泄露活动轮廓。

### 6.1 加密实施步骤

1. 新建 `MemoryCryptoService`，使用 JCA AES-256-GCM；生成随机 32-byte DEK，每次写入随机 12-byte IV。AAD 绑定 `vaultId/table/rowId/version`，防密文跨行替换。
2. DEK 用现有 `ApiKeyEncryptor` 的 Argon2id/AES-GCM 包装一次，保存 wrapped DEK 和 salt/iv/mode；不要给每条记忆重复跑 32MiB Argon2，解锁后 DEK 仅驻内存。
3. HMAC key 从 DEK 经标准 HKDF-SHA256、独立 info 标签 `memory-lookup-v1` 派生，不把 DEK 直接复用于 HMAC，不使用未加盐 SHA256 保存个人事实键。
4. `fingerprint` 模式只提供与现有实现一致的轻量静态保护，不防同机用户/恶意软件；`password` 模式需要显式解锁。Java 字符串无法保证完整清零，尽量缩短明文生存期，不宣称防内存取证。
5. 第一次有主密码的会话启用记忆时必须使用 password vault；禁止把密码保护会话自动提取到 fingerprint vault。模式不兼容则 `MEMORY_SECURITY_MODE_MISMATCH`，不偷偷降级。
6. 已有 password 消息的解密材料与 vault DEK 不同：维护任务只在相应会话密码已于当前进程授权解锁时运行；无材料则 `WAITING_UNLOCK`，不能拿占位文字送模型。会话密码不落队列表、localStorage、URL或日志。
7. 解锁材料存受控内存引用，默认闲置 15 分钟锁定；锁定取消维护请求，清空索引/解密摘要缓存/前端 React Query 记忆数据；已飞出的网络请求无法撤回，但结果不得提交。
8. 指纹换机可能失效：迁移前用户可在记忆管理中设置密码，重新包装 DEK。更改密码只 rewrap，不重写全部事实。忘记密码不提供“恢复”，仅允许明确清空旧记忆库后重建。
9. 加密失败 fail-closed：记忆保存返回错误；后台任务记录无内容错误码；不能回退明文，也不能清空旧值。单条坏密文隔离为不可用，不让整库解锁崩溃；UI 显示损坏条数。

### 6.2 有效期与版本

- `observedAt` 是来源发言时间，`recordedAt` 是入库时间；自动更新按来源时间/稳定消息 ID 排序，不按任务完成先后。
- 稳定风格偏好默认无到期；学习目标默认 90 天待复核；当前任务默认 30 天；明确日期到期按用户时区处理。上述是产品初值，不是心理学结论。
- “明天”按来源会话的时区/日期解析，不按后台执行时刻；时区缺失或语义有歧义进入待确认。存 UTC Instant 与原时区；纯日期用 date + zone，不伪造成毫秒精度事实。
- 到期读路径立即排除，定时清理仅更新状态；不能等清理任务跑过才停止使用。
- 更新产生新版本，旧版本 SUPERSEDED；自动默认读只取当前 ACTIVE。历史版本仅管理面板可见，不做历史问答承诺。
- 默认最多 2,000 条 ACTIVE、500 条 PENDING；每个事实保留最近 5 个版本和至多 3 个有效来源片段。达到上限暂停自动新增并显示整理入口，不能暗中删人工记忆。

## 7. 轮次一致性：先修地基，再接记忆

### 7.1 v2 请求与兼容

沿用 `/api/ai/chat` 和 `/api/ai/chat/stream`，新增 `protocolVersion: 2`（见配套规格）。新前端只传本轮 `input`，不传所有历史/system 消息。后端从指定 session 读取已保存消息和摘要。

旧 v1 `messages` 继续接受一个版本周期，走旧适配层但不自动提取、不注入新记忆；仍实施保守预算和输入校验，保存复用新的容量/历史保留层，不能继续调用旧500条删除分支。新服务端不把旧客户端提供的 assistant/system 内容写为记忆事实。v1 相同重复内容不能靠文本去重推断请求身份；其幂等能力不作保证。mock 模型也走统一组装，不能提前返回绕过记忆逻辑。

### 7.2 标准处理顺序

1. 校验 input 非空、session 存在、scope 合法、requestId 为 UUIDv7；同 requestId 不同 session/input 指纹返回 409。
2. 在短事务中检查并占用本轮历史/附件容量，预留有界回复空间，登记 `RUNNING`、加密保存用户消息并取得真实 ID；按 session 的部分唯一索引拒绝第二个 RUNNING（409 `SESSION_BUSY`）。额度不足先返回 `HISTORY_STORAGE_FULL`/`ATTACHMENT_STORAGE_FULL`，无上游调用。输入指纹覆盖有效请求字段，而非仅用户文本。
3. 读取上下文快照/生成 epoch；组装、预算、网络调用在事务外。失败用户消息保留并显示该轮失败；不会被当作已完成轮次参与摘要/学习。
4. 上游结果统一返回正文、reasoning、usage、finishReason、终态标记。只有正常结束且正文非空为 COMPLETED；主动停止为 ABORTED；读流失败/无终止帧为 FAILED；输出到限为 TRUNCATED。
5. 事务保存 assistant（含部分回复的原有展示能力）、轮次状态和有界上下文元信息，结算实际存储字节并释放该轮预留；用量按attempt独立结算。只有 COMPLETED 才更新维护水位/唤醒任务。网络断开不等于上游没完成，按实际已收到的终态裁决。
6. UI SSE `done` 在落库结算后发；若落库失败，则 `done` 带 `persistenceStatus=failed`、内容可见，不创建维护任务。恢复时不能把该轮假装为完成。
7. 同 ID 已完成：返回已存结果，不再调用模型；仍运行：返回 409 + 状态查询地址；失败/中止：返回既有状态，用户“重新生成”必须明确创建新 requestId，标记 retryOf。
8. 进程重启把遗留 RUNNING 置 INTERRUPTED，不自动重新外发聊天请求。网络调用的 exactly-once 无法保证，不做这种承诺。

### 7.2.1 完成失败的收尾路径（普通/SSE必须共用）

回复生成成功不等于轮次已成功保存。finalize事务回滚后，先按turn ID重读：若其实已提交，复用既有结果，不标失败；若仍RUNNING，另开不依赖正文加密的短事务，CAS为FAILED、persistence_status=failed、memory_eligible=0，仅保存无内容错误码/结束时间。失败回复只留当前UI，不伪造可恢复的持久回复。

用量结算与回复事务解耦：上游返回后按attempt ID独立幂等结算；正文保存失败不撤销已发生用量。用量写失败保留SENT预留，恢复后按UNKNOWN消费，除非还有可信实际usage可结算。禁止为补回复重新请求模型。

finally始终关闭上游响应体、撤销deadline任务、释放运行中句柄。若失败收尾仍因DB不可写而失败，置进程级存储降级，新请求返回503 `STORAGE_UNAVAILABLE`；UI显示回复未保存、状态待恢复。状态响应在此时可返回503，done中的status为FAILED并带stateDurable=false，不能谎称DB已经终结。每5秒有界探测恢复；DB可用后只将“无活跃句柄”的孤儿RUNNING置INTERRUPTED并清理未知用量，再解除降级。每个新请求也做同一孤儿检查，不能仅靠应用重启；不得将仍有活跃句柄的慢请求按年龄随意清掉。详情和伪代码见contracts §7。

活跃句柄必须在开始事务提交RUNNING之前登记，开始失败则finally撤销。孤儿检查、登记及开始事务在同会话短锁内完成，锁不跨网络调用；清理线程检查时使用相同短锁，避免“已提交RUNNING但尚未登记句柄”的正常请求被误判孤儿。读线程未退出的句柄仍算活跃，按§7.2.2暂停处理，不能为解除SESSION_BUSY伪造释放。

### 7.2.2 请求总期限与资源释放

维护调用30秒为覆盖建连、响应头、响应体读取的总期限，而非只给HttpRequest设timeout。AiUpstreamClient增加可取消RequestHandle（响应体引用、取消标志、一次性terminal门闩）；独立受限scheduler到期主动关闭响应体并取消发送future，读取循环和结果提交前均检查取消。尚未取得响应体时也能取消；刚取得时若已取消立即关闭。聊天使用已有用户超时配置但采用相同机制；维护deadline不得被后台重试重置成同一次attempt。

worker只有在读取任务确实退出后才释放执行槽。若关闭/取消后2秒仍未退出，标记worker不健康并暂停维护，不创建替代的无限线程；界面提示重新启动以释放资源。90秒lease仅防旧结果写入，不代替取消。达到期限、用户停止、正常结束竞争只能产生一个终态；晚到正文/usage可按attempt规则处理计量，但不能让被取消结果重新COMPLETED或学习。必须用本地悬挂响应体mock验证，不凭配置值宣称生效。

开始轮次时用户消息加密/落库失败，应在外发前报错；“回复仍可显示”只适用于上游已完成、最终保存失败的情形。模型上下文读取新增按turn/message ID倒序分页的方法，分批解密到预算足够即停，不调用现有全量 `sessions.messages()` 再全部解密裁剪；一批最多16轮，单请求最多扫描32轮，超出给裁剪提示。历史UI使用独立的50条分页接口，不受这32轮模型扫描边界限制。

若同requestId对应的回复已被用户明确删除，返回410 `RESULT_EXPIRED`，不能重新生成冒充幂等恢复。requestId固定UUIDv7；无记录的新请求只接受24小时内生成且不比服务器时间超前5分钟的ID。只有正文已被明确删除、终态和删除时间均已过至少30天、且无活跃依赖的turn墓碑才能清理；仍有原消息的turn不能因为到30天而删除。已有轮次即使超过24小时仍可查询。墓碑清理后旧ID仍因时间过期被拒绝；时钟异常给出提示，不修改系统时间。

### 7.3 中断与切会话

增加 `POST /api/ai/turns/{requestId}/cancel`，服务端 cancellation token 与关闭流连接共同中断上游。仅靠前端 abort 的时机不够。客户端切会话时的响应更新必须同时比较 requestId、sessionId、组件 generation，禁止写到新会话。

SSE 传输失败后的非流式自动回退，仅允许**确定未开始上游推理**（如明确不支持流式且请求未接受）。其他情况先查轮次状态，不用第二个请求重复生成/计费。已收到 text 或 reasoning 后绝不自动回退。

已有 `AiAssistant.test.tsx`、`AiAssistant.evidence.test.tsx` 与会话服务测试是回归入口；新增跨两个会话的延迟回调测试，不能只测函数调用次数。

### 7.4 原始历史保留、容量与用户清理

1. 新旧聊天都停止按500条删库。历史界面每页最多50条，以message ID游标翻页；前端内存最多驻留500条，卸载页只释放UI缓存，向上滚动可重新加载。会话归档只是隐藏列表项，仍占容量，默认排除后台维护；重新打开/取消归档不自动推理。
2. 正文＋思考＋请求/结果加密元数据的**逻辑存储**默认256MiB，附件密文另256MiB，80%预警。由 `ChatStorageSizer` 对实际落库字段的字节计数，包含Base64和加密封装，不按Token估算磁盘。DB页、WAL、索引、摘要/事实和备份另占空间，这不是512MiB物理磁盘总上限。
3. 开始事务原子计入本轮已知字节并预留2MiB回复空间；正文与reasoning的累计原始UTF-8捕获上限合计1MiB，结果元信息明文上限16KiB，加密膨胀由contracts §2.7证明可装进预留。普通/SSE均增量限流；超过捕获上限关闭上游，保存完整码点前缀并标TRUNCATED/`OUTPUT_CAPTURE_LIMIT`，不可学习。此限制是资源保护，不是用截断伪造已完成回复。
4. 完成、失败收尾及孤儿恢复在同一存储事务内结算/释放预留；DB故障沿§7.2.1关闭入口，不能重复释放。迁移统计旧密文字节不需解锁；若旧数据已超限，保留可读、可备份、可清理状态，阻止新增聊天外发直到用户清理或调额度。容量策略独立于20次/30K后台预算，UI不能混称“额度用尽”。
5. 用户清理必须先预览固定的会话/完整轮次范围、附件字节及受影响记忆，再确认；来源证据/候选同步删除，失去唯一来源的自动记忆删除，人工记忆移除来源但保留。失效相关摘要/任务、更新历史revision；若事实/证据变化也递增vault revision并同步过滤索引，之后才返回成功。v8 legacy消息按预览确认的连续完整展示轮次清理，不能误删半轮或扩展到未展示的范围。
6. 清理正文时也清request_meta中的原话/附件引用与result_meta，保留不含正文的turn墓碑用于410；锁定时允许按已确认ID删除密文，不要求解密原话。原聊天未删除就不因摘要、后台水位、前端缓存或30天任务保留策略被连带删除。旧版已丢失的记录不能重建。

## 8. 后台提取、摘要与调度

不是“每次关对话弹窗就总结”，也不是每条回复都调用一次大模型。后端常驻一个受 Spring 管理的有界 worker，随应用退出而退出；不注册 OS 服务。

### 8.1 触发与限额

初始参数集中放 `MemoryPolicy`，允许后续通过评测调整，不散落魔法数字：

| 参数 | 初值 | 目的 |
|---|---:|---|
| 完整轮次累计阈值 | 4 轮 | 批处理降低调用次数 |
| 有新合格内容后的空闲触发 | 60 秒 | 短会话也能形成记忆；关闭侧栏不阻止处理 |
| 高信号单轮触发 | 仅显式“记住”动作/明确长期偏好；5 秒合并窗口 | 新建会话前尽快保存有用信息；不能靠任意关键词扫描所有正文 |
| 单次提取输入 | 最多 8 个完整轮次、按维护输入预算裁剪 | 不重发整个会话；超出拆连续批次 |
| 摘要最小新增量 / 冷却 | 1,024估算Token / 距上次SUMMARY发送120秒 | 加上近期预算70%压力门槛；不是每轮都压缩 |
| 摘要最低净缩减 | 256估算Token | 不发布无收益的新检查点；相同输入不反复压缩 |
| 新事实候选 | 最多 6 条/调用，每条 value ≤160 Unicode 码点 | 防把聊天复制成记忆 |
| 维护单次输入/输出预算 | 3,000 / 1,024 估算 Token | 提取使用独立 options，不能复用 32K STRUCTURED_CALL |
| 后台并发 | 全应用 1；聊天优先 | 避免 429、重复提取与抢占回答 |
| 维护队列容量 | 最多 100 个活跃会话，每会话每类型至多 1 个待处理范围 | 队列合并水位，不堆同一会话的重复 job |
| 每日后台预算 | 20 次尝试 + 30,000 总 Token（取先达到者） | 含提取、摘要、修复和重试；不含用户正常聊天 |
| 调用超时/租约 | 30 秒/90 秒 | 防僵尸任务与 SQLite 长锁 |
| 重试 | 网络/408/429/5xx 最多额外 2 次；30 秒、120 秒+jitter | 401/403/结构非法不盲重试；遵守 Retry-After 和预算 |

提取与摘要分别判断阈值，不能用“4轮”代替摘要最小新增量。阈值按源内容累计；没有新内容时不创建远程任务。聊天仍在生成时不抢占同一配置的维护槽；超过队列容量只保存“仍有未处理范围”的水位，空闲再调度，不把正文复制到队列。所有数字都是待P0a/P11评测的工程初值，不是从参考项目照抄的性能保证。

### 8.2 一次提取的可执行算法

1. claim 一个 job，保存唯一 lease token；捕获 vaultEpoch、policyRevision、sessionGeneration、源消息水位。
2. 检查开关/授权/解锁/日预算；不满足则进入对应等待态，不算一次远程尝试，不忙循环。
3. 读取水位后的 COMPLETED 轮次，排除 reasoning、错误占位、外部上下文；提取输入只送用户发言，摘要任务可另读 assistant 正文。
4. 在本地过滤凭据；总输入包含提示词、既有事实和完整来源。多轮超限就缩小为连续完整轮次；单轮本身仍超限则 `SOURCE_TOO_LARGE`，不截半轮或否定语句冒充完整来源，UI可手动记忆。
5. 按词法匹配找最多 8 条既有相关事实，只送这些短事实的 ID/版本/value，不发送全库。它们只是辅助消歧，不授权模型改写 ID。
6. 使用配套提取提示词，要求严格 JSON；支持 native schema 的目标可启用，否则纯 JSON + 本地校验。所有候选均验证来源 ID、quote 是原文连续子串、角色为 user、时间和 scope 不能越界。
7. 最多一次格式修复（计入预算），只修结构，不授予更多数据；仍失败不写任何候选。每条语义不合格候选可独立拒绝，返回统计，不强迫全批成功。
8. 事务内再次检查 epoch、授权版本、sessionGeneration、lease token 和输入 revision；任一变化置 SUPERSEDED，不落结果。
9. 调用确定性冲突规则；写加密事实/来源/版本，更新已扫描水位与job；有待确认候选或空结果都推进水位。空结果为COMPLETED/`NO_NEW_INFORMATION`，不是失败重试；没有事实变化不递增vault内容revision、不重建索引。
10. 提交后增量更新内存索引并发出小型状态通知。UI 仅刷新管理数据和“新增记忆 N 条”摘要，不每轮弹阻塞对话框。

**候选验证不等于证明正确**：原文子串只能证明来源存在，不能自动证明候选是正确释义；因此自动生效限定为明确低风险偏好，其余待确认。不要用模型自报 `confidence=0.99` 跳过审核。

### 8.3 冲突判定表

事实键由规范化 `subject + predicate + scope` 派生；subject v0.7 固定为当前用户，predicate 使用有限词表（语言、详略、解释顺序、学习目标、学习背景、任务约束、其他）。其他类别默认 REVIEW。多值兴趣不能和单值偏好采用同一唯一约束。

| 情况 | 服务端动作 |
|---|---|
| 同键同规范化值 | CONFIRM：追加去重来源、更新 lastConfirmedAt，不新增 ACTIVE |
| 明确低风险单值偏好，来源更新，旧值为自动且无人工保护 | REPLACE：旧版 SUPERSEDED，新版 ACTIVE，保留来源 |
| 旧值是手动录入/编辑或 pinned | REVIEW：不能自动覆盖 |
| 新旧时间相同、代词模糊、scope 不确定、两个计划可能并存 | REVIEW：候选不参与注入，旧事实标记存在冲突；回答涉及该键时不武断应用 |
| 多值事实如学习科目 | 可并存，不用“同 predicate”删除旧条目 |
| 用户只说本次偏好/假设/引用别人 | IGNORE 或会话局部上下文，不长期保存 |
| 已有 suppression 命中 | IGNORE；除非用户在管理面板明确解除并重新添加 |
| 后到任务处理更早来源 | 不覆盖更新事实，作为历史证据或丢弃候选 |

自然语言“忘记...”只生成遗忘建议，不自动批量执行；UI 展示候选目标和确认按钮。用户点删除是确定授权，不需要再用 LLM 决定删除对象。

采用contracts §5的MEMORY_EXTRACT_V2：ADD为普通候选；REPLACE_PROPOSAL/RETRACT_PROPOSAL必须绑定本批existingFacts里真实的memoryId/version。多值“雅思改托福”必须生成替换建议，不是静默新增两个目标；未找到旧目标则仅生成托福待审阅候选并给出“未定位旧目标”，不猜ID。用户采用替换时校验旧版本、新family冲突与原来源资格，在同一事务中旧版SUPERSEDED、新版ACTIVE；确认过的结果manualProtected=true。撤销建议没有新值；确认后走现有删除+suppression+索引失效事务。待确认期间只抑制被明确指向的旧事实注入，不扩大到整个predicate；拒绝建议后恢复旧事实，且拒绝来源去重。建议过期/目标变化为STALE，用户必须重新审阅。

### 8.4 任务续接摘要算法（不是长期事实或自动执行队列）

1. 先在本地去除重复的页面/RAG片段，历史大附件只留来源占位，reasoning和失败轮次不入摘要；不改原始历史。再测当前generation的有界近期正文压力。只有压缩授权开启、压力≥近期2,400预算的70%、未扫且可摘要新增量≥1,024估算Token、距上次SUMMARY发送≥120秒时才自动排队；至少最近2个完整轮次始终排除在摘要源之外。
2. 使用 `SESSION_SUMMARY_V2`：`topic/taskGoal/confirmedUserConstraints/confirmedDecisions/discussionNotes/workItems/openQuestions/nextSteps/references`。每条带来源与角色；用户确认和助手建议分栏。工作状态只允许planned/in_progress/user_reported_done/unverified，不设由LLM宣告的verified。用户纠正替换旧摘要相应项；未确认建议不能升级为决定。
3. 输入=旧有效V2摘要＋按顺序取得的新合格完整轮次＋有界已提供引用ID，不含reasoning、附件原文、RAG原文或注入过的记忆正文。整包≤3,000估算Token、最多8轮，超预算按完整轮次拆批；单轮仍装不下为SOURCE_TOO_LARGE。空缺处标记未整理，不编造事实。
4. 校验来源/字段/长度后确定性删去低优先内容，发布模型可见摘要≤600估算Token；诊断coverage不混入这个Token预算。净缩减=旧摘要＋本批可替代原文的估算量−新摘要估算量；少于256则保留旧摘要，记录COMPLETED/`NO_COMPRESSION_GAIN`、推进已检查水位但不增加有效coverage，并标明缺口。相同输入不再自动调用。
5. 以 `(sessionGeneration, previousSummaryRevision, throughTurnId, memoryEpoch, inputRevision)` CAS保存检查点。新增轮次不使正在处理的旧批无效，但删/改批内来源、scope/授权变化、遗忘会拒绝旧结果。V1摘要不按V2解释；失效后仅在新授权、预算和来源边界内重建，不回扫已遗忘源。
6. `resumeState`由后端从当前generation最新终态派生，仅含requestId/status/time，不送失败或中断正文给摘要器，也不把它当成功来源。最新终态已COMPLETED就不追溯更早失败；恢复打开只显示“上一轮未完成”，用户下一次发言才开始新轮次，任务清单不能触发外部动作。摘要＋resumeState共用600的会话状态预算。
7. references仅保存本会话实际提供过的笔记pageId/contentVersion/来源turnId；每次使用前验证当前scope、存在性和版本，已变更则失效摘要并提示。引用不是永久全文缓存，查细节仍走用户当前请求下的既有RAG，不给模型任意文件/网络工具。

摘要缺失、失败或预算暂停时用有界近期完整轮次，并显示“较早内容未包含”。要查旧细节可分页打开原聊天再手动引用；保留历史不等于本版提供全历史自动搜索或所有任务跨会话续接。

### 8.5 无变化不运行：调度与整合的实施规则

`inputRevision`由准确的来源ID/内容版本、旧摘要revision、实际existingFacts版本、目标/prompt/策略版本派生HMAC；原始短文本摘要哈希不明文落库。claim后固定该批，新的发言进入下一批，不去修改CLAIMED输入。提取/摘要有各自水位与lastAttempt元数据；usage结算、阅读历史、刷新UI、lastAccess或排名变化都不算新来源。

成功空提取、全部候选被拒以及无压缩收益都记录终态和原因，定时器不能按“没有新增记忆”无限重试。相同输入已完成/失败已达上限则跳过；有新来源后才重新评估。手动flush可越过最小新增量和冷却，但不能越过授权、预算、源资格、最近2轮保留或相同输入终态门槛。网络/格式重试仍受§8.1次数与预算约束。

提取后的整理只运行确定性去重、冲突检查、版本事务和有变化的索引更新；不再安排第二个有偿“全库整合”任务。队列用现有SQLite lease/CAS处理陈旧占用，不引入参考实现的Git副本、文件锁或自主dream agent。

## 9. 记忆检索与上下文预算

### 9.1 v0.7.0：无远程调用的词法检索（R4 后续策略见 §9.5–§9.8）

新建 `MemorySearchIndex`，接口 `search(query, scope, now, limit, deadline)`；只接收已解锁、合法状态的事实。

1. 解锁后分页解密建立不可变索引快照；构建异步、可取消；未就绪时本轮不使用记忆并给出状态，不在首个聊天请求里同步跑几千次解密。
2. 文本做 Unicode NFKC + Latin 小写；汉字连续段生成相邻二元组和三元组，Latin/数字按单词切分；过滤固定的小型停用词表。单字查询不运行全库模糊匹配，只命中显式 key/标签。
3. 内存倒排索引用 BM25（k1=1.2,b=0.75）生成前 30 条候选；默认无 IDF 的模糊分数混加。另加入最多 2 条已批准的通用回答风格偏好（并非主题事实）。
4. 精确 phrase、匹配 predicate、同 scope 各作为稳定排序层：精确短语命中优先，然后 BM25 降序，最后 confirmedAt/id 打破平局。关键词零重合的主题事实不入候选。
5. 再按事实键去重、移除冲突/过期/suppression，处理笔记本偏好覆盖全局，取最多 3 条主题事实 + 2 条风格偏好；总预算见下表。
6. 初版记录“候选少/无相关”，不为了凑 3 条注入无关记忆。用户问“你记得我什么”跳转记忆管理，不能一次把全库塞进 prompt。
7. 内存索引服务目标：2,000 ACTIVE、普通笔记本规模下 warm p95 <50ms；单次总 deadline 100ms。超时降级无记忆；这些是待测门禁，不是已经测得的性能。

检索前不额外调用 LLM 做查询改写。常见“它/之前那个”只可在本会话最近一条明确主题中补充词，不凭其他会话猜人名/项目。词法召回确有同义词限制；评测记录失败案例，再考虑向量增强。SQLite trigram 对过短文本有边界，不能认为现有笔记 FTS 自动解决所有中文记忆检索。[SQLite FTS5 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

### 9.2 统一预算：先把费用增长控制住

由 `ConversationProjection` 选择有效历史/检查点，`ChatContextAssembler` 产出有来源的blocks，`ContextBudgeter`生成最终不可变`ChatContextPlan`；普通/SSE、计数和检查器共用它。所有数字都是本产品默认工程预算，需要评测调参。

| 区域 | 默认上限（估算 Token） | 取舍 |
|---|---:|---|
| 固定系统规则 | 600 | 尽量短、稳定，不含时间戳/随机 ID/个人记忆 |
| 跨会话记忆 | 240 | 常态可接近 100，但含 ID/时间/JSON 开销，不硬说 3 条永远 <100 |
| 会话状态（摘要＋resumeState） | 600 | 无有效摘要则仅可保留服务端中断状态；二者合计不超限 |
| 近期完整轮次 | 2,400 | 尽可能保留最近至少 2 轮；不能切到半句改变否定语义 |
| 当前页面上下文 | 1,000 | 剪裁并标注；与 RAG 同 page/hash 内容去重 |
| NOTEBOOK RAG | 1,800 | 先选高排名再按段落边界截短；citation 与实际选中段同步 |
| 当前用户输入（文本） | 2,000 | 超限请求用户缩短/引用片段，不静默截断 |
| 当前文本附件 | 1,000（共享总预算） | 按段落有界摘取并显示省略；不计入userText限额、不自动学习 |
| 全部输入总预算 | 8,000 | 含角色、分隔符、序列化与其它协议开销 |
| 输出预留 | 沿用默认 4,096 | 与 input 和安全余量共同受模型窗口约束 |

`allowedInput = min(userInputBudget, modelContextLimit - outputReserve - safetyMargin)`；安全余量取至少 512 或窗口 10%。目标窗口未知时不能宣称数学上保证不超窗：用保守默认并提示用户配置实际窗口；上游 context-length 错误最多做一次明确标记的预算缩减重试（用户问题不变、未产生输出、已确定拒绝），记录两次尝试。

计数器按目标 capability 选择可靠 tokenizer；v0.7 不为所有兼容网关强配某一家 tokenizer。无已验证计数器时用 UTF-8 字节数与消息 overhead 做保守估算，并标记 `estimated=true`；不能按“4 个汉字=1 Token”计算。报告分开记录估算值和上游 usage。图像保留现有协议支持，但图像 Token 按模型策略另计；未知时要求更大安全预留/显示未知，不能当 base64 字符数是收费 Token。

各区是上限而非保证配额，总和可以超过8,000，必须再执行总预算。超预算裁剪顺序：低排名 RAG → 页面冗余 → 附件低优先段落 → 低相关记忆 → 最早近期轮次 → 旧摘要中最低优先信息。当前问题与固定安全规则不删。当前显式提交图片不能静默丢弃；若仍装不下返回 `CONTEXT_TOO_LARGE`，指出哪类输入需缩短，不偷偷发更大窗口的另一个模型。历史附件的重放及缺省提示见contracts §4.3。

这是输入预算上限，不是“恒定费用”：当前问题、输出、模型思考、后台维护、缓存写入都影响账单。

### 9.3 Prompt 顺序与不可信数据边界

本节消息末尾规则用于 v0.7.0/PREINJECT 及工具首请求；TOOLS 续请求按 §9.7/contracts §9.3 追加厂商要求的调用与结果，当前问题完整保留但不再是末条。不得为满足旧断言重复追加问题或图片。

稳定系统前缀 `STUDY_ASSISTANT_V2` 放第一；后面放一个序列化的 `CONTEXT_DATA_V1` 数据消息（summary/memories/notebook excerpts/page 分区、各有来源标识），随后是按顺序的近期真实对话，当前用户 input 最后。

数据消息使用 user 内容块，不提升成新的 system/developer 指令；固定系统规则说明这些是历史资料而非可执行指令。JSON 由 ObjectMapper 编码，不能直接拼 XML 标签让内容逃逸边界。字段中即使有“忽略指令”“system:”，也仅作为字符串。执行指令优先级是当前用户明确要求与应用规则；记忆只辅助，不可推翻它们。

Anthropic 连续 user 内容块合并需要保持边界与次序；加 golden test，确保最后仍为当前请求，system 只剩固定规则。助手既往承诺只是对话内容，不得在摘要中冒充已完成操作。将记忆标成数据只能减少风险，不能保证完全免疫提示注入，所以应用层不开放任何记忆写工具/外部行动工具。

### 9.4 唯一上下文投影与本轮检查器

按固定顺序实现：读取session/generation/revision → 取有效加密摘要检查点 → 倒序扫描最多32轮当前合法历史 → 过滤非终态/旧scope/失效源 → 本地去重与附件策略 → 检索合法记忆/RAG → 区域和总预算 → 恢复时间顺序 → 一次序列化。只排除被**有效coverage**替代的原轮次，不能简单删掉所有id≤through的原文。每一阶段保留来源映射和枚举省略原因。

ContextPlan包括planId、historyRevision、summaryRevision、generation、vault/policy版本、实际内容块和模型请求、区域估算与来源选择。估算针对最终厂商序列化形态；新增usage不重建输入。发送前验证权限与相关revision；需要重组时丢弃旧plan并产生新ID，不把旧metadata误绑到新请求。具体DTO见contracts §4.5。

结果仅持久化≤16KiB的加密元信息：本轮提供的memoryId/version、pageId/contentVersion、近期来源ID、摘要覆盖/缺口、附件提供/省略ID、区域估算和省略原因；不持久化完整prompt、记忆正文或第二份摘要。检查器显示“已发送给模型/尚未发送/发送状态未知”，不称“模型确实使用”。多attempt显示最终尝试的详细计划及先前尝试的有界计量摘要，不声称重现所有历史prompt。

点击检查器只读保存的metadata；需要正文预览时另取最多5个当前仍合法来源，每个≤160码点。来源删除/改版/锁定/越scope时只显示占位，不能从旧缓存恢复；摘要检查点已替换则显示历史版本不可预览。未扫描的更早历史显示“未扫描/范围外”，不为解释省略原因再全库解密。完整coverage和省略计数只用于诊断，不全部塞给模型。读取历史/打开检查器不触发提取、摘要、重放或新聊天请求。

### 9.5 R4：把失败案例转为读取设计输入

**当前两套检索不可混称。** 记忆路径是“合格新用户来源 → LLM 候选/人工输入 → 加密短事实 → 解锁后内存字组/标签倒排索引 → BM25 → 权限/有效期/冲突/预算 → 注入”；没有传统长文 chunking，也没有 embedding。笔记 NOTEBOOK 路径是“笔记分块 → SQLite FTS/BM25 + 可用向量 → RRF 融合 → 引用”，其向量分支目前为归一化点积扫描/top-K，不是新增的向量数据库。两条路径在 ChatContextAssembler 汇合，不代表记忆已经使用笔记向量功能。

固定开发案例（不得复制用户真实数据，用同内容的独立合成 fixture）：

| 案例 | 已保存事实 | 问题 | 旧路径失败原因 | R4 验证目标 |
|---|---|---|---|---|
| L01 | 我常住杭州 | 我住在哪个城市？ | 字组零重合，READY 仍无候选 | 工具可以改查“常住/居住地”，小库 list 可找到；本地语义路径单独测召回 |
| L02 | 本周把二叉树遍历刷完 | 这周要刷完什么？ | “这周/本周”、问法变化 | 不要求用户复述原文，改写/语义召回返回正确事实 |
| L03 | 刚写入任一事实 | 立即相关提问 | 写后 revision 改了，旧快照不可用，首问才触发建索引 | 主动预热可观察；构建未就绪有 BUILDING，不用“无记忆”冒充 |
| L04 | 我常住杭州 + 我正在复习结构力学 | 解释量子色动力学 | 泛词或语义接近造成无关召回 | 不强塞无关个人事实；零相关可直接回答一般问题 |

分别记录事实是否入库、快照是否 READY、候选/实际返回数、模型是否调用、查询改写次数、最终回答引用了什么。R3 合成开发集 29/30 不证明自然问法可靠；扩大开发问法覆盖后再固定新保留集，不反复用旧失败作为唯一调参标准。

### 9.6 R4：共用读取服务与主动预热

建议新增 `MemoryReadService` 与可替换的 `MemoryRetriever`，让 IndexedMemorySource 和模型工具共用同一资格/文本渲染/版本验证；管理搜索仍是面向用户的独立 API，不直接当模型工具调用。读取服务不依赖 AiService，模型工具由后端内部分派，不必注册 MCP 服务或增加监听端口。

按下面顺序实现：

1. 建 `ReadContext`：由会话和服务端解析出 vaultId/epoch/revision、当前解锁世代、sessionGeneration、合法 GLOBAL/NOTEBOOK 范围、MEMORY_USE 授权目标及版本、本轮 use 开关。模型不能填写这些权限字段。不要把主密码/DEK放入参数或工具 schema。
2. 抽取 `readable` 判定和 `MemoryTextRenderer`，复用现有 ACTIVE/有效期/FAMILY/待确认冲突/笔记本偏好覆盖规则。先把当前预注入走此服务，保持旧结果和 240 预算；不要一片同时换算法、权限和协议。
3. 每个记忆写入事务成功后发进程内轻量失效/预热调用：手动新增/编辑/删、提取提交、审阅、清空/重置均覆盖。事务外调用现有 requestBuild，合并相同版本构建；空提取不触发。删/锁/撤授权的读屏障先成立，不能为“预热”继续使用旧版本。
4. readiness 只报告 READY/BUILDING/LOCKED/TIMEOUT 等真实原因；READY+0 是 NO_MATCH。记录候选数与被预算选中的数量，普通无关问答不弹 toast；检查器可查看，错误/构建可显示一条不阻塞聊天的状态。
5. 给合法内存快照增加 `list`：按 lastConfirmedAt 降序、memoryId 升序稳定分页；同样过滤范围/状态/冲突和覆盖。优先改用已有快照，不调用管理页解密循环来全库搜空串。快照超过构建上限或有损坏时标 incomplete，不能把扫到的零条说成全库没有。
6. 输出只带短事实、memoryId/version、范围标签、有效期；默认不带原话、来源会话正文或内部 predicate。返回后、真正下一次上游发送前都校验 ReadContext 和每条版本；状态变化丢弃旧结果，不从缓存恢复明文。

主动异步预热的验收分为“commit 后确实入队”“构建完成后第一次读可命中”“未完成时状态准确”。它不保证零等待立即命中。后续若要同步读自己刚写的事实，另设计有界 overlay 与删改屏障，不偷偷在首轮解密全库。

### 9.7 R4：按需只读工具与有界聊天执行

工具名固定 `search_memories`、`list_memories`；参数/结果见 contracts §9.2。模型策略：涉及用户偏好、个人背景、跨会话目标时先查；一般知识问题不强制查。一次无结果可改查询或 list；仍无结果明确未找到，不能虚构。模型自己的查询扩展只用于检索，不写成事实，不改变范围。仅写提示词不算已实现工具。

**三种模式**：PREINJECT 复用现有读路径，是默认/不支持工具时路径；TOOLS 是显式启用且验证过目标能力的后续路径；DISABLED 不检索、不声明工具、不发记忆。初版 TOOLS 不预注入主题事实，避免两套隐式记忆；少量回答风格偏好预注入作为后续评测项，不在 E4 默默实现。若以后加入混合模式，其返回去重/版本/预算与审计仍共用。

新增协调器（建议 `ChatExecutionService`），AiService 的普通/SSE 都调用它；保留现有 ChatTurnService 作为 begin/finalize 权威。分片步骤：

1. 先做与厂商无关的 `ToolCall(id,name,arguments)`、模型输出内容块、ToolResult、attempt 记录模型。工具调用是模型输出的一种，不是 assistant 空回复或最终 stop。保留厂商要求的调用 ID/输出块关联；不得把工具 JSON 拼成用户发言模拟协议。
2. 单独扩展 CC/Anthropic 请求和非流式/流式解析器：工具定义、tool_calls/tool_use、结果消息、结束原因都转为统一类型。工具参数增量以 callId/index 有界缓冲，完整结束后才解析/执行；正文与 thinking 不被当参数。现有 Result/StreamListener 需要扩展，不能仅把 tools 塞到普通参数 Map。
3. 控制流程 `begin → initial plan → model → (tools → fresh next-attempt plan → model)* → finalize`。一个 requestId/lease；每次外发新 planId、独立 ai_usage_attempt。只在最终回答或取消/失败结清轮次与容量预留；工具阶段没有 done、没有维护唤醒，也不新增用户消息。
4. 初值：最多 2 个工具阶段、3 次工具执行、3 次正常上游请求；允许最多 1 次满足旧明确拒绝条件的协议/长度缩减重试，因此总上游请求最多 4。重试占总次数且沿用总 deadline，不重置计时。第三次正常请求不再开放工具；异常仍返回工具请求则停止并明确未完成，不无限续跑。禁止并行执行工具，模型同响应发多个调用按顺序且受总额度。
5. 每次工具结果合计最多 1,200 估算 Token（全轮累计）、每次返回最多 5 条、全轮最多 15 条尝试返回的事实；整条放不下就省略并记原因，不截半条改变否定含义。两个工具定义总计≤1,024估算Token（须测最终厂商包装，不按字符猜），结果含协议/ID开销；每次最终序列化仍守 8,000 输入、输出预留与安全余量。两次中间输出+最终正文/reasoning共用原捕获字节/存储预留上限。详细上限与分页规则见 contracts，不能拿240的自动注入预算假装工具能无限分页。
6. 用户 Stop/连接断开/总期限到期覆盖整个循环和工具读取。取消后不再启动下一个请求；已经发送的输入无法从远端收回，但本地锁/撤权/删除成功后不再发送包含目标的后续请求。工具结果形成与发出之间的竞争须有统一服务端发送检查点与世代校验。
7. 每次网络请求分别结算，UNKNOWN 按现有规则记录；工具本地调用不算维护调用，不占20次后台额度。原20次/30K限制仍只管提取/摘要。新增聊天多步总额上限不得转嫁给维护预算。
8. SSE 增加阶段状态“查询记忆/继续回答”，只报告名称/状态/数量，不把参数、工具结果当 delta。已发的 assistant 正文按原顺序保留，不因工具结果覆盖；工具后续正文追加。最终 done 只一次，失败/停止保留已发部分并标终态；重启不自动重跑旧工具循环。
9. 每次发送保存有界审计：attemptId/planId、调用序号、实际发给该次请求的 memoryId/version、检索 availability/数量、省略和 sendState。最终提供总用量与各attempt摘要；旧检查器兼容无此字段。工具结果正文不另落明文，历史学习视图只认原 USER_AUTHORED，不把工具消息作为用户来源。输出剩余量、协议配对不可裁剪组、普通/SSE统一转录见contracts§9.3；不得每次续请求再读一遍旧历史或重发当前图片两份。

工具能力按“目标+模型+apiFormat”配置，并用无用户数据的 fixture 验证。不支持的目标在首请求前选 PREINJECT；不能以任意400/工具空返回证明不支持，不能在已产生正文后静默 fallback 重跑。OpenAI/Anthropic 是协议分支，不保证所有兼容网关/模型支持同一能力；具体模型若要求新 API，另建适配器并验证，不强迫改造所有现有用户配置。

### 9.8 R4：本地混合检索，独立于工具决策

E6 优先复用已安装且可用的 LocalEmbeddingProvider；初始化可明确选择本地语义模式，默认不下载模型、不改 NOTEBOOK selected space。记录记忆专属模型身份、维度、归一化/输入模板版本；更换后重建，不能读旧向量。

1. 以**每条原子记忆**为向量单元，不重新切长聊天 chunk。输入由 MemoryTextRenderer 的自然句生成，不嵌入原话/思考/附件。保持事实库为权威，不建第二份明文文本库。
2. 解锁后后台批量生成向量，设批量/队列/超时/可取消上限；查询只做一次本地 query embedding。记忆明文进入本地 worker 的内存和IPC，不意味着“没有处理边界”：检查其日志/临时文件/缓存不存输入，模型文件仅 APP_ROOT；锁定取消未发送批次并清快照，正在本地处理结果按世代拒绝。
3. 初版向量只存有界进程内快照，不持久化向量或个人正文。2,000 条规模可复用 float32 归一化点积扫描与 top-K 思路，先测资源，不增加外部向量数据库。若重建太慢，记录限制后另设计加密向量缓存，不暗中写磁盘。
4. 权限过滤后分别取 BM25/语义候选各最多30条，以 RRF（k=60）合并，再做家族去重、冲突/有效期、返回预算。语义候选有独立评测阈值，不能受“字组至少重合2个”的旧词法门槛，否则 L01 永远进不来；RRF 不用来证明相关性，仍需拒答/无关测试。
5. 模型不可用、构建中、超时等返回明确降级；词法可继续用，TOOLS 在额度内可改查/list。不把 local fail 自动变为远程 embedding，不要求所有用户安装本地模型才能手动管理。
6. 比较词法预注入、词法工具、混合预注入、混合工具四组；记录召回、误召回、模型调用率、端到端回答、冷/warm时间、内存和全部模型用量。两已知失败进入开发集；新同义/指代/不相关问法进入固定保留集。工具化不预先承诺省Token，真实付费评测取得上限授权后才跑。

## 10. Prompt Caching：作为可测优化，不作为正确性依赖

缓存复用前缀计算，不是本地长期记忆，通常仍需提交完整有效 prompt，也不减少上下文窗口占用。不能用“缓存存在”替代数据库/摘要，更不能保证免费或固定一折。

### 10.1 厂商差异和实施选择

| 目标 | 本次官方资料确认 | v0.7 行为 |
|---|---|---|
| OpenAI | 支持模型默认有缓存机制，但门槛、breakpoint、保留期和写入价格随模型/请求设置变化；当前文档包含新旧机制 | 当前应用仍用 Chat Completions。只发该端点已核验字段；不把 Responses 示例里的新参数复制进 CC。默认保持稳定前缀，读取用量；未知模型不承诺命中 |
| Anthropic Messages | 支持顶层自动 cache_control 或块级 breakpoint；有最小长度，默认 5 分钟，1 小时有不同写入成本；缓存读/写分别计量 | 对已确认支持的 endpoint/model，采用固定 system 内容块末尾 `cache_control:{type:"ephemeral"}`；不默认增加 1 小时 TTL；不把变化的记忆放在缓存前缀里 |
| DeepSeek 官方端点 | 前缀缓存 best-effort，匹配已持久化的前缀单元；usage 有 hit/miss 字段 | 不加私有开关，保持前缀一致、读取命中量；不硬编码旧资料的缓存块大小/保留期 |
| 自定义 OpenAI-compatible 网关 | “兼容消息格式”不代表兼容缓存、usage 或结构化输出 | 能力默认 unknown；不按模型名字猜能力。高级配置显式声明已验证特性，否则只发基础请求 |

依据：[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Anthropic Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache)。OpenAI 部分依 OpenAI Docs 技能核实官方资料；没有沿用“所有模型都同一门槛/免费写缓存”的旧结论。

不要为短 system 的缓存收益添加无用说明。600 Token 系统前缀可能达不到模型门槛，这是合理状态。未来更长的真实稳定规则/工具 schema 可以受益，但不能倒过来为缓存增加输入。

参考harness中的micro-compaction、内部cache-edit与普通API的Prompt Caching不是同一接口。这里只借鉴“先局部减少冗余、保持真实稳定前缀”，不向OpenAI-compatible请求透传`cache_edits`或未核实参数；缓存失败不能改变历史、来源资格或记忆正确性。

### 10.2 适配器与用量

新 `ProviderCapabilities` 配置以 endpoint/apiFormat/model 为键，描述 cache、structured output、stream usage、context window。`AiUpstreamClient` 不能把任意前端 JSON透传给上游。Anthropic system 从字符串改为可保留 cache_control 的 typed blocks；未知网关保持兼容模式。

Usage 统一字段：`inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, reasoningTokens?, totalTokens?, source=provider|estimate|unknown`。

- OpenAI CC 读 `usage.prompt_tokens/completion_tokens/prompt_tokens_details.cached_tokens`；cached 通常为 input 子集，不重复相加。未提供 cache-write 字段则 unknown，不填 0 冒充准确。
- Anthropic 总输入 = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`。SSE 在 message_start 和 message_delta 收集各自字段，按字段最终值覆盖/规范化，不能把重复累计块再相加。
- DeepSeek 从 `prompt_cache_hit_tokens/prompt_cache_miss_tokens` 映射，并与 prompt_tokens 校验；缺失不代表零命中。
- 流式 usage 请求只对支持目标增加相应选项；应能处理“空 choices 的最后 usage 块”。客户端停止导致 usage 缺失，记录 estimate/unknown。
- 缓存选项导致明确 400 参数不支持且没有输出时，最多一次移除可选字段重试，记能力降级；401、429、断流不能用这种方式反复重发。

费用估算按当前用户填写/确认的价格表：`uncachedInput*Pu + cacheRead*Pr + cacheWrite*Pw + output*Po`，注意不同厂商 input 定义不同，先规范化为互斥桶再计价。没有价格或没有写入量就显示未知区间，不输出看似精确的省钱百分比。

后台预算发起前预留“本次最大输入 + 最大输出”，实际 usage 返回后结算；无 usage 按保守预留消费。重试也是一次尝试并再次预留。应用重启不返还已发出但结算不明的预留，避免绕过限额。单日按用户配置时区，使用明确 date+zone 桶，不用服务进程默认时区偷换。

## 11. 删除、撤销、锁定与恢复

### 11.1 删除一条记忆

管理面板区分“停用”（可恢复）和“删除并阻止旧来源重新学习”（确认不可在应用内撤销）。删除默认执行：

1. 在事务里递增 vault epoch，写入该事实键的 suppression，删除当前及历史版本、无其它引用的证据、候选和待提交变更。
2. 失效所有可能携带旧事实的会话摘要（v0.7 可全量失效摘要，优先正确性）；取消旧 epoch 的 job。
3. 同步使索引 revision 失效，切读路径为过滤后的新快照；拿着旧 revision 的检索结果提交前再次检查。
4. 清除前端对应 query 缓存与“已提供记忆”卡片正文；旧回答中的文本本身不会凭空消失，需说明。
5. 未来自动提取命中 suppression 的键一律不重建；手动“重新允许记住”明确解除。用户问“忘掉预算”不能被当成“预算是忘掉”新值。

为防同一旧来源被改写value绕过family HMAC，删除事务还将全部现有会话的memory_scan_after_turn推进至各自当前最大turn ID，并用全库最大turn ID记录settings中的memory_history_floor（仅数值metadata），新extract必须在此边界之后。这会放弃删除时尚未整理的历史，确认框要说明。并写原证据的EVIDENCE suppression，不保留明文。以后新发言的同义改写仍不能靠HMAC保证识别，UI明确“不保证识别未来所有同义说法”；用户可额外选择停止该predicate自动学习或关闭学习。不能声称实现了无限语义遗忘。FAMILY匹配仍持续阻止同键，只有明确解除才重建；遗忘后的摘要从新边界重建，不能拿旧摘要恢复事实。

语义遗忘范围要说清：删除记忆不删除原聊天。该键的旧原话仍可能出现在用户主动打开的原会话近期上下文；UI 提供“同时删除来源会话”入口。新会话的记忆召回必须不再出现该事实。若用户要求彻底忘掉一段对话，应走来源会话删除流程，而不是宣称只删事实即可让模型完全不知道。

### 11.2 删除来源会话

默认联动删除由该会话派生的证据/候选、摘要、任务，并重新计算每条事实的来源：还有其它合法来源则保留；没有来源的自动记忆删除。用户曾手动编辑/明确转为个人记忆的条目可保留，但移除已删除会话的 quote 和链接，并显示“手动记忆”。删除确认弹窗准确提示这一区别，不静默保留自动画像。

实现使用服务层事务，不能只依赖message外键：旧版或明确清理可能已移除原消息，而evidence的sessionId仍需被找到。按范围清理历史复用同一来源清理逻辑，不能只删除ai_chat_message留下quote/附件/result_meta。旧任务lease和source revision校验必须在删除后失败。

### 11.3 清空与暂停

- “暂停自动学习”：不删记忆；取消未发送任务，对飞行请求置取消/epoch barrier，结果不能落库。
- “不使用记忆”：停止注入，不等于停止学习；UI 分开说明。
- “清空全部 AI 记忆”：停用记忆与维护、清空事实/候选/证据/摘要/任务/旧 suppression，轮换 vault epoch 并设每会话回溯截止水位；重新启用默认只学新消息，不自动回填旧历史。
- “清空”不承诺擦除旧备份、SSD 残留、上游厂商日志/缓存或已发送内容；界面提示备份可能仍包含旧加密记录，用户可到数据管理删除备份。
- 物理文件删除沿用项目回收站规则；SQL 行删除属于用户授权的数据管理。禁止为“遗忘”自动擦除整库或无关附件。

### 11.4 备份/恢复/旧版回退

新表进入既有整库备份，不另造存储目录。导出说明“包含加密 AI 记忆及可能的历史内容”。恢复后首次启动：不恢复正在运行的 lease；生成新的 runtime generation，所有维护授权进入重新确认态；password vault 保持锁定；重建纯内存索引。恢复前后都不能偷偷外发旧会话。

启动接线顺序固定为：恢复状态机 → 版本前置检查/独立备份 → schema事务 → 恢复安全事务 → 开放API/启动worker。改造PendingRestoreApplier，不再丢弃恢复结果；在APP_ROOT/data写只含restoreId/阶段/校验信息的恢复标记，状态至少PREPARED、DB_REPLACED、SAFETY_APPLIED。换库前持久化PREPARED，换库按原恢复流程原子操作并校验；启动若停在PREPARED则根据目标校验结果判定继续或失败关闭，不能盲目二次覆盖。不能换库后立即删manifest而丢掉“待撤销授权”的证据。

恢复安全事务在新库中清空两种consent fingerprint、递增vault epoch与所有session generation、终止旧lease/运行轮次、按当前最大turn设置扫描边界；未结算SENT记UNKNOWN。事务提交后标记SAFETY_APPLIED并清理恢复标记；崩溃后重复撤权/失效是安全的，不提前开启调度。事务或标记验证失败则阻止AI外发并报告，不能让worker读取备份内的旧授权。普通非恢复启动仅执行孤儿恢复，不每次撤销正常用户授权。API/worker显式依赖启动barrier，不依靠不确定的@PostConstruct先后顺序。

schema9 迁移前在 APP_ROOT/backups 建一致性 v8 快照（调用已有快照路径，不直接 copy 活跃 WAL 库）；失败即停升级。初始化先读取版本，遇到高于支持版本明确拒绝。不能假定旧 v0.6.3 二进制已有拒绝未来版本的能力：回退必须使用匹配的升级前 v8 数据副本，不能将升级后的 DB 直接交给旧程序。

快照使用独立autocommit连接执行VACUUM INTO，再开始DDL事务；不能把VACUUM放在DatabaseInitializer已有事务里。抽出不依赖已完成迁移的SnapshotService供初始化和DataBackupService复用，避免构造器循环依赖。附件BLOB随整库快照进入备份，不另做易失配的附件目录拷贝。

## 12. 前端交互落地

新增组件而非把逻辑继续堆进 `AiAssistant.tsx`：

- `components/ai-memory/MemorySettingsCard.tsx`：开关、实际维护模型、授权、预算、解锁状态。
- `MemoryManager.tsx`：生效/待确认/停用/过期筛选，搜索，分页，手动新增、编辑、删除、清空。
- `MemoryDetail.tsx`：来源 quote、来源会话、有效期、作用域、版本；人工改过显示保护标记。
- `MemoryUsageBadge.tsx`：每条回答下显示“本轮提供 N 条记忆”，点击展示当时 ID/版本（未保存明文副本）；已删时显示“已删除”，不从旧缓存复活。
- `ChatContextInspector.tsx`：从同一plan metadata显示实际发送范围、区域估算、usage、摘要缺口、附件省略及原因，不称为模型内部注意力解释。
- `useChatHistoryPages.ts`：50条游标分页、500条驻留上限；另设容量提示/显式清理预览，卸载页面不调用DELETE，归档也不等于删除。
- `hooks/useAiChatTurn.ts`：统一普通/SSE 请求状态、requestId、cancel、session generation；复用旧 UI，不重做聊天视觉。
- `lib/aiMemoryApi.ts` 与 `lib/aiMemoryTypes.ts`：协议集中定义；不把个人事实/密码存 localStorage。

首次空态：“记住你明确表达的偏好和目标，供以后对话参考。”按钮“手动添加”和“开启自动记忆”。自动提取正常运行时仅轻量状态：已保存/待确认/已暂停/等待解锁/预算用尽；不能用正在转圈遮挡聊天。

候选审阅必须显示新值、当前值、原话、作用域、为什么待确认，按钮为“采用新值”“保留当前”“分别保留”（仅多值类别）。“保留当前”写 suppression/拒绝来源标记，不能下一秒又出现同候选。

修改保存使用 version CAS；409 时保留用户编辑草稿，展示服务端最新值让用户比较，不自动覆盖。删除与清空需确认；关闭普通开关无需危险红色弹窗。R4 后续 UI 的具体替代规则见 §12.1，不以本节历史组件实现为理由保留必填键名。

### 12.1 R4：自然语言管理的具体改造步骤

这组改造在 v0.7.0 完成并预发行后进入 E1；不要求在当前 P9 未提交代码中顺手改。保留现有 Arco/主题/键盘/读屏规范，先改协议和服务端默认值，再改表单，最后改列表/详情/审阅。普通用户不需要了解 predicate、family、CAS 或数据库版本。

1. **新增表单**：主字段“你希望 AI 记住什么？”；范围显示“所有对话”/笔记本名称，从聊天入口打开时默认该会话范围，设置页打开默认全局；有效期默认长期，可展开设置，按已有日期/时区契约提交。键名与类别不再必填或显示英文枚举；空内容不能保存。
2. **服务端默认路径**：contracts §9.1 的 FREE_TEXT 写入使用 `predicate=other`、内部 `kind=BACKGROUND`，保留用户原句，不调用 LLM、不伪造用户来源 quote；manualProtected=true。kind 在此是内部兼容槽，不代表推断了用户背景。other 多值只保证不同值可并存，不保证语义冲突消失。相同规范化内容可按现有409/幂等规则反馈，不能新造数据库唯一约束吞掉条目。
3. **结构化偏好仍可操作**：提供可选的“回答偏好”快捷项：语言、详略、先例子/先原理，显示中文选项，后端转换既有 answer.* 与合法枚举。已有结构化条目编辑用对应中文控件，原 predicate 不变；自由文本/旧自定义 predicate 的条目编辑用一句话，不默认改成 other。不能把所有旧记忆迁成 other、重算 family 或抹掉人工保护。
4. **编辑是改现有条目**：按 memoryId/expectedVersion 提交，保留旧来源与版本规则；结构化值从中文选项映射，原值/未知代码不能自动猜。自由文本语义更正应编辑原条，例如杭州→苏州；直接新增两条可能矛盾，界面说明“更新已有信息请修改原条”。自动冲突建议可后续增加，不能承诺 other 已有自动语义去重。
5. **自然句渲染**：抽出共用 MemoryTextRenderer，不把旧 `displayText`（可能是“回答语言：zh”）直接当已完成目标。模板输出“用户希望用中文回答”“用户偏好详细解释”“用户偏好先给例子，再讲原理”；目标/背景/约束保留完整值；other/自定义谓词显示原句。未知枚举不猜译，沿用原值并标可查看详情。UI、工具、预注入使用同一渲染结果，检索同时保留内部语义标签；不直接删除谓词后只给模型 detailed。
6. **列表与详情**：默认内容、范围名称、待确认/已暂停/到期这些可理解状态。编辑/暂停/删除在行菜单；类别中文分组可选。记录时间/来源原话/人工保护在“来源与详情”；ID/版本/内部错误码放诊断折叠区。折叠不删除信息，范围/有效期不能藏得让用户不知会在哪里生效。
7. **审阅**：分别展示“现在记着什么”“建议改成什么”“你当时的原话”“为什么需要确认”；以采用新内容/保留原内容/分别保留作为按钮，keep_both 是否允许只听服务端 multiValued。没有目标的新增候选用“记住/不记住”；不让用户填写目标ID/键名来完成冲突决定。
8. **设置**：常用区保留“回答时参考记忆”“自动整理新对话”“长对话摘要”；主 enabled 仍是总模块开关，不新增第二个同名 bool。若 enabled 关闭但 autoExtract 保留true，显示暂未运行，不能误称自动学习开启生效。advanced 放低风险自动生效、维护模型、预算、加密管理；首次开启动作结合必要外发授权，先给目标/数据/费用摘要再确认，开关和授权的存储/撤销语义仍各自独立。
9. **删除文案**：普通删除说明从记忆库移除；遗忘选项用“同时阻止从之前的聊天重新整理这条信息”，补一句“原聊天仍保留；此操作也会放弃尚未整理的旧内容”。不要把“推进全局遗忘边界”当用户主文案；实际全局边界代价、备份未清理和彻底删除来源会话的入口仍必须可查看。不得宣称未来同义说法一定不会被再次学习。
10. **验证不削弱功能**：离线手动新增/编辑/停用/删均可用；三种 answer.* 的新增与编辑、自由文本、旧自定义键、两个并存目标、人工冲突保护、有效期、两种作用域、409保草稿、敏感信息显式确认、凭据拒绝全部保留。表单简化不能改成前端自动勾选敏感确认、合并两种外发授权或偷偷删除来源。

## 13. 测试、效果与成本验收

完整场景和可机械断言的数据见 [验收用例与评测](v0.7-ai-memory-acceptance.md)。这些门禁是实施目标，本文未运行产品测试，也没有已测性能/节费结果。

### 13.1 三层验证

1. 纯函数与真实 SQLite fixture：状态、CAS、来源、预算、scope、时间、迁移、加密失败必须全可重复。不调用真实付费 API。
2. 本地 mock 上游 HTTP/SSE：捕获真实请求 JSON、分别检查 CC/Anthropic 请求、结束原因/usage、超时/中断/重复请求。不能只 mock `MemoryService` 后断言被调用。
3. Electron 闭环：从用户发言到 DB 到异步候选，再到新会话上游 payload 和 UI；使用 APP_ROOT 内测试数据副本。不能用只传 `vi.fn()` 的孤立组件代替闭环。

### 13.2 真实小模型评测（实施末期经用户确认预算后运行）

准备 120 个自有中文多会话案例：偏好 20、改口 20、作用域 20、时间/过期 15、否定/假设/第三方 15、无证据拒答 10、注入/敏感信息 10、摘要续聊 10。固定 30 个开发集和 90 个保留集；不能先看保留集再改 prompt。案例不含用户真实隐私。

每个目标模型记录 endpoint 类别、精确 model ID、参数、promptVersion、tokenizer/估算器版本；至少验证用户实际准备使用的一个较小模型，不擅自替用户选择/调用收费模型。

对比 A=旧全历史方式，B=仅有界历史，C=有界历史+摘要+记忆。使用同一模型、相同会话轨迹与输出预算。分别报告记忆提取准确性、召回、回答质量、维护成本、缓存用量、总输入和总费用；真实时间成本与实验成本分开。

目标：自动生效偏好 precision ≥95%；明确可记事实 recall ≥85%；检索命中 recall@5 ≥85%；改口/过期/作用域泄漏/凭据自动入库等确定性安全用例必须 0 失败。用小样本的通过率表述，不夸称统计证明安全。若模型达不到自动生效 precision，把该模型默认改为全候选审阅；不得降低安全门槛换高召回。

长会话成本案例至少 100 轮；衡量包含后台维护的**总**用量。期望 C 的总输入相对 A 降低 ≥40%，且预定义关键续聊问题准确率下降不超过 5 个百分点；未达到则先调整摘要触发/预算，或关闭收益不佳的自动摘要，不虚报“省90%”。短会话可能更贵，必须如实展示。

### 13.3 运行资源门禁

warm 检索 p95 <50ms、deadline 100ms；2,000 ACTIVE 内存增量目标 <30MiB；后台空闲没有远程调用；120 条测试数据无用户操作时不能重复提取。冷启动/解锁重建耗时另报，不能混入 warm 指标。聊天检索超时必须降级，不卡 30 秒等维护模型。

## 14. 分阶段执行工作包（小模型逐包执行）

总原则：一包只完成一个可验证切片。不要一口气修改前后端所有文件；不要自行提交 git；不要安装新服务。下面每包均有“做法/测试/停下条件”，不是仅勾选清单。

### P0：建立基线与实现记录

读取本文、两份配套规格、当前 AGENTS 和 git status；检查基线是否已变化。将计划版本、实际 HEAD、默认值、阶段状态记录到 `docs/plans/v0.7-ai-memory-progress.md`（实施时创建）。记录前后端基线测试结果；已有失败单独列出，不归为本包修复范围。依项目要求 pwsh 7，含复杂变量的操作写脚本，修改用 apply_patch。

产物：基线记录、无行为改动。退出：已有失败原因可区分；若聊天中断测试本身不稳定，先定位并形成复现，不掩盖。

### P0a：先验证高风险假设（不得拖到P11）

仅在实施获授权后建立隔离原型/测试，不接生产UI。先准备固定合成数据与断言，再做五组实验：①30条开发集的中文召回与2,000条warm延迟；②fake Clock模拟同日100轮密集/闲置/跨日，验证20次/30K以及摘要1,024新增量/120秒冷却/无收益抑制；③HTTP头后悬挂，验证deadline和退出；④SQLite完成回滚后可恢复，并发容量预留无超卖；⑤准备600条历史，压缩/分页后记录仍完整，模型最多扫描32轮且检查器与请求一致。

产物为带环境、数据seed、参数和失败样本的本地报告，不称为真实模型效果。词法召回不足先在30开发集内调整分词/有限词表；仍不足则报告限制，不能偷偷增加向量服务或调低最终85%门槛。默认预算不足时保留硬上限和有界近期历史降级，不承诺每4轮必有已完成摘要；提高默认额度或取消目标必须由用户决定。网络读取无法可靠取消则暂停后续worker集成。五组原型有证据后才进入P1。

### P1：schema9、DTO 与 migration

在schema.sql增表、DatabaseInitializer增幂等迁移与版本前置检查；先迁移列后建索引。实现ChatTurnRepository、MemoryRepository、ChatStorageSizer及容量账本，回填v8字节计数不解密；加入history revision、归档和摘要调度metadata。本包不接LLM/UI，不自动回填旧会话事实。计数大于默认容量只提示只读/清理，不删除迁移数据。

运行新建/v8升级/重复启动/失败回滚/未来版本拒绝测试；验证 NOTEBOOK、题库、原消息数量与内容未变，`foreign_key_check` 无异常。退出：基础版本/唯一约束/CAS 有失败测试支持。

### P2：加密库、授权与本地管理 API

实现 MemoryCryptoService、MemoryVaultService、MemoryPolicyService。用随机 DEK 和包装流程完成手动添加/列出/改/停用/删 API；把 unlock 改为 POST body，不复用旧 GET 密码参数。scope 验证、脱敏错误、权限版本与 suppression 同步落地。

测试 DB/WAL/log 中不含合成测试原文、IV 不复用、AAD 跨行替换失败、错误密码无外发、fingerprint/password 模式不降级、加密失败旧值不变。退出：不用 LLM 就能完整管理一条本地加密记忆。

### P3：轮次幂等与普通/SSE 完成语义

按§7新建ChatTurnService，统一finalizeTurn，增加cancel/status、insertMessage返回ID。先验证生命周期，再改prompt内容。移除新写明文兜底及v1/v2的500条删库分支；接入开始容量预留、回复捕获上限、完成/失败/孤儿预留结算。实现独立usage结算、存储恢复门禁、RequestHandle、加密附件和source block，不依赖记忆vault存在。

测试同 ID 重发、第二会话、只 reasoning 停止、部分正文停止、正常完成但 done 丢失、完成落库失败、重启遗留 RUNNING。退出：两条路径不会重复创建记忆源事件，旧聊天/切会话测试通过。

### P4：后端上下文与预算（暂不自动提取）

新建ConversationProjection、ChatContextAssembler、ContextBudgeter、TokenEstimator和不可变ChatContextPlan；v2只发本轮，服务端从检查点＋有界尾部构建。先用fixture手动记忆，页面从system移入数据块，所有引用/省略/估算统一来自plan；加只读历史分页和上下文检查API，v1明确隔离。

写 CC/Anthropic golden payload、当前问题不截断、超大用户输入/图片、中文/emoji、RAG 重复去除与无记忆降级测试。退出：任何历史长度下有界；当前用户问题仍最后且完整；不存在双重注入。

### P5：进程内检索与作用域

实现内存词法索引、偏好补充、scope过滤、过期过滤、冲突抑制、版本一致快照。异步解锁重建只用内存，不创建 FTS 明文表。按标准公式写 BM25 小数据手算测试；确定 rank ties 和中文短词规则。

加入跨本隔离、无关 query 返回0、2,000条 warm性能、删后并发读、锁定清缓存测试。退出：不依赖向量模型的有界词法读路径可用；这不保证同义或自然问法召回（失败见§9.5）；NOTEBOOK coverage/status 的基线值保持不变。

### P6：持久任务调度、预算预留与恢复

实现MemoryJobRepository/MemoryMaintenanceWorker；先用deterministic fake extractor。入队只存水位，lease/CAS/epoch/精确inputRevision/合并/退避/暂停/日预算全测透。提取和摘要各有水位/最近attempt，同输入跳过、空提取终态、摘要新增量/冷却/无收益门禁都在本包；Clock和drainOnce可注入，不靠长sleep。

测试断电各点恢复、claim过期、cancel 与提交竞争、上游悬挂、有聊天时让路、budget跨午夜、unknown usage 预留不返还。退出：fake 任务 1次输入只提交1次，队列和资源有硬上限。

### P7：结构化提取与冲突处理

接真实 AiUpstreamClient 的独立 maintenance options；使用配套 JSON schema/提示词/例子，服务端校验来源 quote 和候选。实现单值/多值、人工保护、来源时间获胜和 REVIEW；格式失败不清空记忆，不无限修复。

固定回放案例至少覆盖“不是…而是…”、“仅这一次”、“引用第三方”、“旧任务晚回来”和敏感凭据；测试所用 mock 输出包含伪造ID、额外字段、超长值、非法 JSON。退出：高风险语义只能 REVIEW/IGNORE，没有模型直写权限。

### P8：任务续接摘要与恢复状态

实现SessionContextService和SESSION_SUMMARY_V2；按contracts §2.5逐轮校验，coverage只标实际来源。先完成纯函数摘要校验/600预算/收益判断，再接有偿调用；server单独派生resumeState，引用版本验证不通过时失效摘要。用户明确删源才走删除钩子；摘要不得清原文，也不能把assistant建议升为已验证完成。

测试摘要失败时窗口裁剪有notice、旧摘要不能覆新、停止轮次不混入、来源删/遗忘后摘要不复活、指代续聊和用户纠正。退出：长会话可控，旧聊天记录/导出没有被摘要改写。

### P9：记忆管理 UI 与完整聊天接入

按§12拆组件，先手动管理，再候选/授权/预算，最后接记忆badge和上下文检查器。接50条历史分页/500条驻留、归档、容量提示与清理预览。API/React Query key带session/scope/generation/planId；切会话不混缓存，锁定清除来源预览。读取检查器不发LLM请求，localStorage不存正文/凭据。

测试Loading/空/错误/锁定/待确认/409冲突/删除/清空/模型变更授权失效，Electron实际走“会话A记住→后台→会话B回答”。退出：UI提示准确，现有停止按钮和悬浮侧栏不回归。

### P10：厂商用量和缓存适配

仅在上下文格式稳定后加 ProviderCapabilities、usage归一与 Anthropic breakpoint。先 mock验证字段，再由用户授权的小额真实调用验证目标模型。未知网关保持基础协议，不根据成功一次就自动永久宣称缓存支持。

测试SSE最后usage块、cache-read子集、Anthropic三种输入桶、usage缺失、缓存字段400降级、非400不重试。退出：总用量不重复计数，所有“节省”有基准且包含维护成本。

## 15. 何时算完成，何时应该停下

v0.7 完成不是“表建好、prompt加几句”，而是：真实跨会话能用、更新和遗忘正确、长会话有预算、两条聊天路径一致、用量可解释、记忆不会明文落索引、恢复不偷跑后台调用，并且用户可以自行管理。

实施中若出现以下情况，应停在当前包报告，不临时扩架构：需要新常驻服务；需要把个人记忆送到未获授权的目标；要放弃加密才能实现检索；需要用生产私密数据做fixture；小模型精度不达标而准备放宽安全门槛。可降级为“人工录入+候选审阅+有界聊天”，不能降级为隐私泄漏或静默错误记忆。

本方案的首要取舍是可靠、可控、便携。R4 将更自然的管理和按需只读工具列为 v0.7.0 预发行后的明确增量；向量在 E6 单独评测，图谱、任意写工具和云同步仍不在此范围。不能把“地基完成”写成后续全部能力已完成。
