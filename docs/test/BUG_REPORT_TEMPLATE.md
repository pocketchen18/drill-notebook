# Bug 提报与复现规范 (Bug Report Template)

当测试人员或用户在测试过程中发现缺陷时，须按照本规范进行记录与提报。

---

## 一、 Bug 提报模板

```markdown
### 1. 基本信息
- **Bug 标题**: [模块名] 简明扼要描述问题现象（例如：[知识点] 全屏状态下删除卡片后工作区未重置）
- **严重等级**: P0 (阻塞/崩溃/数据损坏) / P1 (核心功能异常) / P2 (一般体验/样式错位) / P3 (轻微建议)
- **发现环境**:
  - 操作系统: Windows 10/11 / macOS / Linux
  - 运行模式: Electron 客户端 / Web 浏览器端
  - 应用版本 / Commit Hash: 

### 2. 前置条件与测试数据
- 所选题库 / 知识库名称:
- 测试所用的 Markdown 文件或数据样例（如有请附带文本代码块）:

### 3. 复现步骤 (Reproduction Steps)
1. 进入「知识点」页面，选择题库 XXX
2. 点击右上角「全屏」按钮进入全屏阅读
3. 点击大纲树上的某一子节点
4. 点击「删除」按钮并在确认弹窗中点击「确定」

### 4. 预期结果 (Expected Behavior)
- 知识点删除成功，大纲树对应节点移除，右侧/主体区域切换到下一个知识点或展示空提示。

### 5. 实际结果 (Actual Behavior)
- 提示删除成功，但工作区仍然残留已删除卡片的内容，点击上下页报错。

### 6. 错误证据 (Screenshots / Logs)
- 浏览器控制台 / 后端 logs/backend.log 报错日志（附 Stack Trace）
- 截图 / 录屏附件
```

---

## 二、 修复与验证规范（闭环铁律）

1. **先写复现单测**：
   - 开发人员在修复此 Bug 时，必须在对应的 `*.test.ts` 或 `*Test.java` 中增加一个针对该场景的单元/组件测试，确保测试在未修复前必然报错（Red）。
2. **修复并回归验证**：
   - 修改业务代码使该单测变绿（Green）。
   - 运行项目全量测试套件（`npm test` 与 `mvn test`）确保无连带回归问题。
3. **QA 验收关闭**：
   - QA 人员依据 Bug 报告中的复现步骤在实际应用中重新验证通过后，方可关闭该 Bug。
