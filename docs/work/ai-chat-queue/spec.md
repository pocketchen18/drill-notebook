# 人工排队与插话实现规格

2026-11-09。依据已确认的 [UI/UX](ui-ux.md)，仅覆盖当前纵向切片。

## 存储与身份

- 复用 `SessionDispatchService` 的后台运行、会话 FIFO、独立预算及幂等收据。普通人工排队与工具派发共用顺序；工具停止规则保持原行为。
- 新增 `ai_chat_pending` 保存人工待发内容及插话关联：requestId、sessionId、顺序、模式、接收状态、目标运行、正文偏移、内容版本、加密请求体及配置引用。请求体包括文字、附件、页面快照和检索范围；不保存主密码、明文 API Key 或工具原始负载。
- 保存后才受理成功；原始提交指纹保持不变，编辑使用单独版本，重试不会覆盖已编辑内容。删除为可撤销的逻辑移除。已开始不允许编辑、删除或转插话。
- 队列暂停持久保存。启动只恢复未执行人工内容且置为暂停，不自动重发已开始或接收未知的请求。配置按受理时的模型身份恢复，失效时保留待发内容并提示。
- 输入和附件复用聊天现有校验；增加新入口的请求体上限。队列全局容量沿用 64；待发与已接收插话的独立加密暂存额度为 64 MiB（历史额度更低时跟随更低值），不混入原历史账本。普通消息开始后释放暂存，已接收插话随原轮历史清理，移除待发可在 8 秒内撤销，10 秒后清空密文。落点仍为 APP_ROOT 数据库。

## API

- `GET /api/ai/sessions/{id}/queue`：普通队列、暂停和编辑状态、当前运行的插话接收状态；不返回附件原始字节或凭证。
- `POST /api/ai/sessions/{id}/queue`：v2 请求体与 `mode=queue|steer`，插话必须带点击时的 `targetRequestId`。返回真实受理身份，重复请求返回同一收据。
- `POST /api/ai/sessions/{id}/queue/{requestId}/action`：beginEdit / save / cancelEdit / remove / undo / steer，携带版本；编辑只改文字和保留的附件 ID。
- `POST /api/ai/sessions/{id}/queue/pause`：暂停或继续。编辑锁未释放不能通过继续绕过。
- 现有 runtime 增加 `paused`、人工待发数量、待接收插话数量；停止后保留人工内容、取消工具待发项。

## 插话边界

- 插话绑定运行，不中止当前上游请求或工具。模型请求之间领取补充；当前最终响应结束时在同一锁下决定继续或封闭受理，消除终态竞争。
- 送出前标记发送中；有上游响应证据后标记已接收。异常且无法判定交付时标记未知，不自动重发。取消或失败时确定未发送的补充恢复为暂停队列。
- 补充使用独立 user 消息；页面、附件只作为有来源的数据，不升级为 system。多条保持受理顺序。工具调用/结果配对完成后才注入。
- 接续共享原运行预算，不重新计时、不重置额度；用量继续按每次请求结算。无后续工具也处理已经受理的补充。
- 历史、后续上下文、跨会话读取以及整个会话的导出均包含已接收补充；待发或接收未知内容不得伪装为已发送历史。界面与导出按正文偏移区分助手回复和用户插话，原回复不被覆盖；无法解密时明确标记内容缺失。

## 前端与验证

- 使用贴边队列组件和独立数据 hook，保留现有会话、附件、滚动及快捷键结构。提交成功只清除已提交草稿，不覆盖随后输入的新草稿；未知请求保留身份供核对。
- 默认发送排队；Ctrl+Enter 插话且不覆盖已有发送绑定。停止独立；插话 tooltip 固定为「提交，但不中断模型运行」。
- 覆盖 FIFO、多会话隔离、暂停编辑竞争、幂等、停止/重启恢复、加密、附件、插话送达/未知/最终响应边界、历史可读及预算；前端覆盖操作和草稿隔离。完成类型构建、针对性回归与隔离浏览器验收，按实际范围记录。
