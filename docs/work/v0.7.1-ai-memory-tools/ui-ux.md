# v0.7.1 AI 记忆工具：UI/UX

当前已落地能力与开关状态见 [features.md](../../features.md)；本文只记录 UI/UX 设计与待确认项，后续工具沿用同一套交互约定。

需求基线：[requirements.md](requirements.md)。

## 1. 范围

- 聊天模型可调用的记忆工具与当前状态见 [features.md](../../features.md)。
- 设置页提供聊天模型的「工具调用」开关；导入兜底模型不显示该开关。
- 工具调用对用户表现为正常对话：不展示原始 JSON、函数名或参数，只展示最终回答。
- 记忆操作状态展示（P6）、`create_memory` / `update_memory` 的界面属于后续切片。

## 2. 入口与布局

入口：设置 → AI 连接 → 聊天模型卡片。

沿用现有 `.ai-slot-field` 行式布局，在「流式传输」下方新增一行：

```text
工具调用        [开关]
自定义端点需显式开启；开启后模型可调用 search_memories 检索已保存的记忆。
```

- 开关使用 Arco `Switch`，与「流式传输」同一列宽和对齐。
- 标签通过 `aria-labelledby` 关联，说明文字通过 `aria-describedby` 关联。
- 说明文字用次要文本色，不新增颜色、圆角或间距 token。
- 只在 `purpose === 'chat'` 时渲染；`purpose === 'import'` 不显示。

## 3. 默认值与保存

| 场景 | 默认表现 |
|---|---|
| 已验证官方端点（OpenAI / DeepSeek / Anthropic Claude Messages） | 开启 |
| 自定义或未验证端点 | 关闭，需用户显式开启 |
| 已保存过显式值 | 按保存值回显，不再套用默认 |

保存时随该模型槽一起提交 `tools`。只改其他字段（如模型名、Key、流式）不会重置已有 `tools` 值。

## 4. 交互状态

| 状态 | 表现 |
|---|---|
| 关闭 | 模型请求不携带工具定义，模型无法调用记忆检索 |
| 开启 | 请求携带 `search_memories`；模型可自主决定是否调用 |
| 保存中 | 保存按钮进入 loading；开关保持当前值，不抖动 |
| 保存失败 | 现有错误提示；开关回到已保存值（由查询数据驱动） |
| 端点不支持工具 | 请求可能失败或忽略工具；由错误提示反馈，不静默伪造成功 |
| 记忆索引构建中 / 不可用 | 对话仍可继续；工具返回 `UNAVAILABLE`，回答中不应声称检索到了记忆 |
| 查询无结果 | 工具返回 `NO_MATCH`；模型按无记忆继续回答 |

## 5. 对话中的表现

1. 用户正常输入并发送。
2. 若模型决定调用工具，服务端执行检索并把结果回填给模型；前端不出现工具调用帧。
3. 工具调用期间可以继续显示「思考中」；不新增独立的工具执行面板。
4. 最终回答通过正常 `text` / `reasoning` / `done` 事件展示。
5. 回答中的记忆内容不附带原始记忆 ID、内部谓词、族键或来源密文。
6. 用户取消本轮时，整个工具循环终止；已产生的部分文本保留，不继续追加。

## 6. 验收表现

- 打开聊天模型卡片，能看到「工具调用」开关和说明。
- 自定义端点默认关闭；打开并保存后，重新进入设置仍为开启。
- 关闭并保存后，重新进入设置仍为关闭。
- 导入兜底模型卡片没有该开关。
- 开启后对话请求确实携带工具定义；关闭后不携带。
- 模型调用工具时，会话历史和 SSE 中不出现原始工具参数 / 结果。
- 工具不可用或无结果时，回答不会编造记忆内容。

## 7. 待人工确认

- 「工具调用」这个标签是否足够直白，是否改成「允许模型检索记忆」。
- 说明文字是否保留 `search_memories` 这一内部工具名；面向普通用户可改为「记忆检索」。
- 后续 3 个工具是否共用同一个开关，还是拆成「读取」与「写入」两个权限。
- 记忆操作状态是否需要独立的消息卡片，还是只在回答中夹带一行状态。
