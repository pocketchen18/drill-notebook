# v0.7.2 会话列表与菜单 UI/UX

> 状态：设计已确认，会话导航 MVP 已实现，待人工验收。2026-11-08。用户验收并提交 Git 后再实现跨会话工具。
> 需求基线：[v0.7.2 功能需求清单](../../state/v0.7.2-features.md)。视觉沿用 [全局设计规范](../../DESIGN.md)。交互草图：同目录 `session-navigation-preview.html`。

## 1. 本轮范围与设计取舍

本轮只设计 AI 侧边栏顶部的会话入口、会话列表、右键菜单与二级菜单，以及这些操作必要的重命名、删除确认反馈。覆盖自动标题与复制会话链接所需的前端表现；跨会话工具沿用已有工具活动展示，工具参数、权限与读取协议留到对应 Spec。

现有界面将标题、108px 的「切换」下拉框、新建和更多并排放置，列表标题空间不足；重命名只藏在标题双击，更多菜单则平铺三种导出和删除。建议将标题与切换合并成一个宽入口，列表里每个会话都能右键或点击 `…` 操作。

用户提供的三张截图用于参考菜单分组、图标、分隔线和二级展开；不把其中的置顶、未读、归档、分叉、移动、批量操作或新窗口功能带入本轮。聊天正文、输入框、上下文卡片、记忆和工具活动的整体布局沿用现状，也不增加模型或 effort 选择器。

## 2. 会话入口与列表

```text
AI 助手
┌──────────────────────────────────────────┐
│ [本周复习计划与间隔安排                ▾] [+] [⋯] │
│ ┌ 会话 · 5 ────────────────────────────┐ │
│ │ ✓ 本周复习计划与间隔安排          ⋯ │ │
│ │   12 条消息 · 刚刚                  │ │
│ │   高数错题：积分换元法             ⋯ │ │
│ │   8 条消息 · 14:26                  │ │
│ │   神经递质的分类与记忆方法         ⋯ │ │
│ │   16 条消息 · 昨天                  │ │
│ └─────────────────────────────────────┘ │
│ 当前上下文 / 聊天正文 / 输入框沿用现状     │
└──────────────────────────────────────────┘
```

- 点击「当前标题 ▾」展开会话列表，再次点击或点外部收起；「新建会话」只进入未保存的新会话页，不请求创建、不复用旧的空白会话，也不在列表增加占位行。输入、添加附件或反复点击新建均不创建记录；只有首次有效发送时才创建。新会话页标题显示「新会话」，顶部 `…` 禁用；已有会话的顶部 `…` 操作当前会话。标题较长时单行省略，悬停或键盘聚焦可查看完整标题。
- 已在新会话页时再次点击新建，保留当前未发送草稿；首次发送创建失败也保留文字与附件并允许重试。创建期间禁用重复发送和切换会话；创建完成后立即发送同一份输入，只创建一次。
- 列表作为浮层覆盖在聊天区上方，默认宽度跟随侧栏内容区，不常驻占用聊天宽度，不推动正文或改变正文滚动位置。沿用侧栏默认 460px、最小 360px 的现有宽度约束。
- 每行以标题为主，第二行显示消息条数与最近时间，帮助区分同名会话。当前会话有轻底色与对勾；标题生成状态只在进行中临时出现，不长期显示「AI 生成」标签。
- 默认行高约 52px，标题 13px、辅助信息 12px，按现有列表顺序展示。只因标题生成、重命名或打开菜单而更新的行不能跳位；新的对话活动才触发正常排序。
- 点击行切换会话并收起列表；右键和 `…` 只打开该行菜单，不切换当前聊天。行内 `…` 在鼠标悬停、键盘聚焦、选中或菜单打开时可见；触控模式始终可见。
- 长列表最高约 360px，受视口剩余高度约束，只有列表内容滚动。浮层不裁切后续菜单；菜单越界时向左或向上展开。
- 列表加载时显示「正在加载会话…」；失败时显示「会话加载失败」和重试；没有会话时显示「暂无会话」与新建入口。不在此切片增加会话搜索、时间分组、筛选或批量操作。

## 3. 一个菜单，两种入口

右键列表行与点击行内 `…` 打开同一份菜单。顶部 `…` 也使用同一组动作，但目标为当前会话。菜单打开时锁定目标会话；之后列表刷新、标题更新或当前会话变化都不能把动作转给另一条记录。

```text
┌──────────────────────┐
│ ✧ 重新生成标题        │
│ ✎ 重命名          F2 │
├──────────────────────┤
│ ⧉ 复制             › │   ┌────────────────────┐
│ ↓ 导出             › │   │ 🔗 复制会话链接    │
├──────────────────────┤   │ ⧉ 复制会话标题     │
│   删除会话            │   └────────────────────┘
└──────────────────────┘
```

实际界面使用现有 Lucide 风格线性图标，不使用草图字符作为产品图标。一级菜单约 192px，菜单项高 34px，8px 圆角，危险项只对文字和图标使用危险色。

| 动作 | 内容与反馈 |
|---|---|
| 生成会话标题 / 重新生成标题 | 首轮完整问答后可用。未成功生成时为「生成会话标题」；已有自动标题时为「重新生成标题」；生成中显示「正在生成标题…」且不能重复触发。手动请求替换人工标题时先确认。 |
| 重命名 | 在目标行进入原位编辑，不先切换会话；顶部双击标题仍可重命名当前会话。 |
| 复制 → 复制会话链接 | 复制稳定的本地会话引用，供粘贴到新会话。只有写入剪贴板成功才提示「会话链接已复制」。 |
| 复制 → 复制会话标题 | 复制菜单目标的当前完整标题；成功提示「会话标题已复制」。 |
| 导出 → Markdown / HTML / JSON | 将现有三种导出收进二级菜单；沿用桌面应用的保存对话框，始终导出菜单目标。取消保存不显示失败。 |
| 删除会话 | 底部独立危险分组，打开明确标识目标标题的确认弹窗，不立即删除。 |

复制子菜单包含链接与标题两项；导出保留现有三种格式。本轮不另加「复制工作目录」「复制任务 ID」或复制正文等与本次需求无关的入口。

### 菜单展开与收起

- 鼠标悬停或点击「复制 / 导出」均可展开二级菜单；一级菜单与二级菜单之间保留连续可经过的区域，短暂穿过间隙不能立刻关闭。移至其他一级项后再关闭旧子菜单。
- 默认向右展开；右侧空间不足时向左，底部不足时向上调整。以整个应用视口为边界，不以侧栏或列表的滚动盒为边界。无法并排时，点击或键盘进入原位置的子菜单，顶部提供「返回」；此布局不在悬停时替换父项，避免点击误落到新出现的子项。
- 上下键移动菜单焦点；右键方向键或 Enter 展开子菜单，左方向键回到父项。Esc 逐级退出：子菜单 → 主菜单 → 会话列表，并把焦点还给上一层入口。Tab 离开菜单时关闭菜单。
- 支持 Shift+F10 / 键盘菜单键打开聚焦行的菜单，F2 重命名聚焦行；不照抄截图中的全局组合快捷键。输入法组合输入期间，Enter 不提交重命名。
- 点击外部、切换会话、滚动列表或收起侧栏时关闭菜单。应用正在生成内容或更新标题时，不能抢走当前编辑/菜单的焦点。

## 4. 自动标题的可见状态

| 状态 | 列表与当前标题的表现 | 用户可做什么 |
|---|---|---|
| 未发送的新会话页 | 「新会话」 | 只在前端保留草稿，无会话 ID、不出现在列表；重命名、复制链接、导出、删除均不可用，发送后才有实际会话。 |
| 已存在的空会话 | 原有标题 | 旧数据可正常选择、重命名、复制链接或删除；生成标题禁用，说明首轮回复完成后可用。新建入口不复用该记录。 |
| 首轮回复中 | 使用现有临时标题；正常显示聊天生成状态 | 不阻塞阅读或手动改名；尚无完整首轮回复时不发起自动标题生成。 |
| 首轮成功完成、标题生成中 | 保留临时标题，行尾小状态图标，提示「正在生成标题」 | 允许继续聊天、切会话、复制稳定链接或人工改名。 |
| 生成成功 | 当前标题与列表原位替换为简短标题 | 不抢焦点、不切会话、不滚动列表；不弹成功 toast。 |
| 生成失败 | 保留原有临时标题，状态图标消失 | 聊天仍正常；在菜单内可手动「生成会话标题」重试，自动失败不持续弹错。 |
| 人工标题 | 显示人工保存的标题 | 后续自动结果不能覆盖；显式再生成才允许替换。 |

自动生成只针对新会话首次完整问答，不能因继续聊天、切模型、重启或打开列表反复改名。中断或出错的首轮不以半截内容自动生成标题；后续触发边界在 Spec 中对照验收口径明确。

标题要求一行可读，表达用户首次问题与实际回复的共同主题；不带「标题：」、引号、Markdown 标记或多行解释。文案长度是生成偏好，不擅自截掉人工长标题，列表仅在视觉上省略。

人工编辑开始后，迟到的自动标题不得回填输入框；人工保存成功后，任何更早的自动或手动生成结果都不得覆盖。手动再生成同样采用此规则。取消人工编辑时恢复最新有效标题。

「重新生成标题」属于本草案建议的单会话恢复入口，用于自动失败或标题不合适，不引入批量重命名。针对人工标题先显示「替换手动设置的标题？」；生成失败继续保留原名。

## 5. 重命名与删除

### 重命名

- 列表中的目标行切换成输入框，自动聚焦并选中原名；当前聊天保持不变。Enter 或离开输入框提交，Esc 取消，去除首尾空白，空标题在行内提示「标题不能为空」。
- 保存中仅锁定该输入框；失败保留草稿并允许重试。原名未变不发起保存。保存成功后原位更新标题，当前会话才同步顶部标题；不因重命名切换会话或重排列表。
- 未保存草稿不因后台刷新或标题生成而消失。菜单关闭与列表收起先完成重命名提交/取消；失败时保留可恢复草稿，不静默丢失。

### 删除

```text
删除会话？
「高数错题：积分换元法」
会话和消息将被删除，且不可恢复。
已保存的长期记忆会保留。
                    [取消] [删除会话]
```

- 沿用应用内确认弹窗；打开时焦点落在取消，Esc 取消。删除中禁用重复确认，失败保持目标会话与现有聊天，展示明确错误。
- 删除非当前会话，只移除目标行，不清空当前消息、草稿或阅读位置。删除当前会话，成功后回到未保存的新会话页，清空正文、输入草稿与附件；不创建或复用其它会话，不打开历史会话。等待期间不能短暂闪回其它聊天。
- 删除失败保留当前聊天并展示错误，允许重试；删除成功后刷新列表、关闭再打开侧栏都保持新会话页，直到发送或手动选中历史会话。
- 允许删除最后一条会话，列表显示「暂无会话」；列表读取与应用重启不自动补建默认会话。正在生成回复的会话先停止再删除。菜单外状态变更导致删除被拒绝时，也应准确展示原因。
- 删除会话保留长期记忆；来源显示遵循既有「来源已被删除」规则，本轮不更改记忆行为。

## 6. 会话链接与后续工具的衔接

- 菜单使用「复制会话链接」这一可读名称。链接标识会话，不携带标题正文、消息、密钥或临时端口；改名后不变。已确定格式为 `drill-notebook://session/<32位随机引用>`，草图中的 `drill-notebook://session/demo-a1` 仅是示意。
- 复制失败不能显示成功；保留可选中的链接/标题并提供手动复制。复制成功无需打断用户或自动新建会话。
- 用户在现有新会话输入框里粘贴链接并提问，沿用普通消息发送流程，不新增分享页面、对话附件卡或新的输入模式。该链接只用于当前本地数据内引用，不能伪装成公网分享地址，不注册系统协议。
- AI 实际列出或读取历史时，复用现有工具活动列表显示「查找历史会话 / 读取会话」及真实状态；不增加独立工具面板。返回的来源会话标题可在现有回复引用中回看，具体可见范围及点击后的定位由对应读取切片继续设计。
- 本文不提前设计两个工具的参数、索引、授权或全量历史展示；也不把链接复制成功当成会话读取成功。

## 7. 验收表现

| 场景 | 应看到的结果 |
|---|---|
| 360px / 460px 侧栏与长标题 | 标题有足够空间，按钮不挤出；完整标题可查看，菜单始终在应用视口内。 |
| 展开/收起会话列表 | 聊天区域几何与阅读位置不跳动，列表独立滚动。 |
| 右键非当前会话，再重命名 / 复制 / 导出 / 删除 | 每项操作准确针对该行，当前会话与输入草稿不被切换或清空。 |
| 鼠标横向进入二级菜单 | 子菜单持续可点；靠右边缘时向左展开，窄视口有返回。 |
| 全键盘与中文输入法 | 可打开列表、菜单、子菜单；Esc 逐级返回；组合输入 Enter 不误保存。 |
| 首轮回复成功 | 自动标题异步原位更新，正文继续可读，不跳位或打断。 |
| 自动失败、用户手动重试 | 原名仍在；重试中不能重复提交，失败不丢标题。 |
| 生成途中人工编辑/保存、切换会话或删除目标 | 生成结果不覆盖人工标题、不改错会话、不复活已删除行。 |
| 同名会话与改名后复制链接 | 同名可借助消息条数/时间区分，改名不改变链接目标。 |
| 复制受限 | 明确提示失败并可手动复制，不能显示成功。 |
| 新建、编辑草稿、首次发送 | 新会话页不产生记录；重复新建保留草稿；首次有效发送只创建一次，创建失败保留输入与附件。 |
| 删除非当前 / 当前 / 最后一条 / 回复中会话 | 分别保持当前、回到未保存的新会话页、允许删至空列表、提示先停止；不补建会话，长期记忆保留。 |
| 空列表、加载失败、深色与粗指针 | 状态可理解、有恢复入口；颜色可读，触控操作不依赖悬停。 |

## 8. 草图说明与交接

`session-navigation-preview.html` 使用虚构的会话与问答，仅在内存里演示菜单、重命名、生成和删除。复制动作展示待复制示例，不写系统剪贴板；导出只展示反馈，不创建导出文件。首次打开预先展开列表与「复制」菜单，方便检查层级；正式界面默认关闭。

草图可通过右键或行内 `…` 操作，也可体验新建与首轮标题变化。审阅控件可调整列表密度、辅助信息以及标题状态；这些控件不属于产品设置。设计已获确认，当前按同目录 [Spec](spec.md) / [Plan](plan.md) 实施导航 MVP；全局功能清单在发布前同步。
